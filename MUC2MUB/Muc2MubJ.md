# MUC2MUB 取扱説明書

MSXでMUCをMUBへ、一曲ずつ着実に。

この説明書は**MUC2MUB v3.15**を基準に書いています。基準日は2026年9月15日であり、プロジェクトの最新標準実行ファイルである`bin/muc2mub.com`を対象とします。

MUC2MUBは、MUCOM88のMMLソースである`.MUC`ファイルをMSXでコンパイルし、`.MUB`ファイルとして保存するプログラムです。曲を修正したあとに成果物を作るときにも使えますし、複数の曲をDOSのバッチファイルで順番に変換するときにも使えます。

基本的な使い方そのものは簡単です。

```dos
MUC2MUB SONG.MUC
```

これで`SONG.MUB`が作られます。ただし実際の曲を扱っていると、音色ファイル、PCMファイル、ファイル名、メモリ、保存領域のせいで迷う部分が出てきます。この説明書ではそうした部分まで一緒にまとめました。最初からすべての内容を覚える必要はありません。まず一曲変換してみて、必要な項目を探して読んでいただければ大丈夫です。

## 1. どんなプログラムか

MUCは、音符とコマンドを文字で書いたソースファイルです。MUBは、その内容を再生ドライバが使えるように変換したバイナリファイルです。

MUC2MUBの役割は、この2つのあいだの変換です。基準となる文法は**MUCOM88 v1.7系**であり、出力は**MUB8形式**です。

- MUCを編集するプログラムではありません。
- 曲を直接再生したり録音したりするプログラムでもありません。
- WAVやMP3を作るプログラムではありません。
- どんなMMLファイルでもMUCOM88用に自動変換するプログラムではありません。
- 現代のすべてのMUCOM88拡張文法に対応しているという意味でもありません。

他のコンパイラ用のソースであったり、新しいドライバ専用のコマンドが入っている曲は、文法と再生環境を別途確認する必要があります。拡張子を`.MUC`に変えるだけでは互換になりません。

## 2. 実行環境と用意するもの

### 実行環境

| 項目 | 基準 |
|---|---|
| CPU | Z80で実行可能。R800専用プログラムではない |
| オペレーティングシステム | MSX-DOS 2およびマッパーサービスを提供する環境。Nextor構成で検証 |
| メモリ | MegaFlashRom SCC SDや、Carnivore2のように512 KiB以上のマッパー構成を備えたSDカートリッジとの併用を基準として推奨。実際に割り当て可能な空きセグメントが必要 |
| 記憶媒体 | DOSから読み書きできる媒体。入力・アセットの読み込みと出力フォルダへの書き込みができること |
| 実行ファイル | `MUC2MUB.COM` |
| ソース | MUCOM88 v1.7系の`.MUC` |
| 追加ファイル | 曲に必要なFM音色データおよびPCMデータ |

512 KiB以上の構成で検証しています。ただし現在のプログラムは、搭載RAMが正確に何KiBかを基準に一律で許可・拒否する方式ではありません。DOSマッパーを通じて必要な作業セグメントを割り当てられることが条件です。詳しくは[メモリ制限](#11)をご覧ください。

DOS 1やBASICから直接実行する使い方は、サポート対象として案内していません。まずDOS 2系の環境で起動してください。

コンパイルそのものには、曲を再生する音源デバイスは必要ありません。ただし完成したMUBをきちんと聴くには、別途の互換プレイヤーと音源環境が必要です。MSXの内蔵PSGだけでOPNAのFM・リズム・ADPCMまですべて再生されるわけではありません。

### ファイルの準備

最初は、ひとつのフォルダに必要なファイルをまとめておくのがいちばん簡単です。

```text
MUC2MUB.COM
SONG.MUC
VOICE.DAT       曲で外部FM音色を使うとき
MUCOMPCM.BIN    曲で既定の名前のPCMデータを使うとき
SONG.MD5       原文ハッシュを入れたい場合のみ
```

`VOICE.DAT`と`MUCOMPCM.BIN`がすべての曲に無条件で必要なわけではありません。曲の中にFM音色が定義されていたり、PCMチャンネルを使わない曲もあります。逆に、それらのファイルを実際に使う曲であれば、名前だけ同じ別のファイルを持ってきてはいけません。

実行に`.ASM`、`.SYM`、Java、アセンブラは必要ありません。一般の利用者は、最新の`MUC2MUB.COM`をMSXから見えるディスクへコピーすれば大丈夫です。

## 3. はじめての一曲を変換する

### すでに持っている曲から始める

1. 元のMUCと音色・PCMファイルを別途バックアップします。
2. MSX-DOSで、曲の入っているドライブとフォルダへ移動します。
3. 次のように実行します。

```dos
MUC2MUB SONG.MUC
```

出力名を自分で決めるなら、次のように入力します。

```dos
MUC2MUB SONG.MUC TEST.MUB
```

はじめて試すときは`TEST.MUB`のように別の名前で保存しておくと、もともと持っていたMUBと比較しやすくなります。正常な既存の出力ファイルは、上書きの確認なしに新しい結果へ置き換わるので、オリジナルのMUBを比較資料として使っている場合はとくに注意してください。

実行中はバージョンバナーと`Compiling:`、`Used FM voices:`、`Writing  :`などの進行表示が出て、正常に終わると次の文言が表示されます。

```text
Done.
```

ここで終わりにせず、手前に警告がなかったかも確認してください。`Done.`は変換と保存の手順が終わったという意味であって、元の曲に必要な外部ファイルまですべて正しいという保証ではありません。

### 小さなテスト用MUCを作る

普通のテキストエディタで以下の内容を`TEST.MUC`として保存してみてください。コードブロックの枠線は入れません。

```muc
#title FIRST TEST
#composer MY NAME
#comment Simple SSG test
D o4 l4 v12 cdefgab>c
```

```dos
MUC2MUB TEST.MUC
```

この例はDチャンネル、つまりSSGを使うので、外部FM音色やADPCMを利用しません。現在のバージョンは、PCMを使わない曲でも既定のPCMファイルを探す過程で欠落警告を表示することがあります。この例のようにKチャンネルを使わないのであれば、その警告のためにPCMを新しく用意する必要はありません。

`TEST.MUB`ができたら、互換プレイヤーで聴いてみてください。ソース作成 → コンパイル → 結果確認という基本の流れは、これで十分です。

## 4. コマンドとファイル名の規則

### 基本形式

```text
MUC2MUB 入力ファイル [出力ファイル]
```

角括弧は「省略できる」という意味です。実際のコマンドに`[`と`]`を入力するのではありません。

```dos
MUC2MUB SONG.MUC
MUC2MUB SONG.MUC RESULT.MUB
MUC2MUB SONG.MUC OUT\RESULT.MUB
```

最後の例の`OUT`フォルダは、あらかじめ存在している必要があります。プログラムが出力フォルダを自動で作ることはありません。

出力名を省略すると、入力名の拡張子を`.MUB`に変えます。入力名にドライブを明示していれば、自動の出力名にもそのドライブ指定が引き継がれます。別の場所に保存したいなら、出力位置を自分で指定してください。

### 入力ファイル名

入力は次の規則に従います。

- 主名は1〜8文字、拡張子は使う場合1〜3文字です。
- 英字、数字、アンダースコア`_`、ハイフン`-`を使います。
- 英字の大文字小文字は区別しません。
- `A:SONG.MUC`のようにドライブを付けられます。
- サブフォルダのパス、空白、引用符、ワイルドカードには対応しません。
- 長い名前を自動的に縮めて別のファイルを開く方式は使いません。

| 例 | 使用可否と説明 |
|---|---|
| `SONG.MUC` | 可能 |
| `BOS010.MUC` | 可能 |
| `MY_SONG.MUC` | 可能 |
| `A:SONG.MUC` | 可能。アセット探索の位置まで変わるわけではない |
| `LONGSONG1.MUC` | 不可。主名が9文字 |
| `MY SONG.MUC` | 不可。空白を含む |
| `"MY SONG.MUC"` | 不可。引用符で囲んでも解決しない |
| `ALBUM\SONG.MUC` | 入力引数としては不可。先に`CD ALBUM` |
| `*.MUC` | 不可。複数ファイルを一度に受け取る機能ではない |
| `曲の名前.MUC` | 使用しない。DOS用のASCII名で用意 |

拡張子は混乱を避けるため、入力を`.MUC`、出力を`.MUB`で統一するのがよいでしょう。

### 出力ファイル名

出力にはDOSのパスを付けられます。ただし最後のファイル名は、上と同じ8.3規則に従います。入力と出力でパスの対応範囲が異なる点を覚えておいてください。

引数ひとつは最大63バイトで、出力のドライブ・ディレクトリ接頭部は、一時ファイル名を付ける余地のため最大52バイトです。長いパスを試すより、近いフォルダを出力先に使ってください。DOSコマンドライン全体の長さ制限も別途適用されます。

入力と出力の**最後のファイル名全体が同じであれば**、別のドライブやフォルダであっても拒否します。たとえば`SONG.MUC`を`OUT\SONG.MUC`へ出力することは許可しません。元のソースを誤って上書きしないよう、保守的に検査しているためです。`SONG.MUC` → `SONG.MUB`は拡張子が違うので正常な使い方です。

### 対応していない呼び出し方

一度の実行で受け取るのは、入力ひとつと任意の出力ひとつだけです。三番目のファイルを追加しないでください。

`-o`、`/FORCE`、`/STRICT`、`/MUB`、再帰検索といったオプションは、MUC2MUBのコマンドライン機能ではありません。とくに他のプログラムのオプションをそのまま持ってきて使わないでください。

引数なしで実行すると使用形式が出ますが、専用の対話型ヘルプ画面ではありません。また起動時にマッパーを先に初期化するので、メモリ環境が合っていなければ使い方よりマッパーエラーが先に見えることがあります。

## 5. フォルダとドライブの使い方

複数のアルバムを扱うとき、もっとも注意すべき部分です。**音色とPCMの相対ファイル名は、現在の作業ディレクトリを基準に探します。** 入力ファイルのある場所を自動的に見つけて、アセット探索の基準を変える方式ではありません。

私は、曲ごとに次の順序を守る使い方をおすすめします。

1. 該当のドライブへ切り替えます。
2. 曲とアセットのあるフォルダへ移動します。
3. その場でコンパイルします。

```dos
B:
CD \ALBUM1
MUC2MUB SONG.MUC
```

上の例は、`MUC2MUB.COM`が現在のフォルダにあるか、DOSの実行ファイル検索パスで見つかることを前提としています。実行ファイルが見つからない場合は、現在の曲フォルダへコピーして先に試してみてください。

次のように入力だけ別のドライブに指定するのとは違いがあります。

```dos
MUC2MUB B:SONG.MUC
```

このコマンドがBドライブの曲を読んでも、`VOICE.DAT`やPCMの相対探索位置まで一緒にBドライブへ移るわけではありません。「ソースは合っているのに音色が違う」ときは、この部分から確認してください。

異なるアルバムに同じ名前の`VOICE.DAT`が入っているのはよくあることです。便利だからとすべてのファイルをひとつのフォルダにまとめると、あるアルバムのアセットで別の曲をコンパイルしてしまうことがあります。アルバムごとのフォルダ構成を保つほうが安全です。

## 6. MUCファイルの書き方とチャンネル

この節は、変換のために必要な基本の案内です。すべてのMUCOM88コマンドと音源レジスタを説明するMML言語辞典ではありません。複雑な曲は、使用した元のドライバの文法も併せて確認してください。

### テキスト形式

MUCは書式のないテキストです。ワープロ文書やUTF-16ファイルとして保存しないでください。

英数字だけのテストファイルはASCIIで用意すると楽です。既存の日本語MUCOM88資料はShift_JIS/CP932系である場合があるので、元のエンコーディングを保存してください。現在のコンパイラは、文字エンコーディングを自動判別・変換するプログラムではありません。UTF-8 BOMや全角空白が入ると、行頭のコマンド・タグを認識できないことがあります。ハングルのタグ表示も、コンパイラだけでなくプレイヤーと表示環境の対応に左右されます。

CRLF、LF、CRの改行を処理しますが、DOSのツールと一緒に使うときはCRLFで統一すると管理が楽です。比較用の原本があるなら、改行を変えるだけでも原文ハッシュとタグのバイトが変わり得るという点は、別途覚えておいてください。

ファイルの途中にNULやDOSのテキスト終端記号であるCtrl-Zが混ざらないようにします。画面には見えなくても、うしろの内容を読めなくしてしまうことがあります。

### チャンネルは必ず行頭に

```muc
A o4 l4 cdef
A gab>c
```

チャンネル文字は大文字の`A`〜`K`、そのあとに空白またはタブを入れます。同じチャンネルを複数行に分けて書くことができます。

```text
A o4 c      正常なチャンネル行
 A o4 c     前に空白があるので誤ったチャンネル行
a o4 c      小文字チャンネルなので誤ったチャンネル行
A,o4 c      チャンネルのうしろのカンマは区切りとして非対応
A,B c       一行にチャンネルを並べる方式は非対応
```

誤ったチャンネル行は、警告を出して抜け落ちることがあります。曲の一部が消えたように聞こえるときは、「コンパイルエラーがなかった」という理由でこの可能性を除外しないでください。

### チャンネル配置

| チャンネル | 担当音源 |
|---|---|
| A, B, C | FM 1, 2, 3 |
| D, E, F | SSG 1, 2, 3 |
| G | リズム |
| H, I, J | FM 4, 5, 6 |
| K | ADPCM |

他のMMLシステムのチャンネル表と混同しないよう注意してください。とくにD・E・FはFMではなくSSGです。

### よく使う基本表記

| 表記 | 意味または用途 |
|---|---|
| `c d e f g a b` | 音符 |
| `r` | 休符 |
| `o4` | オクターブ指定。`o1`〜`o8`の範囲 |
| `>` / `<` | オクターブ上げ / 下げ |
| `l4` | 以降の音符の既定の長さを指定 |
| `c8` / `r8` | 音符・休符の長さを直接指定 |
| `v12` | ボリューム指定。有効な意味と範囲はチャンネルごとに確認 |
| `@1` | 該当チャンネルの音色・サンプル選択。FMとADPCMで意味が異なる |
| `[cdef]2` | 区間のリピート |
| `[c / d]2` | 最後のリピートでの脱出位置を指定 |
| `L` | 曲のループ位置を指定 |
| `;` | コメント開始 |

大文字と小文字のコマンドを勝手に入れ替えないでください。同じ文字でも別のコマンドであり得ます。

### リピートとマクロ

```muc
A o4 l4 [c d e f]2 g
```

リピートの`[`と`]`は対応させる必要があります。`/`はリピートの中で使う脱出の印です。リピートの外に書いたり、同じリピートに二度入れたりするとエラーになります。リピートのネストは最大16段です。

```muc
# *1{o4 l4 cdef}
A *1 gab>c
```

上の例で`# *1{...}`はマクロ定義、`*1`は呼び出しです。最初は例のように短いマクロを一行で定義して使ってください。マクロ本体は511バイトまで、ネストした呼び出しは最大4段です。自分自身を呼び続けるマクロは使えません。

マクロはソースを整理する手段であって、いつでも結果のDATAを減らしてくれる圧縮機能ではありません。繰り返されるイベントのサイズを減らしたいなら、音楽的に同じ結果を保てるかを確認しながらリピート構文を使ってください。

## 7. タグと曲情報

タイトル、作曲者、外部ファイル指定などは、ファイルのいちばん上にまとめて書きます。

```muc
#title MY SONG
#composer MY NAME
#author MY NAME
#comment Test version
#voice VOICE.DAT
#pcm PCM.BIN
#date 2026/09/15
A @1 o4 l4 cdef
```

この例の外部ファイルは、実際に用意されている必要があります。

| タグ | 用途 |
|---|---|
| `#title` | 曲のタイトル |
| `#composer` | 作曲者 |
| `#author` | 作成者情報 |
| `#comment` | 補足説明。値が空でも許容 |
| `#date` | 日付情報 |
| `#voice` | 外部FM音色ファイル名 |
| `#pcm` | 外部PCMファイル名 |

現在の警告チェックでは、このほかに`#mucom88`、`#driver`、`#version`、`#uuid`、`#mucmd5`も既知のタグ名として扱います。とはいえ、それらのタグを書けば新しいドライバや拡張文法へコンパイルエンジンが切り替わるという意味ではありません。`#mucmd5`を書くことと、[入力ごとの`.MD5`ファイル](#18)を用意することも別の話です。

タグを書くときは、次のように整理してください。

- `#`を行頭に置きます。
- メタデータタグはファイルの先頭部分に連続してまとめます。
- タグのあいだに通常のコメントや空白だけの行を挟みません。
- 音楽データが始まったあとに`#voice`、`#pcm`、`#title`を後付けしません。
- ヘッダをソース全体に散らしたり、数万バイトの長さにしたりしません。

現在のメタデータ処理は、最初のヘッダ区間、最初のソースメモリ窓を基準にしています。大きなMUCのうしろのほうまで音楽行を処理できるという事実と、ファイルのどこに置いたタグでも適用するということは別の話です。

ヘッダ外のタグは無視されたという警告が出ることがあります。認識できなかったタグも警告の対象です。こうしたタグが原文テキストとして残る場合と、実際のコンパイル設定として反映される場合とを混同しないでください。

## 8. FM音色を用意する

FM音色は主に外部ライブラリから持ってくるか、MUCの中に直接定義します。

### 外部音色ファイル

```muc
#voice VOICE.DAT
A @1 o4 c
```

タグを省略すると、既定の名前は`VOICE.DAT`です。現在の外部ライブラリローダーは8,192バイト、つまり32バイト単位の音色レコード256個分の領域を使います。別の形式の音色ファイルを、名前だけ変えて入れてはいけません。

重要な点がひとつあります。**音色ファイルを開けなかった場合、現在のバージョンは音色領域を0で初期化したうえで処理を続けることがあります。** すべての外部音色の欠落を親切なエラーとして捕まえてくれるわけではありません。番号で選んだ音色には、静かに誤った内容が入り得ます。短かったり壊れていたりする音色ファイルについても、完全な形式検証を期待しないでください。

したがって、FM曲の音がおかしいときは、まず次を確認してください。

1. この曲に合った音色ファイルか。
2. 現在の作業フォルダにあるか。
3. `#voice`の名前とDOSで見える名前が一致しているか。
4. ライブラリのサイズと内容がオリジナルと同じか。
5. ソースの`@番号`または`@"名前"`が、そのライブラリを基準に書かれているか。

### 長い音色・PCM名

入力MUCの長い名前は拒否しますが、`#voice`と`#pcm`のアセット名は、従来のFCB方式の切り詰め動作を保っています。

```muc
#voice shinobivoice.dat
```

この場合、MSX側には`SHINOBIV.DAT`という名前で用意する必要があります。一般的なVFATの`SHINOB~1.DAT`という別名を自動的に探してくれる機能ではありません。

できればタグと実際のファイルの両方を、最初から短く明確な8.3名で揃えてください。異なる長い名前が同じ8.3名に切り詰められる場合は、フォルダを分ける必要があります。ただし、オリジナルのMUBと完全なバイト比較を行う予定であれば、タグ名を修正すること自体がタグとハッシュを変えるという点も考慮しなければなりません。

### ソース内のインライン音色

現在のバージョンは、複数行の`@N`定義、`@N:{...}`形式、生パラメータの`@%N`形式を処理します。以下は中括弧形式の例です。

```muc
  @1:{
7,2
31,8,3,5,2,41,1,1,3
31,5,4,5,2,39,0,5,2
31,4,2,5,1,31,0,3,7
28,30,6,6,0,0,2,1,4
}
A @1 o4 l4 cdef
```

先頭の2つの値はFB、ALGであり、次の4行は各オペレータの`AR, DR, SR, RR, SL, TL, KS, ML, DT`の順です。インライン定義の前のインデントと、音楽チャンネル行の前に空白を入れてはいけないという規則は、互いに別の話です。

MUC2MUBはインライン定義を音色領域へ反映したうえで、実際に使用したFM音色を結果に入れます。使用された音色は1つあたり25バイトのパラメータとしてシリアライズされます。外部ライブラリ全体をそのままMUBへ貼り付けるのではありません。

一曲で使えるFM音色は最大32個です。この制限は「音色番号が32以下でなければならない」という意味ではなく、曲で実際に登録・使用する異なるFM音色の数に対する制限です。

誤ったインライン定義がすべて明確なエラーとして検出されるわけではありません。値の個数、順序、番号を守り、実際の再生またはオリジナルのDATA比較までしてください。

<a id="09"></a>

## 9. PCMとADPCM

### どのファイルを用意するのか

KチャンネルでADPCMを使う曲には、その曲に合ったPCMバンクファイルが必要です。

```muc
#pcm PCM.BIN
```

タグがないときの既定のファイル名は`MUCOMPCM.BIN`です。拡張子が必ず`.PCM`でなければならないわけではありません。`.BIN`など、もとの曲が使っていた名前に従いつつ、DOSのファイル名規則に合わせて用意します。

ここで言うPCMファイルは、MUCOM88で使えるように用意されたデータです。普通のWAVやMP3の拡張子だけを変えて入れるものではありません。コンパイラがオーディオ形式を解析してOPNA用のADPCMへ変換してくれることはありません。

### いつMUBに入るのか

音楽イベントとFM音色データは、先にメモリマッパー上に作っておきます。PCMブロック全体をそこへ一緒に載せることはしません。

保存の段階でPCMファイルのサイズを確認し、ディスクから少しずつ読んでMUBのタグのうしろへ書き足していきます。正常なKチャンネル使用曲では、必要なPCMバンクを含んだひとつのMUBが作られる方式です。

- PCMはメモリ上の音楽DATAとは別です。
- PCMファイル自体のバイトをつなげるのであって、保存時に再び音声圧縮をすることはありません。
- 使用したサンプルだけを選んでPCMバンクを自動的に切り詰めることはしません。
- Kチャンネルを使わなければ、PCMファイルがあってもPCMブロックは含みません。
- PCMのサイズは32ビットで扱うため、64 KiBより大きいPCMも保存経路で処理します。これが任意のサイズ・形式のすべてのPCMや、すべてのプレイヤーの対応を保証するという意味ではありません。

### PCM欠落の警告

```text
Warning: PCM file not found: PCM.BIN
```

この警告が出てもコンパイルを終えてMUBを作れます。従来の動作との互換性を保った部分です。

Kチャンネルを使う曲であれば、正常な完成として扱わないでください。FMとSSGは聞こえるのにサンプル音だけが抜けた結果かもしれません。ファイルを用意したうえで再コンパイルする必要があります。

Kチャンネルのない曲でも、PCMサイズを問い合わせる過程のために欠落警告が出ることがあります。その場合は、曲がもともとPCMを使わないことを確認すれば大丈夫です。

ファイルを見つけられないことと、見つけたファイルを実際に読んでいる途中で失敗することは違います。後者は`Cannot read PCM file`エラーとなり、保存に失敗することがあります。コンパイル中にPCMファイルを差し替えたり、媒体を抜いたりしないでください。

<a id="10"></a>

## 10. コンパイルと保存はどう進むのか

全体の流れは次のとおりです。

```text
MUCの読み込み
  ↓
行境界を保ってソースをマッパーへ読み込み
  ↓
音色の準備 → チャンネルごとの一括コンパイル → 音楽・FM DATAの完成
  ↓
一時ファイルにヘッダ + DATA + タグを記録
  ↓
必要なPCMをディスクから読んで書き足し
  ↓
ファイルを閉じる → 最終的なMUB名へ置き換え
```

ソースを読みながら、そのまま最終的なMUBへ音符を書き下ろしていく方式ではありません。まずソースを読み込み、チャンネルごとにコンパイルした音楽DATAをメモリ上に構成してから、ディスクへ保存します。内部の保存方式は、行境界を保ったマッパー窓と作業用の行バッファであり、64 KiBをZ80のひとつの連続したアドレス空間にすべて広げなければならない構造ではありません。

出力ファイルの大きな構成は次のとおりです。

| 順序 | 内容 |
|---|---|
| 1 | 80バイトのMUB8ヘッダ |
| 2 | 音楽DATA: チャンネルテーブル、イベント、使用FM音色など |
| 3 | タグ: 曲情報と追加メタデータ |
| 4 | 必要な場合はPCMバンク |

メモリ上で完成した音楽DATAは、保存の段階で再びMMLとして解釈したり再コンパイルしたりせずに記録します。ただし最終的なMUBにはヘッダ・タグ・PCMも必要なので、「マッパーメモリ全体をそのままダンプしたファイル」ではありません。

コンパイル過程の文法・長さ・バッファ検査と、保存時のI/O検査は行いますが、作られた曲を自動的に再生して原曲と聴覚的に比較したり、保存ファイル全体を読み直してオリジナルのMUBと突き合わせたりする機能はありません。完全一致の検証は別の比較手順です。

<a id="11"></a>

## 11. メモリとサイズの制限

この部分は、互いに異なるサイズを区別して見る必要があります。

| 対象 | 現在の基準 |
|---|---|
| 入力MUC | ディスク上の実サイズで最大65,536バイト、つまり64 KiB |
| ソース読み込み用マッパー | 行境界を保つために16 KiBセグメントを5個使用 |
| 音楽・FM出力DATA | 16 KiBセグメント2個、32 KiBの領域に収まる必要がある |
| 音色・作業用マッパー | 16 KiBセグメント1個 |
| 作業マッパー割り当て合計 | 8セグメント = 128 KiB。DOS・プログラム・その他のメモリは別 |
| 通常のチャンネル行のMML本体 | `A `のような先頭2バイトのうしろに最大1,023バイト |
| マクロ本体 | 最大511バイト |
| リピートのネスト | 最大16段 |
| マクロ呼び出しのネスト | 最大4段 |
| 一曲で使用したFM音色 | 最大32個 |

### 64 KiBには何が含まれるのか

音符だけでなく、タイトルタグ、コメント、空白、改行まで含めたファイル全体のバイトです。64,000バイトと65,536バイトを混同しないでください。65,536バイトは許容範囲ですが、65,537バイトは超過です。

16・32・48・64 KiB規模のソースを処理できます。しかし、サイズが上限以下だというだけで、すべてのソースが成功するわけではありません。文法、一行の長さ、マクロの長さ、最終DATAのサイズなどの条件も満たす必要があります。

とくに、コメント一行を数万字に伸ばしたり、改行なしで曲全体を一行に詰め込んだりする書き方は避けてください。非常に長い非音楽行も、ソースメモリ窓の読み込み限界にぶつかることがあります。読みやすい複数行に分けるのがよいでしょう。

### 入力サイズと出力サイズは比例しない

コメントの多い64 KiBのMUCの音楽DATAが小さい場合もあり、音符やマクロ呼び出しがぎっしり詰まったより小さなMUCが出力領域を先に埋めてしまうこともあります。出力DATAには音符だけでなく、チャンネル構造と音色テーブルも入ります。32 KiBを音符だけで全部使えると計算しないでください。

出力領域が足りない場合は、音楽的に同じ結果を保てるリピート構文で整理するか、曲を分ける必要があります。コメントだけを減らすのは入力サイズには役立ちますが、すでに大きくなった音楽DATAを減らすことはできません。

最終的な`.MUB`ファイルはヘッダ・タグ・PCMまで含むので、32 KiBや64 KiBより大きくなり得ます。ファイルが大きいというだけの理由でDATA上限を超えたと判断してはいけません。

### 4 MiBのRAMを挿せば制限は増えるのか

いいえ。4 MiBマッパーでの検証は、その構成で正常に動作するかを確認したものであって、4 MiB全体を予約したり使用したりする試験ではありません。

現在のコンパイラは、DOSの既定のマッパーコンテキストで必要な8個のユーザーセグメントを割り当てます。すべてのスロットのRAMを直接調べて容量を合算したり、他のマッパーの空き領域を積極的に集めたりする方式ではありません。物理RAMの総量が大きくても、DOSが提供する割り当て状況によってはメモリエラーが出ることがあります。

RAMの増設だけで、入力64 KiB、音楽DATA 32 KiB領域、行・マクロの長さ制限が自動的に増えることはありません。

<a id="12"></a>

## 12. 複数の曲をバッチ変換する

MUC2MUBは一度に一曲を処理します。複数の曲を順番に呼ぶ仕事は、DOSシェルやバッチファイルが担います。

### いちばん簡単なバッチファイル

以下の内容を`BUILD.BAT`として用意します。この節のコマンドはMSX-DOSで実行する例です。

```bat
@ECHO OFF
MUC2MUB SONG01.MUC
MUC2MUB SONG02.MUC
MUC2MUB SONG03.MUC
```

```dos
BUILD
```

この例は順番に実行する基本形です。**途中の曲が失敗したときに自動で中断したり、失敗の一覧をまとめたりするバッチではありません。** 最後のコマンドの成功だけを見て、すべて成功したと判断しないでください。

曲ごとの記録を残したいなら、出力を別に保管できます。

```bat
@ECHO OFF
MUC2MUB SONG01.MUC > C01.LOG
MUC2MUB SONG02.MUC > C02.LOG
MUC2MUB SONG03.MUC > C03.LOG
```

リダイレクトすると、画面に進行表示が見えなくなることがあります。ログ名は、ソース・音色・PCM・既存のMUBと重ならないように決めてください。同じログへ`>`で書き直すと、先のログは置き換えられます。ログの作成にもディスク領域が必要です。

### アルバムが複数のフォルダにある場合

次の例は、各アルバムフォルダで`MUC2MUB`コマンドを見つけられることを前提としています。

```bat
@ECHO OFF
CD \ALBUM1
MUC2MUB SONG01.MUC
MUC2MUB SONG02.MUC
CD \ALBUM2
MUC2MUB SONG01.MUC
MUC2MUB SONG02.MUC
```

各フォルダには、そのアルバムの音色・PCMファイルを置きます。ドライブも違うなら、`CD`だけでなく該当のドライブへ切り替えてください。

ワイルドカードの繰り返しや条件付き中断を追加したいなら、使用するMSX-DOSシェルの文法を確認する必要があります。Windowsの`FOR`の例をそのままコピーして動くと想定しないでください。MUC2MUB自体には、ファイル一覧の繰り返しや「失敗した曲だけ再試行」といった機能はありません。

### バッチ運用の原則

- 最初は一曲、次は小さなまとまり、最後にアルバム全体の順で進めます。
- 実行前に対象の一覧と、各曲のアセットを確認します。
- 失敗しても続けるか、最初の失敗で止めるかは、シェル側で明示的に決めます。
- 終了コードとあわせて、ログの警告も確認します。
- 失敗した箇所に残っている既存のMUBを、新しい結果として誤って集計しません。
- 同じ出力フォルダで複数の変換を同時に実行しません。一時ファイル名が固定されています。
- `M2MTEMP.$$$`と`M2MBACK.$$$`を、バッチの開始時に無条件で削除しません。
- 中断後は結果の一覧を確認し直し、必要な曲から再実行します。

とくに保管用の一括変換では、「プログラムが全部実行された」ことと「すべての曲が正しく変換された」ことを区別するのが重要です。

<a id="13"></a>

## 13. 成功・警告・エラーと終了コード

| 状態 | 意味 | DOS終了コード |
|---|---|---|
| 正常完了 | コンパイルと保存の手順が完了 | `0` |
| 警告つきの完了 | 無視された行・タグ、または欠落アセットなどがあり得る | 完了していれば`0`であり得る |
| 一般エラー | 引数、コンパイル、ファイルI/O、メモリなどの失敗 | `1` |
| DOSによる中断 | Ctrl-C、STOP、媒体エラーなどでDOSが中断処理 | DOSの該当する中断・エラーコード |

画面のコンパイルエラー番号とDOSの終了コードは別のものです。

```text
Error line 4, channel A (code 6): Note length out of range
> A l0 c
```

この例の`code 6`は音長エラーの分類番号です。DOSシェルへ6を返すという意味ではありません。一般的なコンパイル失敗の終了コードは1です。

エラーの位置は、MUCの実際の行番号とチャンネルで表示します。行の内容は先頭から最大72バイトまでしか見せないので、長い行のうしろの部分は元のエディタで確認する必要があります。マクロ内のエラーは、呼び出した音楽行を基準に表示されることがあるので、マクロ定義も一緒に見てください。

ソースの位置を特定できない場合は、`Error (source line unavailable)`で始まるメッセージが出ます。エラーがないという意味ではなく、位置情報を付けられなかったという意味です。

一般的には、最初のエラーから直して再コンパイルしてください。一度に全ソースのすべてのエラーをまとめて出力する方式ではありません。

<a id="14"></a>

## 14. コンパイルエラー全案内

以下は現在の診断メッセージの全分類です。例は代表的な発生条件であって、あり得るすべての誤った文法を並べたものではありません。

| コード | 画面メッセージ | 原因と確認する箇所 |
|---|---|---|
| 0 | `Syntax error / missing number` | 解釈できない文法、または必要な数値の欠落。直前のコマンドのパラメータを確認 |
| 1 | `Invalid parameter` | そのコマンドに不適切な値。大きすぎる数、符号、値の範囲を確認 |
| 2 | `Repeat end without matching start` | 対応する`[`なしに`]`を使用 |
| 3 | `Unclosed repeat/loop` | `[`で開いたリピートがチャンネル終了まで閉じられていない |
| 4 | `Too many voices (maximum 32)` | 使用FM音色が32個を超過。実際に使う音色を整理 |
| 5 | `Octave out of range (o1..o8)` | オクターブが対応範囲外。`o`と`<`、`>`の流れを確認 |
| 6 | `Note length out of range` | 有効でない音長。とくに`l0`、0、または計算不能な長さを確認 |
| 7 | `Invalid loop escape` | リピート外の`/`、または同じリピートに重複した脱出の印 |
| 8 | `Missing parameter or separator` | 必要なパラメータ・区切りの欠落。複数の数値を取るコマンドのカンマと値を確認 |
| 9 | `Command not valid for this channel` | 現在のチャンネルで使えないコマンド。FM・SSG・リズム・ADPCMの区別を確認 |
| 10 | `Too many nested repeats` | リピートのネスト16段を超過。リピート構造を単純に整理 |
| 11 | `Voice name not found or invalid` | 名前で指定した音色が見つからないか、名前指定が不適切。音色ライブラリと綴りを確認 |
| 12〜14 | `Unspecified compiler error` | 予約されているか、一般利用者向けの意味が定義されていない分類。数字を保存して報告 |
| 15 | `Macro not found` | 呼び出した番号のマクロ定義がない |
| 16 | `Invalid macro definition` | マクロ定義の形式・中括弧の問題、または再帰・呼び出しネストの限界 |
| 17 | `MML line or macro too long` | 音楽行またはマクロ本体が作業バッファの上限を超過 |
| 18 | `Output buffer overflow` | 音楽イベントと音色などを収める出力領域の不足 |

定義されていない他の番号も`Unspecified compiler error`として表示されることがあります。コード番号だけを見て勝手に新しい意味を付けず、原文と発生条件を一緒に保管してください。

### よく出会うエラーの例

以下はわざと誤って書いた例です。正常な曲の例として使わないでください。

```muc-error
A l0 c
```

既定の音長が0です。意図した長さが4分音符なら`l4`のように直します。

```muc-error
A ]2
```

閉じるリピートだけがあります。開始の`[`が必要です。

```muc-error
A [c
```

リピートが閉じられていません。意図に合う`]回数`で締めくくります。

```muc-error
A /c
A [c / d / e]2
```

1行目はリピートの外で`/`を使っており、2行目は同じリピートに`/`を二度使っています。

```muc-error
A q100000 c
```

コマンドが受け付けられない大きな値です。数字をやみくもに減らすより、そのコマンドの意味と望む効果から確認してください。

```muc-error
A *99
```

99番のマクロを定義していなければエラーです。`# *99{...}`の定義が存在するか確認します。

```muc-error
# *1{*1}
A *1
```

マクロが自分自身を呼び続けています。繰り返しが必要なら、再帰ではなくリピート構文で表現する必要があります。

### 長い行を分ける方法

```muc
A o4 l8 cdefgab>c
A <bagfedcr
```

前の行と同じチャンネル文字を次の行にも書きます。画面上の自動折り返しだけでは、実際のファイルの一行は分かれません。エディタで改行文字を入れる必要があります。

マクロの長さ超過であれば、本体を短く分けて呼び出し構造も単純に整理します。行を分けるだけでマクロ本体全体のサイズ制限がなくなるわけではありません。

<a id="15"></a>

## 15. 警告メッセージ案内

警告は、ソースを自動的に直したという意味ではありません。一部の内容を無視したまま結果を作ることがあるので、意図した曲になっているかを確認する必要があります。

| メッセージ | 意味 | 解決方法 |
|---|---|---|
| `Invalid channel prefix; use A-K + space/tab` | 正しくないチャンネル行 | 行の1文字目の大文字A〜K、その次の空白・タブを確認。インデント・カンマ・小文字を修正 |
| `Unknown or malformed tag` | 知られていないタグ、または誤ったタグ表記 | タグ名・形式を確認。他のコンパイラ専用のタグでないか検討 |
| `Missing tag value` | 値を要求するタグに値がない | タイトル・ファイル名など必要な値を埋める。空の`#comment`は許容 |
| `Tag outside initial header is ignored` | 最初のヘッダ区間の外のタグ | ファイル冒頭の連続したヘッダへ移動 |
| `Warning: PCM file not found:` | 指定または既定のPCMファイルが見つからない | Kチャンネルの使用有無、現在のフォルダ、実際の8.3名を確認 |

行に関する警告は次のように出ます。

```text
Warning line 4: Invalid channel prefix; use A-K + space/tab
>  A o4 c
```

「警告はあったが正常終了した」という結果を、バッチの集計でそのまま成功に合算しないでください。少なくとも警告が意図されたものかを確認したうえで、最終的な成功に分類するのがよいでしょう。

逆に、警告がひとつもないという事実だけで、外部音色ファイルの内容やPCM形式が正しいと判断してもいけません。現在、すべてのアセットの問題が警告の対象として捕まるわけではありません。

<a id="16"></a>

## 16. ファイル・ディスク・メモリのエラー

これらのエラーは、MMLの文法を直すだけでは解決しないことがあります。

| 画面メッセージ | まず確認すること |
|---|---|
| `Usage: MUC2MUB <input.muc> [output.mub]` | 入力引数があるか、基本の呼び出し形式を守っているか |
| `Invalid name/arguments (input: 8.3, no path).` | 長い入力名、パス、引用符、空白、追加の引数、引数の長さ、出力ファイル名・入力保護の検査 |
| `Cannot open input file` | 現在のドライブ・フォルダ、実際のDOSファイル名、ファイルの存在 |
| `Cannot read input file` | 媒体の読み取り問題、破損ファイル、接続状態 |
| `Input exceeds 64 KiB.` | 生のファイルが65,536バイトを超えていないか。非常に長い行による読み込み限界も点検 |
| `Error: Mapper unavailable or insufficient memory.` | DOS 2のマッパーサービス、割り当て可能なセグメント、メモリを占有している他のプログラム |
| `Cannot create output file` | 出力フォルダの存在、書き込み可否、名前・パスの長さ、読み取り専用の対象、残った一時・バックアップファイル、ディレクトリ項目の空き |
| `Cannot write output file` | ディスク領域、書き込み禁止、媒体エラー。要求より少なく書けた場合も失敗として扱う |
| `Cannot close output file` | ファイルを閉じることだけでなく、最終的な名前の置き換え・バックアップの片付けの失敗の可能性。最終・一時・バックアップのすべてのファイルを確認 |
| `Cannot read PCM file` | PCMの読み込み途中での失敗、または保存段階でPCMを開き直せなかった |
| `Output buffer overflow` / `Error: output buffer overflow` | 音楽DATAが出力領域に収まらない。入力サイズ・ディスク領域とは別の問題 |

### ディスクは空いているのに作成に失敗するなら

空きバイトだけを見ず、次も確認してください。

- 目的のフォルダが実際にあるか。
- 既存の出力が読み取り専用やシステムファイルになっていないか。
- 同じ名前のディレクトリなどがないか。
- `M2MTEMP.$$$`または`M2MBACK.$$$`がすでにないか。
- とくにFATのルートディレクトリのファイル項目が埋まっていないか。
- 出力パスが長すぎないか。

プログラムは読み取り専用属性を勝手に解除しません。既存のファイルがなぜ保護されているのか、先に確認してください。

### RAMが十分に見えるのに起動できないなら

DOSがマッパーを提供しているか、既定の割り当て先から8セグメントを確保できるかを確認します。他のプログラムがメモリを使っている状態なら、終了してから再試行してください。物理RAMの総量と、DOSがいま割り当てられるメモリは同じ値ではありません。

### エラーのあとにMUBが残っているなら

そのファイルは、いま作られた結果ではなく、以前に正常に保存されていたファイルかもしれません。原本を守るために残してあるものです。ファイルがあるというだけの理由で、今回の変換を成功と判断しないでください。

## 17. 安全な保存と中断後の復旧

すでにあるMUBを最初から切り詰めて書き直す方式は使いません。新しい結果を一時ファイルとして完成させてから置き換えます。

### 正常な保存の順序

1. 出力フォルダに`M2MTEMP.$$$`を新しく作ります。
2. 新しいMUBの内容を最後まで記録して閉じます。
3. 既存の出力があれば、名前を`M2MBACK.$$$`へ変えます。
4. 一時ファイルを、要求された最終的なMUB名へ変えます。
5. 正常に置き換わったあと、以前のファイルのバックアップを片付けます。

保存中は、以前の結果と新しい結果が同時に存在できる領域が必要です。既存のMUBを残したまま、新しいMUB全体を書ける余裕を確保してください。バックアップは以前のファイルの名前を変えるものなので、以前のデータの3つ目の完全なコピーを作る方式ではありません。ただしディレクトリ項目は追加で必要です。

一時ファイルの書き込み・クローズが失敗した場合は、既存の最終ファイルを保存します。名前の置き換えが失敗した場合は、以前の名前への復旧を試みます。復旧さえ失敗したときは、以前のファイルのバイトを`M2MBACK.$$$`に残します。

置き換えが終わったあと、バックアップの削除だけが失敗する場合もあります。この場合、エラーが表示されても、新しい最終MUBと以前のバックアップが同時に存在することがあります。メッセージだけでどのファイルが最新かを断定せず、内容を確認してください。

### 一時ファイル名は予約しておいてください

`M2MTEMP.$$$`と`M2MBACK.$$$`がすでにあると、プログラムはむやみに上書きせず中断します。利用者が作ったファイルや、以前の失敗の復旧資料かもしれないからです。出力名としてこの2つの名前を使わないでください。

### Ctrl-C、STOP、媒体エラー

DOSの中断処理では、自分が開いておいた一時出力ハンドルを片付けようとします。しかしディスク自体が書き込み不能であれば、一時ファイルの削除まで成功する保証はありません。

Ctrl-CやSTOPは、現在の曲だけでなくBAT全体の中断につながることがあります。DOSがバッチを終了するか尋ねてきたら、画面の質問に従って応答してください。中断後に同じBATがひとりでに続きを実行すると想定しないでください。

### 再実行する前の復旧手順

1. 媒体を安定して接続し、現在のフォルダと出力フォルダを確認します。
2. 最終的なMUB、`M2MBACK.$$$`、`M2MTEMP.$$$`の存在とサイズを確認します。
3. 残ったバックアップ・一時ファイルは、まず別の名前や別の媒体へ保管します。
4. バックアップが以前の正常なファイルか確認します。一時ファイルは不完全であり得るので、そのまま配布しません。
5. 最終ファイルがなく、バックアップが以前の正常な結果であれば、そのバックアップを保存したうえで復旧します。
6. 領域・属性・媒体の問題を解決し、予約ファイル名が衝突しないよう整理してから再コンパイルします。

たとえばバックアップの内容が以前の正常なMUBだと確認できたなら、`RECOVER.MUB`のような名前でコピーして保管できます。ここでは、内容を確認せずに一括削除する復旧コマンドは案内しません。復旧の可能性を先に残しておくことが重要です。

この保存方式も、電源の遮断やFATの破損まで原子的に保証するものではありません。重要な原本と完成品は、別の媒体にもバックアップしてください。

## 18. オリジナルのMUBと比較する、MD5の使い方

### 何が同じであれば「同じMUB」なのか

比較の水準を分けて見ると、原因を見つけやすくなります。

| 比較対象 | 確認する内容 |
|---|---|
| 音楽DATA | チャンネルイベントと実際のFM音色パラメータが同じか |
| PCMブロック | 同じバンクの同じバイトが含まれているか |
| タグ・ヘッダ | タイトル、改行、長さ・オフセット、追加メタデータが同じか |
| ファイル全体 | 最初から最後まですべてのバイトと全体の長さが同じか |

FM音色の個数やチャンネルテーブルが同じでも、実際の25バイトの音色パラメータが違うことがあります。DATAのサイズが同じであることも、DATAの内容が同じという意味ではありません。

### 入力ごとの`.MD5`ファイル

現在のバージョンは、MUCの原文ハッシュを入れるために、入力と同じ名前の`.MD5`ファイルを読みます。

```text
SONG.MUC  →  SONG.MD5
BOS010.MUC  →  BOS010.MD5
```

出力ファイルを`TEST.MUB`と指定しても、入力が`SONG.MUC`であればハッシュファイルは`SONG.MD5`です。かつての共通の`MUBHASH.TXT`は使いません。

ファイル内容の条件は次のとおりです。

- 該当するMUCの**原文バイト全体**のMD5です。
- ASCII 16進数32文字だけを入れます。
- 改行、BOM、空白、ファイル名は入れません。
- ファイルサイズはちょうど32バイトでなければなりません。
- 大文字の16進数も受け付けますが、出力では小文字に正規化します。

`.MD5`がなかったり、サイズ・文字が誤っていたり、読み込みに失敗したりすると、`#mmlhash`にASCII文字の`0`を32個記録します。これはMUB全体や音楽DATAを0にするという意味ではありません。

なにより、**MSXでMD5を計算して原文と突き合わせる機能ではありません。** 形式の合った外部の値を受け取って入れる機能です。古い`.MD5`でも形式さえ合っていればそのまま入り得るので、MUCを修正したならハッシュも作り直す必要があります。

### PCで`.MD5`を作る

以下はMSX-DOSのコマンドではなく、**PCのPython 3で実行する例**です。作業フォルダの`SONG.MUC`を読んで`SONG.MD5`を生成または更新します。

```python
from pathlib import Path
import hashlib

source = Path("SONG.MUC")
digest = hashlib.md5(source.read_bytes()).hexdigest()
source.with_suffix(".MD5").write_bytes(digest.encode("ascii"))
```

バイナリで読み書きするため改行を変換せず、`.MD5`の末尾に改行も付けません。作られたファイルをMUCと一緒にMSX側へ移してください。転送の過程でMUCの文字エンコーディングや改行を変えた場合は、計算し直す必要があります。

### オリジナルと完全に一致させるには

1. MUCが同じ原文バイトかを確認します。
2. 同一のFM音色ライブラリとPCMバンクを使います。
3. 入力に合った`.MD5`を用意します。
4. 同じ文法・互換基準のコンパイル結果どうしを比較します。
5. ヘッダ、DATA、タグ、PCMを分けて差異を探します。

オリジナルのMUBが別のバージョン・オプション・メタデータ規則で作られていたなら、音楽DATAが同じでもファイル全体は異なり得ます。このバージョンの追加タグには`#mucver 1.7d`、`#mmlhash`、固定UUIDが入ります。このUUIDを、曲ごとに新しく計算した固有の識別子だと解釈しないでください。

単純なバイト全体の比較もPCで行えます。

```python
from pathlib import Path

original = Path("ORIGINAL.MUB").read_bytes()
compiled = Path("TEST.MUB").read_bytes()
print("完全一致" if original == compiled else "差異あり")
print("原本:", len(original), "バイト / 結果:", len(compiled), "バイト")
```

この比較は、長さまで含めた完全一致の検査です。差異があると出たからといって、ただちにコンパイラの音楽DATAの誤りだと断定せず、どのセクションが違うのかを確認してください。逆に、よく聞こえるという理由でバイナリの差異をないものとして扱ってもいけません。

<a id="19"></a>

## 19. mucplay・mucEdit・mubplayと一緒に使う

各プログラムの役割は、次のように分けて考えると分かりやすくなります。

- **muc2mub**: DOSでMUCをコンパイルし、MUBファイルとして保存します。
- **mucplay**: MUCをコンパイルして再生する作業に使います。
- **mucEdit**: ソースを編集し、mucplayと連携して確認する作業に使います。
- **mubplay**: 作られたMUBを再生する側で使います。

共有コンパイラを使うプログラムは、互いに合った最新のビルドの組み合わせを使うのがよいでしょう。古い実行ファイルが別のフォルダやDOSの検索パスに残っていると、新しいバージョンを試したつもりで以前のバージョンを実行してしまうことがあります。

muc2mubが読むのは、**ディスクに保存されたMUC**です。エディタに未保存の変更が残っていれば、別途実行したmuc2mubはその変更を知りようがありません。独立した変換を行う前にソースを保存してください。

standaloneのmuc2mubの64 KiB入力対応を、mucEditの編集バッファ上限としてそのまま解釈しないでください。現在の連携エディタには、別途の正規化ソース24 KiBの上限があります。大きなファイルを独立してコンパイルできることと、エディタで同じサイズを編集できることは別です。

エディタ連携やmucplayの持続セッションでは、未保存の編集内容を以前の原文ファイルのMD5として表示することはしません。したがって音楽DATAが同じでも、単独のmuc2mubと`#mmlhash`が異なることがあります。このときはハッシュの差異と音楽データの差異を分けて比較してください。

## 20. よくある質問

### Z80モードでも動きますか。

はい。Z80を対象とするDOSプログラムであり、Z80構成で検証しています。R800は必須ではありません。

### 平均的なコンパイル時間はどのくらいですか。

ソースのサイズだけでは決まりません。チャンネル構成、イベント数、マクロ、音色、PCMのサイズ、記憶装置とDOS環境によって変わります。エミュレータの加速実行の時間も、実機Z80の時間と同じではありません。この説明書では、根拠のない平均秒数を提示しません。

測定するときは、CPUモード、エミュレータの速度設定、マッパー構成、記憶媒体、MUC・PCMのサイズも一緒に記録し、同じ曲を何度か実行してみてください。プログラムの開始から`Done.`までの時間は、純粋なコンパイルだけでなくファイルの読み込みと保存も含みます。

### MUBの平均サイズは。

固定された比率はありません。コメントは音楽イベントへ変換されず、マクロ呼び出しはイベントを増やすことがあり、PCMは最終的なファイルサイズを大きく増やします。まずDATAとPCMのサイズを分けて見てください。

### 64 KiBのMUCなら、MUBも64 KiBまでですか。

いいえ。入力ソースの上限、音楽DATA領域、最終的なファイルサイズはそれぞれ別です。最終的なMUBはPCMのために64 KiBより大きくなり得ます。

### `Done.`なのにFMの音がおかしいです。

外部音色ファイルの存在と内容、現在のフォルダ、8.3名をまず確認してください。インライン定義の番号・パラメータの順序も確認します。音色ファイルの欠落が常にエラーとして報告されるわけではありません。

### FMは鳴るのにPCMだけ鳴りません。

PCMの欠落警告、Kチャンネルの使用有無、`#pcm`の位置とファイル名、バンクの内容、プレイヤーのADPCM対応を順に確認します。もとのサンプルファイルと別のファイルを入れた可能性も見てください。

### 曲の一部のチャンネルだけ抜けます。

チャンネル行がインデントされていないか、小文字・カンマ形式になっていないかを確認します。警告ログと元の行を見てください。ファイル途中の制御文字、誤ったマクロ、非対応の文法も確認の対象です。

### ないPCMの警告を隠すオプションはありますか。

現在、警告の抑制や厳格モードといった別のオプションはありません。ログを確認して、PCMが不要な曲の警告なのか、実際の欠落なのかを区別してください。

### 既存のMUBを上書きしないようにできますか。

無条件の上書き禁止という別のオプションはありません。別の出力名やフォルダを指定してください。正常な既存の出力は、安全な保存手順を経て置き換えられます。

### 失敗したのに以前のMUBがそのままあります。

既存の結果を保護したためです。今回の実行が成功したという意味ではありません。ログと終了状態を確認してください。

### 4 MiBのRAMなのに出力バッファ超過が出ます。

搭載RAMと音楽DATAの上限は別です。現在の2つの出力セグメントの上限は、増設に応じて自動的に増えることはありません。

### `.MD5`がないとコンパイルできませんか。

コンパイルできます。原文ハッシュを表す部分に文字`0`を32個入れます。再生用に使うことと、オリジナルのMUBとのバイト全体一致を確認することは、別の要求です。

### コンパイルさえ終われば完成品として配布してよいですか。

まず警告、外部アセット、結果の再生を確認してください。オリジナルの再現が目的なら、バイナリ比較まで行う必要があります。コンパイルの成功は、完成確認のひとつの段階です。

- [ ] 編集したMUCをディスクに保存した。

- [ ] オリジナルの再現が目的なら、DATA・PCM・タグ・バイト全体を比較した。
- [ ] 最終的な配布に必要な著作権とアセットの使用条件を確認した。
- [ ] 元のソースと必要なアセットを別途バックアップした。

### 複数の曲を変換したとき

### 問題を知らせてくださるとき

「コンパイルできません」よりも、以下の情報を一緒にいただけると、原因をずっと早く絞り込めます。

```text
MUC2MUBのバージョン:
MSXの機種 / エミュレータと機種設定:
CPUモード:
DOS / Nextorのバージョン:
メモリマッパー構成:
```
