# MUBPLAY 取扱説明書

MUCOM88 MUB Player for MSX  
Written by ToughkidCST

`MUBPLAY`は、MUCOM88のMUB音楽ファイルをMSXで鑑賞するために作ったプレイヤーです。MakotoカートリッジのYM2608を使って、FM、SSG、リズム、ADPCMを再生します。

MSX-DOS2上で`MUBPLAY`のうしろに聴きたいMUBファイル名を付けるだけです。はじめて使う方のために、用意するものから順を追って説明します。

この説明書は、**Makoto(YM2608)用の`mubplay.com`**を基準に書いています。

### MUBで聴くと何がよいのですか

MUBの長所のひとつは、**同じ曲を収めた非圧縮のVGMに比べてファイルサイズがはるかに小さいこと**が挙げられます。保存容量に余裕のないMSX環境では、PCMを伴う音楽ファイルにとってかなりありがたい長所でもあります。

VGMは、演奏しながら音源チップへ送るコマンドと、その間の時間を記録します。一方MUBは、音符・音色・効果などの音楽データを保存し、プレイヤーがそれを解釈して演奏します。平たく言えば、VGMは音源チップを動かした記録に近く、MUBはプレイヤーが読んで演奏する楽譜に近いものです。ひとつの音を保っているあいだにも変わり続ける効果を、VGMでは複数のコマンドとして記録することになりますが、MUBでは効果を指定する短いコマンドで表現できます。

使う側から見ると、次の点がよいところです。

- **同じディスクにより多くの曲を入れられます。** ファイルが小さければ、フロッピーディスクやSDカードに音楽をまとめておくのが楽になります。
- **ファイルのコピーと管理が軽くなります。** 運ぶデータが減るので、複数の曲をMSXへ持ち込むときやバックアップするときにも有利です。

ただし、すべての曲でサイズの差が一定というわけではありません。PCMが大きな割合を占める曲はMUBも大きくなりますし、圧縮されたVGZと比べれば差は縮まることがあります。ファイルが小さいからといって、PCMの転送時間がなくなったり、CPU負荷まで必ず減ったりするわけでもありません。MUBPLAYは音楽データを直接解釈して演奏するので、機種の処理性能も重要です。

小さな曲ファイルをディスクに入れておき、MSXでひとつずつ取り出して聴く用途に使ってみていただければと思います。

## 1. 用意するもの

一般的な音楽再生には次のものが必要です。

- MSX-DOS2またはNextorを使うMSX環境
- プログラムと曲データを載せられる空きメモリとメモリマッパー環境
- Makoto(YM2608)カートリッジ
- `MUBPLAY.COM`
- 再生する`.MUB`ファイル

曲によって必要なメモリとローディング時間は異なります。DOSが動くというだけで、あらゆるサイズの曲を再生できるわけではありません。

MSX2+の通常のZ80環境でも使用でき、turbo R環境も考慮しています。ただし同じ曲でも、機種と処理の余裕によって再生状態にわずかな差が出ることがあります。

実機では、Makotoの音が実際に接続したスピーカーやミキサーへ入っているかも確認してください。MSX本体の音は聞こえるのにMakoto側の音だけ聞こえない場合は、まずオーディオ接続と音量を確認するのがよいでしょう。

### 他のサウンドカートリッジでも再生できますか

この説明書の実行ファイルはMakoto用です。MSX-MUSICやSCCだけで代わりに再生することはできません。Neotron-B(YM2610B)用のバージョンも準備していますが、この実行ファイルとは区別して使ってください。このバージョンに出力デバイスを選ぶコマンドラインオプションはありません。

## 2. もっとも簡単に再生する

まずは`MUBPLAY.COM`とMUBファイルを同じディレクトリに置いて実行してみてください。

たとえば次の2つのファイルがあるなら、

```text
MUBPLAY.COM
SIN002.MUB
```

DOSでこう入力すればよいだけです。

```text
MUBPLAY SIN002.MUB
```

`.COM`は省略できます。曲ファイルは`.MUB`まで書いてください。

この説明書のコマンド例にはDOSプロンプトを入れていません。画面に`D:\>`が見えていても、例のコマンド部分だけを入力してください。

### 別のドライブにある曲を再生する

`MUBPLAY.COM`を実行できる場所から、曲のパスを指定することもできます。

```text
MUBPLAY D:\SIN002.MUB
```

サブディレクトリにある曲なら、このように入力します。

```text
MUBPLAY D:\MUSIC\SIN002.MUB
```

ファイル名はDOSで見える名前を使ってください。最初は短い8.3形式の名前と簡単なパスを使うのが楽です。現在のコマンドラインには、空白の入ったパスを引用符で囲んで扱う機能はありません。

1回の実行で指定する曲はひとつです。複数のファイル名を並べたり、`*.MUB`を指定して連続再生したりする機能はありません。

## 3. 実行するとどんな画面が出ますか

正常にロードされると、次のような表示が出ます。曲情報はファイルに入っている内容によって変わります。

```text
MUBPLAY - MUCOM88 MUB Player for MSX
Written by ToughkidCST

Loading MUB file with Makoto (YM2608)
Title : THE SHINOBI
Composer : Yuzo Koshiro
Author : Yuzo Koshiro
Date : 2018/12/12
Comment : sin002
Press any key to stop.

```

ローディングが終わると曲情報を表示し、最後の案内と画面スクロール処理を終えてから自動的に演奏を始めます。開始のためにもう一度キーを押す必要はありません。

PCMデータが入っている曲は、Makotoへデータを転送する時間が必要になることがあります。そのため`Loading MUB file with Makoto (YM2608)`でしばらく止まって見えることがあります。ファイルサイズとディスク速度によって、かかる時間も変わります。

### 再生を中断するには

演奏中に**ESCやスペースのような通常のキーを押せば**中断してDOSへ戻ります。ESCだけが有効なわけではありません。ShiftやCtrlだけを押すような、文字入力の発生しないキー操作は中断キーとして使わないでください。

オプションがなければ、既定では1回演奏して終了します。リピート区間のある曲はその区間のリピート境界を基準に終了し、リピート区間のない曲はすべてのチャンネルの演奏が終わると終了します。

現在、一時停止、再開、曲の前後移動、チャンネル別ミュートの機能はありません。最初から聴き直したい場合は、中断してから同じコマンドをもう一度実行してください。

## 4. 繰り返して聴く

リピート回数は`/L`オプションで指定します。数字は`/L`の直後に付けます。

| 入力例 | 動作 |
| --- | --- |
| `MUBPLAY SIN002.MUB` | 既定の1回演奏 |
| `MUBPLAY SIN002.MUB /L1` | 1回演奏 |
| `MUBPLAY SIN002.MUB /L2` | 2回目の演奏区間までリピート |
| `MUBPLAY SIN002.MUB /L3` | 3回目の演奏区間までリピート |
| `MUBPLAY SIN002.MUB /L0` | リピート回数の制限なしで演奏 |

かけっぱなしにしたいときは、次のように実行すればよいでしょう。

```text
MUBPLAY GH002.MUB /L0
```

やめたいときにキーを押せば終わります。

ここでのリピートは、**MUBの中に指定された音楽のリピート区間**に従います。ファイルを毎回読み直してイントロから再生しなおす方式ではありません。曲がイントロのあとの特定の位置へ戻るように作られていれば、その位置から繰り返します。

リピート区間のない曲に`/L0`を指定しても、新しいリピート区間ができるわけではありません。この場合は曲が終われば終了します。

現在、数字は1桁の`0`から`9`までを使います。`/L10`や`/L30`のように2桁の数を指定する用途には使えません。`/L 3`のように数字を空けて書かず、`/L3`と書いてください。

数字なしで`/L`だけを指定しても既定で無制限リピートを選びますが、意味の明確な`/L0`表記をおすすめします。

## 5. 曲情報を読む

MUBファイルに次のタグが入っていれば、ローディング後に表示します。

| 画面の項目 | ファイル内のタグ | 内容 |
| --- | --- | --- |
| `Title :` | `#title` | 曲のタイトル |
| `Composer :` | `#composer` | 作曲者 |
| `Author :` | `#author` | データ制作者または編曲者など、ファイルに記録された作成者 |
| `Date :` | `#date` | ファイルに記録された制作・変換の日付 |
| `Comment :` | `#comment` | 説明とコメント |

情報のない項目は表示しません。タイトルだけ出る曲もあり得ますし、曲情報なしですぐ再生の案内が出ることもあります。それだけでファイルに問題があると判断する必要はありません。

表示順序は、ファイルに記録されたタグの順序に従います。`#comment`が複数入っていれば、複数行で表示されることがあります。日付も、現在の日付やファイルの更新日を自動で入れるのではなく、MUBに保存された値を表示します。

### 日本語のタイトルはどう表示されますか

現在のタイトル出力は、英数字と半角カタカナを基準に処理しています。半角カタカナの実際の形は、使用中のMSXの文字環境にも左右されます。

たとえば`ARG014.MUB`のタイトルは半角カタカナなので、日本語MSX環境では次のように表示されます。

```text
Title : ｶﾗｸｰﾑ ﾉ ﾏﾁ
```

漢字や全角の日本語のように、現在の出力方式では表示できない文字がタイトルに含まれている場合は、崩れた文字を出す代わりに、タイトル全体を次のように表示します。

```text
Title : [Japanese Title]
```

タイトルの一部が英数字であっても、表示できない文字が一緒にあればタイトル全体が置き換えられます。

現在は、漢字ROMのある機種でもプレイヤーが自動的に漢字画面へ切り替えることはありません。またこの置き換え処理は`Title`項目にのみ適用します。他の項目に全角の日本語が入っていれば、その項目は崩れて見えることがあります。

## 6. VOICE.DATやPCMファイルも一緒に入れる必要がありますか

完成したMUBを再生するときは、**別途の`VOICE.DAT`は必要ありません。** プレイヤーはMUBに含まれるFM音色データを使います。

PCMも、MUBの中に含まれるPCMブロックを読みます。タグに`#voice voice.dat`や`#pcm mucompcm.bin`という記録が見えても、それは再生時に同じ名前の外部ファイルを探して読むという意味ではありません。

最初は`MUBPLAY.COM`と再生するMUBファイルだけを用意して使っていただければ大丈夫です。

ただし、PCMを使う曲なのにMUBを作るときに必要なPCMデータが含まれていなかった場合、プレイヤーが外部のPCMファイルを探して自動的に補うことはありません。そのような場合は、MUBを作る段階で含まれているかどうかを確認してください。

また`.MUC`はコンパイル前の音楽ソースです。`MUBPLAY`に直接渡すファイルは、コンパイルの終わった`.MUB`です。

## 8. オプション一覧

基本の形式は次のとおりです。

```text
MUBPLAY ファイル名.MUB [/L数字] [/T] [/V]
```

角括弧は、必要なオプションだけを選んで入れるという意味です。実際のコマンドに`[`や`]`を入力することはありません。

| オプション | 用途 |
| --- | --- |
| `/L0` | 通常再生で無制限リピート |
| `/L1` ～ `/L9` | 通常再生でリピート回数を指定 |
| `/T` | 演奏を始めずにローディング経路を点検 |
| `/V` | 再生データをVGMファイルとして出力 |

オプション文字は大文字小文字を区別しません。`/l2`も使えますが、この説明書では読みやすさのため大文字で統一しています。

ふだん音楽を聴くには、ファイル名と、必要なときの`/L`オプションだけ知っておけば十分です。以下の2つの機能は、ファイルの点検や比較作業が必要なときに使ってください。

## 9. ローディングだけ点検する: /T (デバッグ用)

```text
MUBPLAY GH002.MUB /T
```

曲を読む過程を実行したあと、演奏を始めずに終了します。成功すると次のメッセージが出ます。

```text
Load test OK.
```

このモードではメモリマッパー情報も表示します。結果表示用のファイルとして、カレントディレクトリに`LT_OK.TXT`または`LT_NG.TXT`を生成・更新しようとします。このファイルは人が読む詳細なレポートではなく、点検用の表示ファイルです。以前の実行のファイルが残っていることがあるので、ファイルが存在するという事実だけで今回の結果を判断せず、画面のメッセージも確認してください。

ひとつ注意点があります。現在の`/T`は**音楽の演奏を始めないモード**であって、サウンドカートリッジにまったくアクセスしないモードではありません。PCMの入ったMUBは、ローディング中にMakotoへPCMを転送する経路も実行します。したがって、Makotoのない環境で安全にファイル形式だけを検査するツールとしては使わないでください。

`Load test OK.`は、ローディング経路が成功したという意味です。曲全体の音色やすべての再生コマンドまで検証したという意味ではありません。

## 10. VGMファイルとして出力する: /V

MUBの再生データをVGMとして保存する機能です。音を録音してWAVやMP3を作る機能ではなく、音源チップへ送るコマンドとタイミングをファイルに記録する機能です。

```text
MUBPLAY SIN002.MUB /V
```

出力名は、入力MUBの拡張子を`.VGM`に変えて作ります。上の例では`SIN002.VGM`になります。入力パスにディレクトリがあれば、出力も同じパスを基準にします。

**同じ名前のVGMがすでにあれば、確認の問い合わせなしに上書きします。** 以前のファイルを保管したい場合は、実行前に別の名前へ移しておいてください。入力MUBをVGMに変えたり削除したりすることはありません。

### /Vと一緒に使う/Lは意味が違います

現在のバージョンでは、`/V`を指定したときの`/L`の数字を、**リピート回数ではなく出力する音楽の時間(秒)**として使います。

```text
MUBPLAY SIN002.MUB /V /L5
```

このコマンドは約5秒分を出力します。作業そのものが実際の時計で5秒以内に終わるという意味ではありません。ファイル書き込みとPCMデータの処理速度によって、作業時間は変わります。

| 入力例 | VGM出力の分量 |
| --- | --- |
| `MUBPLAY SIN002.MUB /V` | 既定の約30秒 |
| `MUBPLAY SIN002.MUB /V /L5` | 約5秒 |
| `MUBPLAY SIN002.MUB /V /L9` | 約9秒 |
| `MUBPLAY SIN002.MUB /V /L0` | 既定の約30秒 |

ここでも数字は1桁だけ処理します。`/L30`で30秒を指定しないでください。既定の30秒がよければ`/V`だけを使えば済みます。音楽の処理単位に合わせて記録するため、結果の長さは指定した秒数と少し異なることがあります。

`/V`は、通常再生のキー入力による中断と同じ動作を提供しません。指定した分量の出力が終わるまで待ってください。`/T`と`/V`を同時に指定すると`/T`が優先されるので、この2つのオプションは別々に使ってください。

この機能は比較・点検用の補助機能です。出力ファイルを確認するときは、YM2608に対応したVGM再生環境を使う必要があります。MSXのVGMPLAYで確認するなら、Makoto(YM2608)を使う環境に合わせてください。

## 11. 問題が起きたとき

### `MSX-DOS 2 is required.`と出ます

現在の実行環境が、必要なDOS2の条件を満たしていない場合です。MSX-DOS2またはNextorで起動した状態かどうか確認してください。BASIC画面からそのまま使うプログラムではありません。

### `ERROR: YM2608 (Makoto) not detected.`と出ます

Makotoを検出できませんでした。実機ではカートリッジの接続を、openMSXTKではMakoto extensionが実際に挿さっているかを確認してください。

MegaFlashROM SCC+ SDだけを入れた状態では、Makotoは追加されません。2つのextensionは役割が異なります。

### `ERROR: Failed to load MUB file.`と出ます

ファイルを読むこと、またはMUBとして処理することに失敗したという意味です。次の順序で確認してみてください。

1. `DIR`でファイル名が実際に見えるか確認します。
2. 現在のドライブとディレクトリが合っているか確認します。
3. `.MUC`ではなく、コンパイル済みの`.MUB`かどうか確認します。
4. 他のMUBファイルでも同じ症状が出るか確認します。
5. ファイルのコピー中に壊れたり、一部だけコピーされたりしていないか確認します。

ファイルの拡張子だけを`.MUB`に変えても再生はできません。またこのエラーメッセージひとつだけで、原因がPCMなのか、パスなのか、ファイルの内容なのかを確定することはできません。

### ローディング画面で長く待たされます

PCMの大きい曲は転送時間が必要です。まずは他の小さい曲と比べてみてください。特定の曲だけで長くかかるのか、すべての曲で進行が止まるのかを区別すると、原因を探すのに役立ちます。

長いあいだまったく進まない場合は、単に大きいファイルだからと決めつけず、ファイル名と環境を一緒に知らせてください。

### `ERROR: Insufficient TPA space.`やメモリ関連のエラーが出ます

プログラムが使えるメモリの余裕を確認してください。常駐プログラムやドライバの構成によって空き容量は変わります。不要な常駐プログラムを減らした環境と、小さなMUBファイルでも比べてみるとよいでしょう。

### タイトルが`[Japanese Title]`と表示されます

正常な動作です。現在の画面出力では処理できない文字がタイトルに含まれているという意味です。曲ファイルが壊れたという意味ではなく、元のタイトルと音楽データも変わりません。

### 音が出ない、または一部の音だけ違います

まずMakotoのオーディオ出力と音量を確認してください。特定の曲のADPCMだけが抜けるなら、MUBの中に必要なPCMが含まれているかも確認する必要があります。`VOICE.DAT`を横にコピーする方法で解決する問題ではありません。

同じファイルを使っても原曲と音色・テンポが違う場合は、その違いを知らせてください。Z80とturbo R環境の差、特定区間の処理負荷、ファイルの再生コマンドなども確認する必要があります。

### `An exception occurred`や`Address out of bounds`が出ます

正常な曲の終了メッセージではありません。エラーが出た曲の名前と、表示されたアドレス・メッセージを、できるかぎりそのまま残してください。ローディング中なのか、演奏を始めた直後なのか、特定の区間なのか、終了するときなのかも重要です。

エラーのあとも音が残り続ける場合は、まず外部の音量を下げてください。この場合は、正常な終了処理が終わっていないものとして確認する必要があります。

## 12. 再生に問題があるとき

曲が違って聞こえたりエラーが出たりする場合は、次の内容を一緒に知らせていただけると、確認がずっと楽になります。

- 使用した`MUBPLAY.COM`の配布版、または受け取った日付
- MUBファイル名と、可能であれば再現に使ったファイル
- MSXの機種とCPUの実行モード
- MSX-DOS2・Nextorおよびカートリッジ構成
- 実際に入力した実行コマンド
- エラーメッセージ、または問題の聞こえる区間
- 比較する原曲の音源と、現在の再生を収めた録音・映像

映像は、画面だけよりも音が一緒に入っているほうがよいです。たとえば「イントロで遅くなってから速くなる」「FMのメロディが違う」「ドラムは出るのにPCMがない」のように、聞こえる違いを説明してください。

ESCで途中終了した映像であれば、そのことも書いてください。キャプチャの長さが異なる理由と、実際の音楽の速度差を区別するのに役立ちます。

## 13. よく使うコマンド集

1曲聴く:

