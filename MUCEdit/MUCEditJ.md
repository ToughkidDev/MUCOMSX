# MUCEdit 取扱説明書

## MSXでMUCを編集し、コンパイルし、音楽を聴いてみる

**MUCEdit v0.8 by ToughkidCST**  
文書基準日: 2026年9月14日

MUCEditは、MSX上でMUCOM88のMUCファイルを直接開いて編集するためのテキストエディタです。MUCPLAYと併用すれば、編集しているその場でコンパイルして曲を聴き、そのまま戻って修正できます。完成した曲をMUBやVGMとして書き出すこともできます。

最初からすべてのコマンドを覚える必要はありません。まずファイルを開き、一箇所を変えて、コンパイルして聴いてみてください。この説明書もその順序で読んでいただければ大丈夫です。後半には、MUC文法、エラーと警告、問題が起きたときに確認すべき点をまとめてあります。

始める前に、ひとつだけ覚えておいてください。

> **保存・コンパイル・演奏は、それぞれ別の操作です。**  
> 保存は元のMUCファイルを更新します。コンパイルは現在の編集内容を演奏データに変換します。演奏は最後にコンパイルした結果を再生します。

この違いを理解しておくと、MUCEditはぐっと使いやすくなります。

## 1. MUCEditとMUCPLAYの役割

名前は似ていますが、役割は異なります。

| 構成要素 | 役割 |
|---|---|
| `MUCEDIT.COM` | MUCテキストの編集、ファイル入出力、ブロック選択、検索、Undo/Redo、コマンドメニュー |
| `MUCPLAY.COM` | MUCの読み込みとコンパイル、演奏、MUB/VGM出力、コンパイル結果とエラーの表示 |
| `MUBPLAY.COM` | コンパイル済みの`.MUB`ファイルを単独で演奏するプレイヤー。Makoto(YM2608)用 |
| `.MUC` | 人が読んで直せる曲のソーステキスト。DOSから`MUCPLAY SONG.MUC`で直接再生でき、内部でコンパイルしてから演奏します。 |
| `.MUB` | コンパイル済みの曲データ。必要に応じて音色・タグ・PCMを含み、DOSから`MUBPLAY SONG.MUB`で直接再生できます。 |
| `.VGM` | 再生過程の音源チップコマンドとタイミングを記録したファイル。DOSから`VGMPLAY SONG.VGM`で直接再生できます。 |

上記コマンドの`SONG.MUC`、`SONG.MUB`、`SONG.VGM`は例です。実際に聴きたいファイル名に置き換えて入力してください。それぞれのプレイヤーと、その曲の音源チップに対応した実行環境が必要です。

MUCEditだけでもテキストの編集と保存はできます。F1メニューのコンパイル・演奏・書き出しを使うには、互換性のあるMUCPLAYが一緒に必要です。この作業のために別途`MUC2MUB.COM`を実行する必要はありません。コンパイラはMUCPLAYに含まれています。

MUBPLAYは、完成したMUBを単独で聴くときに使います。たとえばMUCEditでF1→4を使って`SONG.MUB`を書き出したなら、DOSから`MUBPLAY SONG.MUB`で演奏できます。MUCEditのF1メニューが呼び出すMUCPLAYとは別のプログラムであり、MUCソースを編集したりコンパイルしたりする役割は持ちません。

MUCEditは、Windows用のVS Code自体をMSXへ移植したプログラムではありません。慣れた編集キーをできるだけ使えるように構成した、MSX用のエディタです。複数ファイルのタブ表示、マルチカーソル、マウス選択、OS共通のクリップボードといった機能まで同じではありません。

## 2. 動作環境と用意するファイル

### 2.1 基本環境

- 80桁テキスト画面が使えるMSX2以上の環境
- MSX-DOS2系の実行環境と、512KB推奨のメモリマッパー対応 (MegaFlashROM SCC SD+、Carnivore2など)
- 読み書きできるディスクまたはストレージ
- 演奏する場合は、MUCPLAYが対応する音源デバイス (Makoto YM2608)

連携確認に使用した代表的な環境は次のとおりです。

```tex
Panasonic_FS-A1WX
MegaFlashROM_SCC+_SD
MAKOTO
MSX-DOS2 / Nextor
```

実用の準備としては、**512 KiB級のメインマッパーを備えた環境**を基準に考えるとよいでしょう。これは連携検証に使用した構成であって、すべての機種とDOS構成に対する厳密な最小RAM保証値ではありません。DOS、常駐プログラム、現在保持している曲のセッションもメモリを使うため、搭載RAMの総量だけで実行可否が決まるわけではありません。

また、MSXに内蔵PSGがあることと、MUCPLAYが要求する再生デバイスがあることは別の話です。この説明書の基本となる演奏環境はMAKOTOのYM2608です。他の音源構成については、お使いのMUCPLAYビルドの対応範囲を確認してください。

### 2.2 ファイルはまず同じディレクトリにまとめてください

最初は次のように曲ごとのフォルダを作ることをおすすめします。

```text
SONG/
  MUCEDIT.COM
  MUCPLAY.COM
  SONG01.MUC
  SONG02.MUC
  VOICE.DAT
  PCM01.BIN
```

実際には、DOSから見えるファイル名が重要です。長いホスト側のファイル名ではなく、**8.3形式の短い名前**を使うのが安全です。たとえば`SONG01.MUC`、`VOICE.DAT`、`PCM01.BIN`のように整理してください。名前を変えた場合は、MUC内のファイル指定も合わせて直す必要があります。

曲に次のタグがあれば、そのファイルが必要です。

```text
#voice VOICE.DAT
#pcm PCM01.BIN
```

名前が似ているだけの別の音色・PCMファイルを持ってくると、曲はコンパイルできてもまったく違う音が鳴ることがあります。曲と一緒に提供されたファイルを使ってください。

### 2.3 ファイル名とパスの注意点

- エディタでのファイル名直接入力は最大63バイトです。
- **コンパイル連携に使う文書名・パスは最大24バイトで、空白を含められません。**
- 音色・PCMファイルを読むコンパイラのFCBパスは、DOSの8.3名の制約を受けます。長い名前がそのまま処理されると考えないでください。
- ファイル一覧ウィンドウで別のパスを入力しても、DOSのカレントディレクトリは変わりません。
- 特に、別フォルダのMUCだけをパス指定で開くと、音色・PCM・MUCPLAYの位置を取り違えやすくなります。最初は曲フォルダへ`CD`してから、そこで実行してください。

### 2.4 ディスクは書き込み可能である必要があります

元のMUCを保存しないコンパイルでも一時ファイルを使います。したがって、読み取り専用ディスクでは連携作業が制限されます。

状態保存用ファイルに約33 KiB、一時MUCに現在の文書サイズ分の領域が必要で、書き出しを行えばMUB・VGMの領域も追加で必要になります。PCMが大きい曲は結果ファイルも大きくなります。「元のMUCが数KBだからディスクもその程度空いていれば足りるだろう」とは考えず、十分な余裕をとってください。

## 3. はじめて起動して一曲聴いてみる

DOSで曲のあるディレクトリへ移動します。

```text
CD SONG
MUCEDIT SONG01.MUC
```

空の文書で始めるならファイル名を省略します。

```text
MUCEDIT
```

起動したら、次の順で試してみてください。

1. ファイルの内容が画面に表示されるか確認します。
2. `F1`を押し、続けて`2`を押してコンパイルします。
3. 結果画面にエラーや警告がないか読みます。
4. 案内に従って何かキーを押し、エディタへ戻ります。
5. `F1`を押し、続けて`3`を押して演奏します。
6. 途中で止めたいときは何かキーを押します。
7. 結果画面に復帰の案内が出たら、もう一度キーを押して戻ります。

ここでの`F1→2`は、F1と数字の2を同時に押すという意味ではありません。**F1を押してメニューを開いてから、数字の2を押す順番**です。

では一箇所を修正して、**もう一度F1→2、続けてF1→3**をやってみてください。気に入った修正であれば`Ctrl+S`で保存すれば完了です。

## 4. 画面とカーソルの読み方

画面は80桁で、上のタイトル行と下の案内行のあいだが編集領域です。

### タイトル行

```text
MUCEdit v0.8 by ToughkidCST  |  SONG.MUC*
```

- ファイル名が表示されます。まだ名前がなければ、名前のない文書として表示されます。
- ファイル名のうしろの`*`は、保存されていない変更があることを示します。
- 選択範囲があれば`[SELECT]`表示が追加されます。
- ファイル名が長いと、タイトル行の後半の情報がすべては見えないことがあります。

### カーソルとブロックは違います

カーソルは文字を入れる位置を示す細い縦棒です。現在のv0.8実装では、入力待ちのあいだカーソルが点滅し、移動すればすぐ見える状態になります。**選択ブロックの反転表示は点滅しません。** カーソルが点滅することと、ブロック全体が消えることは区別してください。

選択された改行は、行末の空白1マスとして表示されます。空行にも選択表示が出ることがありますが、これは空行の改行を選択したという意味です。

### 長い行

長いMML行は右へ続くことがあります。カーソルを移動すると横スクロールします。画面の右側で見えないからといって、テキストが削除されたわけではありません。

画面幅80桁と、コンパイラの1行の長さ制限は別の話です。長い行を見やすく複数行に分けるときは、新しい行にも必ずチャンネル文字を付けてください。

## 5. ファイルを開く／ファイル一覧ウィンドウ

`Ctrl+O`または`F1→1 Open/MUC`を使います。

カレントディレクトリの`*.MUC`ファイルが1列の一覧ウィンドウに表示され、下にはファイル名を直接入力できる欄が出ます。

| キー | ファイル一覧ウィンドウでの動作 |
|---|---|
| `↑` / `↓` | 前後のファイルを選択 |
| `Ctrl+↑` / `Ctrl+↓` | 前後のページ |
| `Home` / `End` | 現在ページの先頭項目・末尾項目 |
| `Enter` | 選択したファイル、または入力した名前を開く |
| `Esc` | キャンセルして編集画面へ戻る |
| 文字入力 | 一覧選択のかわりにファイル名・パスを直接入力 |
| `Backspace` / `Delete` | 直接入力した名前の最後の文字を削除 |

1ページには最大16件が表示されます。これは全ファイルのうち16件しか読まないという意味ではありません。一覧の末尾を越えて移動したり、ページキーを使ったりすれば次の項目を探します。

知っておいていただきたい点は次のとおりです。

- 一覧は**DOSのディレクトリ検索順**です。名前順のソートではありません。
- サブディレクトリを辿るファイルマネージャではありません。必要なパスは直接入力できます。
- 文字を入力し始めると、既存の一覧選択のかわりに直接入力した名前を使います。
- ファイルがなくても直接入力は可能です。空の一覧で名前を入れずにEnterを押してもファイルは開きません。
- 一覧用の作業メモリが不足する場合は、ファイル名の直接入力方式で動作することがあります。

未保存の変更があれば、まず`Unsaved changes. Discard? (Y/N)`と尋ねます。捨ててよいときだけ`Y`を押してください。その後、一覧ウィンドウでEscでキャンセルした場合や、新しいファイルの読み込みに失敗した場合は、現在の文書が保たれるように処理します。

## 6. 保存・新規・再読み込み・終了

### 保存: Ctrl+S

現在の文書を現在の名前で保存します。名前のない文書であれば、ファイル名を入力します。保存に成功すると、未保存の表示が消えます。

既存の名前に保存すると既存ファイルを更新します。元を残して比較したい場合は、先に別名で保存してください。保存失敗に備えた自動バックアップファイルの作成機能はありません。

### 別名で保存: Ctrl+Shift+S

現在の内容を別のファイル名で保存します。たとえば配布された`BOS010.MUC`を修正する前に`BOS010A.MUC`として保存しておけば、元と比較しやすくなります。

別名に変えたあとは、演奏・書き出しの前にもう一度コンパイルしてください。以前のファイル名に結び付いていたコンパイル結果を、新しい文書の結果として扱うことはありません。

### 新規文書: Ctrl+Nまたは F1→A

新しい空の文書で始めます。未保存の内容があれば、破棄するかどうか確認します。

`F1→N Save/New`は、**現在の文書をまず保存してから**新規文書を始めるコマンドです。`N`の文字だけを見て「ただのNew」と思い込まないよう注意してください。

### 再読み込み: F1→O Reload

現在の名前のファイルをディスクから読み直します。未保存の修正内容を捨てて、最後の保存版に戻るときに使います。未保存の変更があれば確認を求めます。

ReloadはUndoとは異なります。ファイルを読み直すと、その文書を新しく開いた状態になるため、以前の編集履歴が引き続き使えるとは考えないでください。

### 終了

| コマンド | 動作 |
|---|---|
| `F1→E Save/Exit` | 保存してから終了 |
| `F1→Q Quit` | 保存せずに終了。未保存の変更があれば確認 |

MUCPLAYを呼び出したセッションでは、終了時にプレイヤー側で保持されていたマッパーメモリを返す処理が続くことがあります。終了メッセージが少し長く出ても、すぐにリセットせず、DOSプロンプトに戻るまで待ってください。

## 7. カーソル移動とブロック選択

### 基本の移動

| キー | 動作 |
|---|---|
| `←` / `→` | 1文字移動 |
| `↑` / `↓` | 前後の論理行へ移動 |
| `Home` / `End` | 現在行の先頭・末尾 |
| `Ctrl+Home` / `Ctrl+End` | 文書の先頭・末尾 |
| `Ctrl+←` / `Ctrl+→` | 単語単位の移動 |

上下に移動するときは、できるだけ元の桁位置を保ちます。途中に短い行や空行があると、一時的に行末にとどまることがあります。

実機のMSXキーボードでは、**HOMEがHome、SELECTがEnd**に対応します。エミュレータのPCキーボードマッピングは設定によって異なる場合があります。

### ブロック選択

ブロックを取るには、**Shiftを押したままカーソルを移動**します。

| キー | 選択範囲 |
|---|---|
| `Shift+←/→` | 文字単位 |
| `Shift+↑/↓` | 行をまたいで拡張 |
| `Shift+Home/End` | 現在位置から行頭・行末まで |
| `Ctrl+Shift+←/→` | 単語単位 |
| `Ctrl+Shift+Home/End` | 文書の先頭・末尾まで |
| `Ctrl+A` | 文書全体 |
| `Ctrl+L` | 現在行 |

たとえば`t225`の数値を変えたいときは、数字の前後へ移動し、Shiftと左右キーで数字を選択してから新しい数字を入力すれば置き換わります。選択された部分は新しい入力で置き換えられます。

選択した状態でShiftなしに左を押すと選択開始点へ、右を押すと選択終了点へ移動し、選択が解除されます。Escで選択を解除することもできます。

MUCEditの選択は一般的な連続テキスト選択です。矩形の桁選択や、複数箇所を同時に編集するマルチカーソルには対応していません。

## 8. コピー・切り取り・貼り付け・行編集

### 基本の編集

| キー | 動作 |
|---|---|
| `Ctrl+C` | 選択部分をコピー。選択がなければ現在行をコピー |
| `Ctrl+X` | 選択部分を切り取り。選択がなければ現在行を切り取り |
| `Ctrl+V` | クリップボードの内容を貼り付け |
| `Backspace` | カーソル前の文字を削除。選択があれば選択を削除 |
| `Delete` | カーソル後の文字を削除。選択があれば選択を削除 |
| `Enter` | 改行を挿入 |
| `Tab` | タブ文字を挿入 |

クリップボードはMUCEdit内部用で、最大4 KiBです。Windows/macOSでコピーした内容がCtrl+Vで自動的につながるわけではありません。ホスト側の内容を入れるには、使用中のエミュレータの文字列入力機能などを別途使う必要があります。

タブは空白数個に変換して保存するのではなく、タブバイトそのものを入れます。特にチャンネル文字の前にタブを入れて字下げすると、MMLチャンネル行として認識されないことがあるので注意してください。

### 行単位の編集

| キー | 動作 |
|---|---|
| `Ctrl+Shift+K` | 現在行を削除 |
| `Ctrl+Enter` | 現在行の下に新しい行を挿入 |
| `Ctrl+Shift+Enter` | 現在行の上に新しい行を挿入 |
| `Graph+↑/↓` | 現在行を上下へ移動 |
| `Shift+Graph+↑/↓` | 現在行を上下へ複製 |

GraphはMSXキーボードのGRAPHキーです。PCのVS CodeでAltを使う行移動・複製に対応します。

行移動と複製はクリップボードを上書きしません。この機能は**カーソルのある現在の論理行**を対象とします。複数行を選択したからといって、選択行全体がまとめて移動する方式ではありません。

似たフレーズをもう一つ作るときは行複製が便利です。ただし複製された行は同じチャンネルのうしろに続けて演奏されます。別のチャンネルで同時に鳴らしたい場合は、複製した行のチャンネル文字も変更してください。

<a id="09"></a>
## 9. UndoとRedo

- `Ctrl+Z`: 直前の編集を取り消す
- `Ctrl+Y`: 取り消した編集をやり直す

コンパイルや演奏をしてエディタへ戻っても、文書と一緒にUndo/Redoの状態を保ちます。保存済みかどうかの状態も追跡するため、Undoで最後の保存時点まで戻ると未保存表示が消えることがあります。

ただし**無制限のUndoではありません。** 現在の履歴領域は4 KiBで、変更前後のテキストと管理情報が一緒に入ります。したがって「常に何回まで戻せる」という固定回数では説明できません。

- 履歴領域がいっぱいになると、既存の履歴を初期化して新しい履歴を残します。
- 一度の変更そのものが履歴領域より大きい場合、その変更はUndoで戻せず、以前の履歴も初期化されることがあります。
- Undoしたあとに新しい内容を編集すると、既存のRedo経路は失われます。
- ファイルを新しく開いたり、New/Reloadしたりすると、以前の文書のUndo履歴は保持されません。

大きなブロックを消したり、長いフレーズ全体を書き換えたりする前には、別名で保存しておいてください。私はUndoをバックアップの代用と考えないことをおすすめします。

<a id="10"></a>
## 10. 文字列検索と部分修正

`Ctrl+F`を押し、検索する文字列を入力してEnterを押します。見つかった部分が選択されます。同じ文字列の次の位置は`F3`で探します。文書の末尾まで探すと、先頭に戻って検索します。

現在の検索は**大文字小文字を区別する通常の文字列検索**です。正規表現検索や一括置換の機能はありません。

かわりに、部分的な置き換えは次のように行えます。

1. `Ctrl+F`で`t225`を探します。
2. 見つかった部分が選択されているか確認します。
3. `t200`と入力して、その部分を置き換えます。
4. 必要であれば同じ方法で他の箇所も修正します。

検索で選択された範囲の上にそのまま入力すると、その範囲が置き換わります。探すだけのつもりだった場合は、方向キーやEscで選択を解除してから入力してください。

<a id="11"></a>
## 11. F1メニュー全解説

F1を押すと、次の2行が表示されます。

```text
E Save/Exit     Q Quit       S Save      N Save/New    A Discard/New   O Reload
1 Open/MUC      2 Compile    3 Play/Muc                4 Exp/MUB       5 Exp/VGM
```

| キー | メニュー名 | 説明 |
|---|---|---|
| `E` | Save/Exit | 保存してから終了 |
| `Q` | Quit | 保存せず終了。必要に応じて確認 |
| `S` | Save | 現在の文書を保存 |
| `N` | Save/New | 保存してから新規文書 |
| `A` | Discard/New | 現在の文書を破棄して新規文書。必要に応じて確認 |
| `O` | Reload | 現在の名前のファイルをディスクから読み直す |
| `1` | Open/MUC | ファイル一覧ウィンドウまたは直接入力で開く |
| `2` | Compile | **現在メモリ上の編集内容**をコンパイル |
| `3` | Play/Muc | 最後のコンパイル結果を演奏 |
| `4` | Exp/MUB | 最後のコンパイル結果をMUBとして保存 |
| `5` | Exp/VGM | 最後のコンパイル結果をVGMとして出力 |

メニューでEscを押すと、コマンドを実行せずに戻ります。`O`はアルファベットのOであり、数字の0ではありません。

<a id="12"></a>
## 12. 未保存コンパイルと演奏

### 12.1 保存しなくてもコンパイルされます

F1→2は、ディスク上の元のMUCを読み直してコンパイルするコマンドではありません。**いまエディタの中で編集中の文書**をコンパイルします。

たとえばディスク上のファイルが`A t225`で、画面上で`A t125`に変えたなら、保存しなくてもF1→2は`t125`を使うはずです。このとき元のMUCは依然として`t225`のままで、タイトルの未保存表示も残ります。

新規文書にまだ名前がない場合、コンパイルの過程で名前の入力を求められることがあります。名前を付けることと、元のMUCを実際に保存することは別です。**コンパイルが成功したからといって、新しいMUCファイルが保存されたと考えないでください。** 残したい内容はCtrl+Sで保存する必要があります。

### 12.2 なぜMEDCOMP.MUCができるのですか

MUCPLAYのコンパイラはファイルを入力として受け取ります。エディタはメモリ上の文書を、カレントディレクトリの`MEDCOMP.MUC`という一時ファイルに書き出して渡します。

また、エディタへ戻るための状態を`MUCEDIT.RET`に保存します。正常に復帰すれば、一時入力と復帰状態ファイルは片付けられます。これらのファイルは、元のMUCの代わりになる通常の保存ファイルではありません。

同名の`MEDCOMP.MUC`がすでにある場合は、むやみに上書きせずコンパイルを中止します。衝突メッセージが出た場合の対処は[復旧の案内](#22)を参照してください。

### 12.3 Playは自動コンパイルではありません

```text
編集 → F1, 2 → 結果確認 → キーを押して復帰 → F1, 3
```

この順序を覚えてください。編集したあとF1→3だけを押すと、**以前のコンパイル結果**を聴くことになります。これは未保存の内容を保存していないからではなく、まだ新しくコンパイルしていないからです。

MUCEditのPlayは`/L2`で実行します。ループする曲は、2回の再生回数を基準に終了するよう要求します。曲の`L`位置や各チャンネルの終了構造によって繰り返す部分が決まるため、すべての曲がファイルの先頭から末尾まで同じように2回再開されるという意味ではありません。

### 12.4 エラーが出たら

エラー画面を読み、エディタへ戻って修正してから、もう一度コンパイルしてください。失敗したコンパイルを新しい正常セッションとして扱うことはありません。演奏を試みると、コンパイル済みの結果がないというエラーが出ることがあります。

`Compiled into session.`はコンパイル成功を知らせるメッセージです。しかしその前に、**Warningがあったかどうかまで**見る必要があります。成功メッセージだけを見て警告を見逃すと、意図しない曲を聴くことになりかねません。

<a id="13"></a>
## 13. MUBとVGMの書き出し

### 13.1 MUB: F1→4

最後にコンパイルしたセッションをMUBファイルとして保存します。文書が`SONG.MUC`であれば、通常は`SONG.MUB`という名前を使います。

MUBにはコンパイル済みの曲データと必要な音色・タグが入り、PCMを使う曲ではPCMバンクも含まれます。**MUBが作られたからといって、元のMUCが保存されるわけではありません。** ソースも一緒に残したい場合はCtrl+Sも行ってください。

修正内容を反映したMUBを作るには、先にF1→2で再コンパイルする必要があります。以前の出力と比較したい場合は、既存のMUBを別名で保管してください。書き出しが自動でバージョン管理やバックアップをしてくれるわけではありません。

### 13.2 VGM: F1→5

最後のコンパイル結果を、音源チップコマンドとタイミングの流れとして出力します。`SONG.MUC`の既定の出力名は`SONG.VGM`です。

VGMはWAVやMP3のような録音ファイルではありません。YM2608などの記録されたチップコマンドに対応したVGM再生環境が必要です。またMUCのように、テキストを書き直して作曲するためのソースファイルでもありません。

MUCEditメニューのVGM書き出しは、Playの`/L2`をそのまま使うわけではありません。別途ループ回数を渡さないため、現在のMUCPLAYのVGM既定値である**1回分の出力**を使います。大きな曲やPCMのある曲は出力に時間がかかることがあるので、完了メッセージを確認するまで待ってください。

### 13.3 書き出し前の確認

1. 必要な修正はすべて終わったか。
2. その修正状態で、もう一度コンパイルしたか。
3. エラーだけでなく警告も確認したか。
4. 正しいPCM・音色ファイルを使ったか。
5. ソースのMUCも別途保存したか。
6. 既存の出力ファイルを保存する必要があるなら、あらかじめ別名で残したか。

<a id="14"></a>
## 14. MUCファイルの基本構造

MUCはMMLで曲を書くテキストファイルです。基本的に**ヘッダ → 音色・マクロ定義 → チャンネル別の演奏内容**の順に構成すると読みやすくなります。

### 14.1 ヘッダタグ

```muc
#mucom88 1.7
#title My First Song
#composer ToughkidCST
#author ToughkidCST
#date 2026/09/14
#comment First test on MSX

D t200 C128 o4 l8 v10 cdefgab>c4
```

| タグ | 用途 |
|---|---|
| `#title` | 曲のタイトル |
| `#composer` | 作曲者 |
| `#author` | MUC作成者・編曲者などの制作情報 |
| `#date` | 日付情報 |
| `#comment` | 説明・コメント |
| `#mucom88` | MUCOM88関連のバージョン情報 |
| `#voice` | 外部FM音色ファイルの指定 |
| `#pcm` | PCMバンクファイルの指定 |
| `#driver`, `#version`, `#uuid`, `#mucmd5` | 互換用メタデータ |

タグ名の大文字小文字は区別されませんが、**`#`の直後に正確な名前を書き、空白で区切って値を書く**習慣をおすすめします。`#title: My Song`、`# title My Song`、`#tittle My Song`は同じタグではありません。

メタデータを書いたからといって、その名前のドライバやコンパイラのバージョンが自動的に選ばれるわけではありません。実際の解釈と再生は、実行中のMUCPLAY次第です。

`#voice`や`#pcm`のような機能タグは、ファイル先頭のヘッダにまとめてください。通常のコメントや本文を先に書いて、あとから機能タグを入れると、初期ヘッダの外のタグとして無視されることがあります。特に**セミコロンのコメントや空白文字が入った行のうしろへ機能タグを先送りしないこと**が安全です。

`#tempo`は現在知られているタグではありません。テンポはチャンネルの`t`または`T`コマンドで指定してください。

### 14.2 チャンネル A–K

| チャンネル | 音源 |
|---|---|
| A, B, C | FM 1, 2, 3 |
| D, E, F | SSG 1, 2, 3 |
| G | リズム |
| H, I, J | FM 4, 5, 6 |
| K | ADPCM/PCM |

FMチャンネルがAからFまで連続していると思いがちですが、そうではありません。**D・E・FはSSGで、H・I・Jが残りのFM**です。

チャンネル行は必ず行頭の大文字A–Kと、空白またはタブで始まります。

```muc
D o4 l4 cdef
E o3 l4 c r g r
D gab>c
```

この例では、Dの2行はつながっています。Eは別チャンネルで進行します。同じチャンネルの次の行に移ったからといって、オクターブ・音長・音量が自動で初期化されるわけではありません。

次の形は正しいチャンネル行ではありません。

```text
 D cdef       ; 前に空白がある
d cdef        ; チャンネル文字が小文字
Dcdef         ; チャンネルのうしろに空白/タブがない
DE cdef       ; 2チャンネル同時指定の形式ではない
ABCD          ; ただ書いただけの文字列
```

前に空白を入れて桁を揃えたい場合でも、**チャンネル文字だけは行頭に残してください。** 音楽コマンドのあいだの空白で、読みやすく整えれば十分です。

### 14.3 コメント

説明は`;`を使って書けます。

```muc
; Main melody
D o4 l8 cdef ; first phrase
D gab>c4    ; second phrase
```

説明文を何の印もなく本文に書かないでください。現在のコンパイラは演奏行として解釈できず、警告を出すことがあります。コメントは、曲をあとから直すときにも大いに役立ちます。

<a id="15"></a>
## 15. 音符・音長・オクターブ・テンポ

### 15.1 音符と休符

`c d e f g a b`はド・レ・ミ・ファ・ソ・ラ・シです。音符は小文字で書きます。

- `c+`: ドの半音上げ
- `d-`: レの半音下げ
- `r`: 休符

```muc
D o4 l8 c c+ d d- e r g r
```

MMLは大文字小文字で意味が変わります。`c`は音符ですが`C`は基準クロック、`r`は休符ですが`R`は別の効果コマンドです。

### 15.2 音長

| 表記 | 意味 |
|---|---|
| `l4` | 数字を省略した音符の既定の長さを4分音符に設定 |
| `l8` | 既定の長さを8分音符に設定 |
| `c4` | このドを4分音符で演奏 |
| `c8` | このドを8分音符で演奏 |
| `c4.` | 付点4分音符 |
| `r8` | 8分休符 |

```muc
D o4 l8 c d e4 f8 g4. r8
```

`C128`なら全音符を128クロックに分割します。このとき`l4`は32クロック、`l8`は16クロックです。既定の基準も128ですが、別の場所から持ってきたフレーズを合わせるときは、`C`の値が同じか確認してください。

直接クロックで指定する`%`も使えます。たとえば`c%12`はこの音を12クロックに指定します。ふつうは最初は`l4`、`l8`のような表記を使い、細かなリズムを合わせるときに直接クロックを使うとよいでしょう。

長さ0は使わないでください。`l0`のように有効な音長を作れない入力はエラーになります。基準クロックより大きすぎる分母を与えて長さが0になる場合も避ける必要があります。

### 15.3 オクターブ

- `o4`: オクターブ4
- `>`: 1オクターブ上げる
- `<`: 1オクターブ下げる
- 明示的なオクターブ指定範囲: `o1`から`o8`

```muc
D o4 l4 c d e f >c <g
```

音符を複数行に分けた場合、前の行の`>`は次の行にも影響します。フレーズを移して貼り付けたのに音域がおかしいときは、その前のオクターブ状態から確認してみてください。

### 15.4 タイと音長の延長

`&`は次の音とつなぐタイの表現に使います。同じ音を長く保つ用途から覚えてみてください。

```muc
D o4 l4 c4&c4 d4 e4
```

`^`は前の音の長さを追加する別の表現です。最初は`&`で明確に書き、既存の曲に出てくる`^`を修正するときに、前の音と長さの関係を一緒に見ていくとよいでしょう。

### 15.5 テンポ: tとTは違います

| 表記 | 意味 |
|---|---|
| `t225` | Timer-B値の直接指定。**BPM 225という意味ではない** |
| `T120` | BPM方式のテンポ指定。内部ではTimer-B値に変換 |

```muc
D T120 C128 o4 l4 cdefgab>c
```

既存のMUCOM88の曲では`t`による直接指定が多く使われています。`T`は内部の整数変換とクロック設定の影響を受けるため、他の再生器のBPM表示と完全に同じ測定値を保証する表示ではありません。

テンポは曲の再生クロックに影響します。複数のチャンネルに異なるテンポをばらばらに書くより、一箇所で明確に管理することをおすすめします。既存曲のテンポを比べるときは、別の行に同じコマンドがもう一つないかも探してみてください。

<a id="16"></a>
## 16. 音色・音量・パン・チャンネル別表現

### 16.1 音量 v

`v`は音量の指定です。ただしチャンネルの種類ごとに処理方式と実用的な有効範囲が異なります。

```muc
D o4 l8 v8 cdef v12 gab>c4
```

SSGは0–15の範囲から始めると理解しやすいでしょう。FMも、まずは既存曲の`v`設定を基準に、小さな幅で調整してみてください。Kチャンネルはバイト単位のADPCM音量を使うため、FM・SSGと同じ数値を入れても同じ大きさに聞こえるわけではありません。

`)`は音量の増加、`(`は減少に使います。数字を付けて変化量を指定する表現もあります。大きすぎる値を与えると、期待どおりに大きくなったり小さくなったりするのではなく、チャンネルごとのバイト処理範囲を外れることがあるので、少しずつ変えて聴いてみてください。

### 16.2 音長と実際に鳴る長さ: q

`q`は音の終わりで早めに音を切る長さを設定します。**q0は基本的に音の終わりまで保つ側**です。他のMMLで使う「q8なら8/8の長さ」のような比率表記と混同しないでください。

```muc
D o4 l8 v10 q0 cdef q4 gab>c
```

音符全体の時間は同じでも、qのある部分は終わりを少し離して演奏する感じになります。タイ・エンベロープ・チャンネル種別による効果も一緒に作用します。

### 16.3 パン p

FM・ADPCMの基本的なパンは、`p1`が右、`p2`が左、`p3`が両方です。`p0`は両方の出力を切る設定になり得るので、音が出ないときは必ず確認してください。

SSGには同じ方式の独立したハードウェアパンがありません。SSGに`p`を書いて、FMと同じ左右移動が起きると期待しないでください。

### 16.4 FM音色 @

FMチャンネルの`@1`は音色番号1を選びます。外部音色ファイル、またはソース内の音色定義が、その番号に合わせて用意されている必要があります。

外部ファイルはヘッダで指定します。

```text
#voice VOICE.DAT
```

現在、1曲で使える異なるFM音色は最大32種類です。音色番号の数字そのものと、「この曲で使った音色の種類数」は区別してください。

ソースに直接書く基本的な音色定義は次の構造です。

```text
  @番号
   FB, ALG
  AR, D1R, D2R, RR, D1L, TL, KS, ML, DT
  AR, D1R, D2R, RR, D1L, TL, KS, ML, DT
  AR, D1R, D2R, RR, D1L, TL, KS, ML, DT
  AR, D1R, D2R, RR, D1L, TL, KS, ML, DT
```

または`@番号:{ ... }`形式も使われます。先頭の2つの値はフィードバックとアルゴリズムで、あとの4行は各オペレータのパラメータです。値の順序を入れ替えると別の音色になります。FM音色をはじめて修正するときは、検証済みの既存定義をコピーして1項目ずつ変えるのがよいでしょう。

音色定義行の`@`と、**チャンネル行内の音色選択コマンド`@`**は区別してください。チャンネル内の`A @1 c`は音色を定義するのではなく、選択しています。

### 16.5 SSG

SSGはD・E・Fチャンネルです。基本の音符・音長・オクターブ・音量のほかに、次の系統のコマンドを使います。

| コマンド | 用途 |
|---|---|
| `@n` | SSGプリセットの選択。FM音色番号と同じデータではない |
| `P1` | トーン使用の設定 |
| `P0` | ミックス出力をオフ |
| `wN` | ノイズ周期の設定 |
| `E...` | ソフトウェアエンベロープ。6つの値をカンマで区切る |
| `SN` | ハードウェアエンベロープの形状 |
| `mN` | ハードウェアエンベロープの周期 |

プリセットやエンベロープまで一度に変えると、どの設定が音色を変えたのか分かりにくくなります。まずは単純なSSGメロディが正常に聞こえるか確認してから、1項目ずつ追加してみてください。

### 16.6 リズム G

Gは通常のメロディチャンネルではなく、リズムチャンネルです。FM・SSGの音量や音色コマンドをそのまま適用するチャンネルとは考えないでください。

たとえばGの`v`は、全体／各リズムの音量をカンマで並べる**7値形式**を使います。`G v12 c`のように通常のメロディと同じ1値形式で書くと、区切り・引数のエラーになることがあります。

リズムパートをはじめて作るときは、正常に再生される曲のG チャンネルをもとに、楽器の選択と音量を保ったまま長さから調整していくのがよいでしょう。

### 16.7 PCM K

Kチャンネルは、PCMサンプルを選んで演奏するために使います。`@n`の意味と実際に出る音は、使用中のPCMバンクによって変わります。

```text
#pcm PCM01.BIN
```

このタグは単なる説明ではなく、使用するファイルを指定するものです。`#`を消すとPCM指定機能が失われ、既定の名前である`MUCOMPCM.BIN`を探すことになる場合があります。

コンパイル段階は、PCMを音源チップへ転送する段階ではありません。PCM関連の問題は、演奏するときやMUBへ取り込むときに現れることもあります。「コンパイルが成功したのだからPCMもすべて正常だ」と判断しないでください。

<a id="17"></a>
## 17. リピート・マクロ・上級コマンド

### 17.1 リピート [ ]

```muc
D o4 l8 [cdef]2 gab>c4
```

`cdef`を2回演奏してから、うしろのフレーズへ進みます。リピート回数は明確に書くことをおすすめします。開く`[`と閉じる`]`の対応が取れている必要があります。

### 17.2 最後のリピートで抜ける /

```muc
D o4 l8 [c d / e f]2 g4
```

最後の回では`/`以降のリピート本体を省略し、リピートの次へ進みます。`/`はリピートの中で使う必要があり、同じリピートに重ねて入れないでください。

リピートのネストは最大16段です。非常に複雑にネストするより、適度な長さに分けて読みやすく書くほうがよいでしょう。

### 17.3 曲のループ位置 L

```muc
D o4 l8 cdef L gab>c
```

`L`は、そのチャンネルの曲のループ位置を設定します。単純に文字列の前半を繰り返す`[ ]`とは異なります。複数チャンネルをループさせるときは、各チャンネルのフレーズの長さとループ位置を合わせる必要があります。

エディタのPlayの2回制限と、ソースの`L`は別の役割です。`L`は曲の中のループ位置であり、`/L2`はプレイヤーが実行するループ回数を決めるオプションです。

### 17.4 マクロ

繰り返し使うフレーズを、名前ではなく番号で定義できます。

```muc
# *1{o4 l8 cdef}
# *2{gab>c4}
D v10 *1 *2
```

`# *1{...}`が定義で、チャンネル内の`*1`が呼び出しです。定義していない番号を呼んだり、波括弧を閉じなかったりするとエラーになります。

現在の安全な上限は、マクロ本体511バイト、呼び出しのネスト4段です。自分自身を呼び続ける形も、有効な曲の書き方ではありません。マクロの中でエラーが出ると、**定義行ではなく呼び出したチャンネル行**が表示される場合があることも覚えておいてください。

### 17.5 ポルタメント

```muc
D o4 l4 {c>c}4 d4
```

波括弧の中の音のあいだを移動する表現です。マクロ定義の波括弧と同じ文字を使いますが、役割は異なります。既存のフレーズを修正するときは、波括弧の位置とうしろの音長指定まで一緒に確認してください。

### 17.6 上級コマンド早見

以下は、既存の曲を読むときによく出会うコマンドです。「この記号がだいたい何を調整するのか」を探すための表であり、すべてのチャンネルで同じ引数を受け取るという意味ではありません。

| コマンド | 用途・注意点 |
|---|---|
| `DN` | デチューン。音源の種類ごとに値の作用が異なる |
| `KN`, `kN` | 移調系。絶対／相対の移調状態を設定 |
| `sN` | シャッフル・音長の交互調整 |
| `VN` | 全体音量のオフセット系 |
| `M遅延,速度,変化量,深さ` | ソフトウェアLFOの4引数形式。実際の入力は数字とカンマで書く |
| `MF0`, `MF1` | ソフトウェアLFOのオフ・オン |
| `MW`, `MC`, `ML`, `MD`, `MT` | LFOの部分設定。コマンドごとの引数・チャンネル制限を確認すること |
| `H...` | ハードウェアLFO。ソフトウェアLFOとは別で、チャンネル制限がある |
| `yレジスタ,値` | レジスタの直接指定。他の音源設定を変えてしまうことがあるので注意 |
| `yTL,オペレータ,値` など | FMパラメータ名を使う直接制御系 |
| Cチャンネルの`S...` | FM3スロットデチューン。SSGのSとは引数形式が異なる |
| `R`, `Rm`, `RF`系 | リバーブ・残響関連のコマンド。一般的なオーディオプラグインの効果と同じではない |
| `^長さ` | 前の音の長さを延長 |
| `\|` | 読みやすさのために入れる区切り表示。自動の休符や拍の補正ではない |
| `:` | そのチャンネルの以降のコンパイルを終了するコマンド |

たとえばソフトウェアLFOの数値形式は次のように使います。

```muc
D o4 l4 v10 M8,2,1,4 cdef MF0 gab>c
```

コマンドごとに有効範囲が異なり、数字が入るというだけでどんな値でも安全に使えるわけではありません。上級コマンドは正常な例から小さな幅で変更し、エラー・警告と実際の音を一緒に確認してください。

## 18. 実際に入力してみる完成例

### 18.1 SSGで始める最初の曲

次の内容を新しい文書に入力し、`FIRST.MUC`という名前を使ってみてください。

```muc
#mucom88 1.7
#title First Steps
#composer ToughkidCST
#author ToughkidCST
#comment Simple SSG test

D T120 C128 o4 l8 v10 q0 cdef gab>c4 r4
E C128 o3 l4 v8 c r g r c r g r
F C128 o2 l2 v7 c g c g
```

1. Ctrl+Sで`FIRST.MUC`を保存します。
2. F1→2でコンパイルします。
3. メッセージを確認して戻り、F1→3で聴いてみます。
4. Dチャンネルの`v10`を`v6`に変えます。
5. **保存せずに**F1→2、F1→3をやってみます。
6. 気に入らなければUndoで戻して、もう一度コンパイルします。
7. 最終的に残したい状態でCtrl+Sを押します。

この例は、PCMや外部FM音色を使わないようSSGだけで構成しています。ただしエディタで実際に演奏するには、前述のMUCPLAYの対応音源環境が必要です。

### 18.2 リピートとマクロを組み合わせる

```muc
#mucom88 1.7
#title Phrase Practice
#comment Macro and repeat test

# *1{o4 l8 cdef}
# *2{g4 e4 c4 r4}
D t200 C128 v10 [*1]2 *2
E C128 o3 l4 v8 [c r g r]2
```

`*1`を変えれば、そのマクロを呼び出した位置すべてに変更が反映されます。あちこちにコピーした同じフレーズを個別に直すより、管理が楽になります。

### 18.3 簡単なインラインFM音色

以下は音色定義の配置を示す例です。はじめて聴くときは音量を下げて確認してください。

```muc
#mucom88 1.7
#title Inline FM Test
#comment Four-operator voice example

  @1
   0,7
   31,8,4,6,8,36,0,1,0
   31,8,4,6,8,36,0,1,0
   31,8,4,6,8,36,0,1,0
   31,8,4,6,8,36,0,1,0

A t200 C128 @1 o4 l8 v8 p3 q2 cdef gab>c4
```

この例をもとに音色の値を変えるときは、元を残して1値ずつ変えてみてください。文法の正しい音色だからといって、必ずしも聴いて心地よい音色とは限りません。

<a id="19"></a>
## 19. コンパイルエラーの読み方

現在のコンパイラは、可能な場合に**行番号、チャンネル、エラーコード、理由と原文の一部**を表示します。

```text
Error line 2, channel A (code 6): Note length out of range
> A l0 c
```

読む順序は次のとおりです。

1. `line 2`: 2行目を確認します。空行やコメントも行数に含まれます。
2. `channel A`: Aチャンネルの処理中に発生したエラーです。
3. `code 6`: 音長関連のエラーです。
4. `> A l0 c`: 実際に問題のある行の一部です。ここでは`l0`を直す必要があります。

原文の抜粋は最大72バイトなので、長い行の末尾まですべて出るわけではありません。マクロ内部で発生したエラーは、呼び出し行を指すことがあります。ソース位置が分からないファイル入出力などのエラーには、任意の行番号が付かないことがあります。

エディタには、該当のエラー位置へ自動的に移動する機能はありません。メッセージの行の内容やコマンドを覚えておき、Ctrl+Fで探す方法が便利です。**先に発生したエラーから一つずつ直して、再コンパイル**してください。一度の失敗画面にすべての問題が並ぶとは期待しないほうがよいでしょう。

<a id="20"></a>
## 20. コンパイルエラーコードと発生条件

以下は現在の診断コードの説明です。同じコードでも、文脈によって複数の原因があり得ます。

| コード | 表示される理由 | 代表的な発生条件・確認する箇所 |
|---:|---|---|
| 0 | Syntax error / missing number | 必要な数値がない。例: `A l` |
| 1 | Invalid parameter | 引数形式または数値範囲が不適切。例: `A q100000 c` |
| 2 | Repeat end without matching start | `[`なしで`]2`を使用 |
| 3 | Unclosed repeat/loop | `[`を開いて閉じていない |
| 4 | Too many voices (maximum 32) | 1曲で使うFM音色の種類が32を超えた |
| 5 | Octave out of range (o1..o8) | `o0`、`o9`のように明示的オクターブ範囲を外れた |
| 6 | Note length out of range | `l0`など有効な長さを作れない。C128状態の`l129`も確認対象 |
| 7 | Invalid loop escape | リピート外の`/`、同じリピート内の重複した脱出など |
| 8 | Missing parameter or separator | 複数引数が必要なコマンドの数字・カンマが欠けている。例: `A M1` |
| 9 | Command not valid for this channel | チャンネルに合わないコマンド。例: FMのAチャンネルにSSG用の`P1`を使用 |
| 10 | Too many nested repeats | リピートのネスト上限16段を超過 |
| 11 | Voice name not found or invalid | 名前で指定した音色が見つからない、または名前指定が不正 |
| 12–14 | Unspecified compiler error | 予約・一般エラー領域。その番号だけで原因を断定しないこと |
| 15 | Macro not found | 定義されていない`*番号`の呼び出し |
| 16 | Invalid macro definition | 閉じていない定義、過度なネスト・再帰呼び出しなどマクロ構造の問題 |
| 17 | MML line or macro too long | MML本体1行1,023バイト、またはマクロ本体511バイトの上限を超過 |
| 18 | Output buffer overflow | コンパイル済みの曲データが出力バッファ32 KiBの上限を超過 |

この表が、すべての不正な数値とすべてのMMLの組み合わせを完全に検査する保証はありません。文法検査、ファイル検査、実際の音源上での意味は、それぞれ別のものです。エラーなくコンパイルできても、意図した音になっているかは聴いて確かめる必要があります。

### 実際に試せるエラー例

以下は**わざとエラーになるように作った入力**です。実際の曲にそのまま貼り付ける例ではありません。

```text
A o9 c          → コード5: オクターブ範囲超過
A l0 c          → コード6: 長さ0
A ]2            → コード2: 開くリピートがない
A [cdef         → コード3: 閉じていないリピート
A /c            → コード7: リピート外の脱出
A M1            → コード8: 必要な引数の不足
A P1 c          → コード9: チャンネルに合わないコマンド
A *99 c         → コード15: 99番マクロを定義していない場合
```

### サイズのエラーはどう減らしますか

- 長い1行は複数行に分けます。分けたすべての演奏行の前にチャンネルを付けます。
- 長いマクロは、短い複数の定義に分けます。
- 出力容量の超過は、ソースファイルのサイズとは別です。繰り返す音符を不必要に長く書き下している箇所がないか見てみてください。
- 可能であれば`[ ]`のリピートで表現します。マクロはテキストを減らす手段ですが展開されるので、マクロを使ったから出力サイズも必ず減るわけではありません。
- PCMのサイズはMUB全体のサイズに大きく影響しますが、コード18の**曲データ32 KiB**とは別の制限です。

<a id="21"></a>
## 21. 警告メッセージと不正な入力

**Errorはコンパイル失敗、Warningは注意が必要な状態**です。警告だけでコンパイルを中断することはありません。

以前は、不正なチャンネル行やタグが黙って無視されていたため、「直したのに、なぜ何も変わらないのだろう」と感じやすい状況がありました。現在のMUCPLAYのコンパイラには、こうした入力を知らせるソース事前警告が追加されています。ただし、古いMUCPLAYには該当の警告がないことがあります。

### 21.1 不正なチャンネル接頭部

```text
Warning line 2: Invalid channel prefix; use A-K + space/tab
> Ac4
```

`A c4`のように、チャンネルのうしろに空白を入れる必要があります。次の点も確認してください。

- チャンネル文字の前に空白・タブを入れていないか。
- チャンネル文字を小文字で書いていないか。
- A–K以外の文字をチャンネルとして使っていないか。
- `AB c`、`A,B c`のような、対応していない複数チャンネル接頭部を書いていないか。
- 説明文やテスト用の文字列を、コメント記号なしで書いていないか。

たとえば`J cdef`の前に文字を付けて`TESTJ cdef`にすると、その行が正常なJチャンネルとして演奏されるわけではありません。**警告を出して、従来の解釈どおりに無視することがあります。** コンパイル成功のメッセージが出たからといって、その文字列を音楽として解釈したという意味ではありません。

### 21.2 不明または不正なタグ

```text
Warning line 1: Unknown or malformed tag
> #tittle Example
```

綴りと、`#`のうしろの空白・コロンを確認してください。ユーザー定義タグも、現在知られているタグ一覧になければ警告される場合があります。警告が出たからといって、その文字列を自動的に削除・修正することはありません。

### 21.3 タグ値の欠落

```text
Warning line 1: Missing tag value
> #pcm
```

`#pcm PCM01.BIN`のように値を入れてください。空の`#comment`は、通常のコメント用途として許容されます。

### 21.4 ヘッダ外のタグ

```text
Tag outside initial header is ignored
```

`#voice`、`#pcm`などをファイル先頭のヘッダへ移してみてください。`#comment`とマクロ定義は別に扱われます。ファイルの途中にタグを書いたからといって、その時点でPCMバンクや音色ファイルが変わるわけではありません。

### 21.5 PCMファイルの欠落

```text
Warning: PCM file not found: MUCOMPCM.BIN
```

プレイヤーの読み込み経路によっては、次のような文言も見られます。

```text
WARNING: cannot open #pcm file: MUCOMPCM.BIN
```

確認の順序は次のとおりです。

1. `#pcm`タグが正確に書かれているか。
2. ファイル先頭のヘッダにあるか。
3. 指定したPCMファイルが現在の作業環境で読めるか。
4. DOSで実際に見える8.3ファイル名がタグと一致しているか。
5. もとの曲に入っていたPCMバンクで合っているか。

互換性のため、PCMのないMUBが生成されることがあります。**MUB written. というメッセージだけを見て、正常なPCM入りファイルだと判断してはいけません。** PCMが必要な曲であれば、欠落警告を解決してから出力し直してください。

警告は、不正な入力のすべての意味まで検査するわけではありません。たとえば日付が実際のカレンダーに合っているか、PCM内の各サンプルが曲の期待する楽器かどうかは、この警告だけでは確認できません。

## 22. エディタのメッセージと復旧方法

| メッセージ | 意味と対処 |
|---|---|
| `mucEdit new requires MSX-DOS2.` | MSX-DOS2系の環境かどうか確認 |
| `Open failed. Press a key.` | 名前・パス・ディスク・ファイルへのアクセス可否を確認 |
| `Text exceeds 24 KiB; not loaded.` | 正規化した文書が編集容量を超過。外部ツールで分割・縮小してから開き直す |
| `Need 32 KiB free mapper RAM to load.` | 新しい文書の読み込みに一時マッパー2つが必要。現在の作業を保存し、常駐プログラム・セッション・RAM構成を確認 |
| `Save failed. Press a key.` | ディスク容量、書き込み保護、名前、デバイスエラーを確認。メモリに残っている文書を別名・別デバイスに保存する手段をまず確保 |
| `Document memory full. Press a key.` | 挿入・貼り付け後に文書が24 KiBを超えていないか確認 |
| `Selection exceeds 4 KiB clipboard.` | コピー・切り取りの範囲をもっと小さく分ける |
| `Text not found. Press a key.` | 検索の綴りと大文字小文字を確認 |
| `Save the document first. Press a key.` | 現在のコマンドに必要な文書名がないか確認し、保存／名前指定を行う |
| `Compile this document first: F1 then 2.` | 現在の文書をコンパイルしてから演奏・書き出し |
| `Compiler path: max 24 bytes, no spaces.` | 短く空白のないファイル名・パスを使う |
| `MUCPLAY.COM not found.` | 現在の作業ディレクトリでMUCPLAYが見つかるか確認 |
| `Use the matching /E2 MUCPLAY.COM.` | 新しいエディタのE2復帰方式に対応したMUCPLAYを使う |
| `Cannot create MUCEDIT.RET.` | 状態保存ファイルの作成に失敗。ディスクの空き・書き込み可否を確認 |
| `Cannot create MEDCOMP.MUC (exists or disk error).` | 同名の一時ファイルの衝突、またはディスクエラー |

### 22.1 MEDCOMP.MUCが残っている場合

一時ファイルだからといって、無条件に削除しないでください。**保存していない最新の編集内容が入っている可能性があります。**

1. 現在のエディタとプレイヤーの作業が進行中かどうか、まず確認します。
2. 可能であれば、エディタの現在の文書を別名で保存します。
3. 残っている`MEDCOMP.MUC`と`MUCEDIT.RET`を別の場所へコピーして保存します。
4. 元のMUCと比較し、必要な修正が一時ファイルだけに残っていないか確認します。
5. 進行中の連携・復旧がなく、バックアップを確保したあとでのみ、衝突ファイルを別名へ移すなどの整理を行います。

`MEDCOMP.MUC`はテキスト入力ですが、`MUCEDIT.RET`は内部の状態ファイルです。両者を同じように編集したり、拡張子だけ変えてソースとして使ったりしてはいけません。

### 22.2 エディタ復帰の失敗

```text
Resume failed. R: Retry  Esc: Empty editor (MUCEDIT.RET kept).
```

- `R`: 残っている状態ファイルで復帰をもう一度試みます。
- `Esc`: 状態ファイルを消さずに、空のエディタで起動します。

このとき、新しいファイルを作ったりCOMを入れ替えたりする前に、状態ファイルを先に保存しておいてください。`MUCEDIT.RET`はエディタのバージョンとメモリ構造に結び付いています。異なるビルドのあいだで自由に持ち回れる一般的な復旧ファイルではありません。

通常の起動では、古いRETがあってもそれを自動復旧することはありません。`/R`はプレイヤーが正常復帰に使う内部手順であり、任意のRETを読み込ませるユーザー向け復旧コマンドとして使わないほうがよいでしょう。

## 23. メモリ・ファイルサイズ・文字処理の制限

| 項目 | 現在の基準 |
|---|---|
| 画面 | 80桁、全24行のうち通常の編集領域は22行 |
| 編集文書 | 最大24 KiB = 24,576バイト |
| 内部クリップボード | 最大4 KiB |
| Undo/Redo履歴 | 合計4 KiB、変更前後の内容と管理情報を含む |
| 補助作業マッパー | 16 KiBを1セグメント |
| ファイルを開くための一時マッパー | 16 KiBを2セグメント追加で必要 |
| 一覧ウィンドウ | 1ページ16件、全体の一覧は追加ページで検索 |
| MMLチャンネル行の本体 | 最大1,023バイト |
| マクロ本体 | 最大511バイト |
| マクロ呼び出しのネスト | 最大4段 |
| リピートのネスト | 最大16段 |
| 使用するFM音色の種類 | 最大32 |
| コンパイル済みの曲データ | 最大32 KiB。PCMを含むMUB全体のファイルサイズとは別 |

### 23.1 追加マッパーがあっても文書は40 KiBになりません

16 KiBの補助作業マッパーは、行移動・複製やファイル一覧などの作業領域です。文書24 KiB、クリップボード4 KiB、Undo 4 KiBの制限を増やす設定ではありません。

ファイルを開くときは、現在の文書をすぐに消さず、一時領域に新しい文書を読み込んで検証します。そのため、作業マッパーとは別に32 KiBの空きマッパーが一時的にさらに必要です。読み込み・クローズ・確保に失敗したときに、現在の文書を守るための構造です。

### 23.2 ディスク上のファイルサイズと編集サイズ

24 KiB制限は、改行などを整理した**内部文書サイズ**が基準です。

- CRLF、CR、LFの改行を読み、内部ではLFに整えます。
- ファイル先頭のUTF-8 BOMは取り除きます。
- DOSのCtrl+Zバイトはテキストの終端として扱います。
- 保存時は、内部のLFをCRLFとして出力します。

したがって、ディスク上のMUCが24 KiBを少し超えていても、改行を整理した内容が上限内であれば開ける場合があります。極端に改行の比率が大きいCRLFファイルであれば、約48 KiBまで内部24 KiBに収まることもあります。しかし、**一般的な48 KiBのMUCを編集できるという意味ではありません。**

現在のコンパイラが別途より大きなソース窓に対応していても、MUCEdit自体の編集上限は24 KiBです。

### 23.3 ハングル・日本語・UTF-8

MUCEditはバイト単位で動作するMSX用テキストエディタです。UTF-8 BOMを読めるという事実は、ハングル・日本語のUnicode編集全体に対応しているという意味ではありません。

複数バイトから成る文字は画面上で崩れて見えたり、移動・削除が文字単位ではなくバイト単位で作用したりすることがあります。MMLコマンド・数値・ファイル名はASCIIで書いてください。別の文字エンコーディングの説明文に手を入れるときは、必ず元を保管し、必要であればそのエンコーディングに正しく対応した外部エディタで修正するのが安全です。

<a id="24"></a>
## 24. よくある質問

### 保存しないと、修正した内容でコンパイルされないのですか

いいえ。F1→2は現在メモリ上の編集内容をコンパイルします。保存は必要ありません。ただし、そのあとF1→3を押さないと新しい結果は聴けません。コンパイルせずPlayだけを押すと、以前の結果を再生します。

### 修正したのに、コンパイル結果の画面が同じです

成功画面の文言が同じでも、曲データまで同じという意味ではありません。テンポや音符が変わっても、一般的な成功の文言は同じことがあります。実際に聴いてみるか、MUBを別名で保存して比較してみてください。

また、コメントやタイトルのような情報だけを変えた場合は、演奏される音は同じになります。チャンネル接頭部の壊れた行は警告のうえ無視されることもあるので、Warningも確認してください。

### 適当な文字列を入れてもErrorが出ません

すべてのテキストがMMLとして解釈されるわけではありません。説明文、不正なチャンネル接頭部、不明なタグは、警告だけを出して通過することがあります。**エラーがないことと、すべての行が演奏に使われたことは別です。**

### PCMの警告が出るのに、FMは聞こえます

FMデータとPCMバンクは別です。FMが聞こえるからといって、PCMも正常という意味ではありません。`#pcm`、実際のDOSファイル名、バンクファイルの位置を確認してください。

### MUBを出力したらPCMの音が抜けていました

欠落警告を無視して出力した可能性があります。現在の方針では、一部のPCM欠落状況でPCMなしのMUB生成を許容しています。正しいバンクを用意して、もう一度書き出してください。

### 音がまったく出ません

1. F1→2 (/Compile)が成功したか確認します。
2. 演奏画面に、対応音源デバイス関連のエラーがないか確認します。
3. エミュレータ・OS・実機のオーディオのミュートと出力接続を確認します。
4. `v0`、`p0`、SSGの`P0`、休符だけのパートなどを確認します。
5. 該当チャンネルの行が警告で無視されていないか確認します。
6. PCMだけを使う曲であれば、バンクの欠落から確認します。

### ブロックを選択したまま文字を入力したら、内容が消えました

選択範囲を新しい入力で置き換える、正常な編集動作です。選択の上に入力するつもりでなかったならCtrl+Zで戻し、選択を解除してから入力してください。大きな選択はUndoの上限を超えることがあるので注意が必要です。

### 行を分けたら、うしろの部分が演奏されません

新しい行の前にチャンネル文字を書き忘れていないか確認してください。`D cdef`のうしろのフレーズを、次の行に`gab>c`とだけ書いても、同じDチャンネルに自動でつながりません。`D gab>c`と書く必要があります。

### ファイル一覧の順序がおかしいです

現在の一覧は名前順のソートではなく、DOSのディレクトリ検索順です。一覧に見える順序だけでファイルが抜けていると判断せず、ページを移動するか名前を直接入力してください。

### 40桁画面で使えますか

現在のMUCEditは80桁画面を前提としています。40桁への切り替えモードは提供していません。

### 画面が遅くなりました

実機・エミュレータのCPU/VDP設定、エミュレータの速度制限やフレームスキップなどを分けて確認してください。画面更新が少ないことと、MSX内のプログラムの実行自体が遅いことは別の場合があります。まずは利用者が意図した正常なエミュレータ設定に戻して比較するのがよいでしょう。

### 検索・一括置換・自動補完はどこにありますか

文字列検索と次を検索には対応しています。現在のバージョンには、正規表現・一括置換・MMLの自動補完・シンタックスハイライト・エラー行への自動移動の機能はありません。選択と検索を組み合わせて、部分的に修正してください。

### MUCPLAYを替えるたびに、MUCEditも作り直す必要がありますか

E2連携規約が維持されていれば、原則としてエディタを毎回リビルドする必要はありません。ただし、新しいMUCPLAYがその規約を実際に守っているかどうかの連携検証は必要です。タイトルのバージョン文字列だけを見て互換性を判断しないでください。

<a id="25"></a>
## 25. 安全な作業とアップデート

私がおすすめする作業習慣は、難しいものではありません。

1. 受け取った元の曲は、一式を別に保管します。
2. 作業するファイルは別名で保存してから始めます。
3. 大きなブロックの削除や音色全体の変更の前には、途中の保存版を残します。
4. 修正結果を聴くたびに、コンパイルの成功と警告を確認します。
5. 完成したら、MUC、必要な音色・PCM、MUB/VGMを分けて保管します。
6. 終わるときは、できるだけメニューを通して正常に終了します。

### 実行ファイルの入れ替え

MUCEditとMUCPLAYを使っている最中にCOMファイルを上書きしないでください。メモリ上のコード・セッションと、ディスク上の新しいプログラムが混ざると、復帰状態が合わなくなることがあります。

推奨する順序は次のとおりです。

1. 編集中の内容を保存します。
2. MUCEditを正常に終了してDOSへ戻ります。
3. 別途保持しているMUCPLAYセッションがあれば、**入れ替え前のプレイヤー**で`/RELEASE`して片付けます。
4. 既存のCOMをバックアップします。
5. 新しいCOMを使用するディレクトリへコピーします。
6. 新しく起動して、小さな曲でコンパイル・演奏・復帰を確認します。

`MUCPLAY.SES`は曲全体をディスクに保管するプロジェクトファイルではなく、メモリに保持されたセッションを見つけるために使う情報です。別のマシンやリセット後まで曲データをそのまま復元できるファイルとは考えないでください。セッションファイルを消すことと、メモリを返すことも同じ作業ではありません。

### 問題を報告してくださるとき

次の情報を一緒にいただけると、原因を探しやすくなります。

- 実機のモデル、またはエミュレータと拡張デバイス
- 実行したMUCEDIT.COMとMUCPLAY.COMの実際の場所・ファイルサイズ・ビルド情報
- 問題が起きたMUCと、必要な音色・PCM
- 「開く → コンパイル → どの文字を修正 → 再コンパイル → 演奏」のような正確な手順
- エラー・警告の文言、または画面
- 元のファイルと、残っていればMEDCOMP.MUCの別途コピー

復旧が必要なファイルを先に消してから報告するのではなく、できるかぎり現在の状態を保存しておいてください。個人的に公開したくない内容があれば、コピーから除いて知らせていただければ大丈夫です。

| 保存 | Ctrl+S |
| 別名で保存 | Ctrl+Shift+S |
| 新規文書 | Ctrl+N |

| MUB / VGM出力 | F1→4 / F1→5 |

### 移動と行編集

| やりたいこと | キー |
|---|---|
| 行の先頭・末尾 | Home / End — 実機では HOME / SELECT |
| 文書の先頭・末尾 | Ctrl+Home / Ctrl+End |
| 単語移動 | Ctrl+← / Ctrl+→ |
| 移動しながら選択 | 上の移動キーにShiftを追加 |

### 間違えやすい5つ

1. **Ctrl+Sは保存、F1→2はコンパイルです。**

3. **F1→NはSave/New、Ctrl+Nは新規文書です。**
4. **MMLのtとT、cとCは別のコマンドです。**
5. **Warningのあとの成功メッセージは、警告を消してくれません。**
