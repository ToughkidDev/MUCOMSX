# MUCEdit 사용설명서

## MSX에서 MUC를 편집하고, 컴파일하고, 음악을 들어보기

**MUCEdit v0.8 by ToughkidCST**  
문서 기준일: 2026년 9월 14일

MUCEdit은 MSX에서 MUCOM88의 MUC 파일을 직접 열고 편집하기 위한 텍스트 에디터입니다. MUCPLAY와 함께 사용하면, 편집하던 자리에서 컴파일하고 곡을 들어본 다음 다시 돌아와 수정할 수 있습니다. 완성된 곡을 MUB나 VGM으로 내보내는 것도 가능합니다.

처음부터 모든 명령을 외우실 필요는 없습니다. 우선 파일을 열고, 한 부분을 바꾸고, 컴파일해서 들어보세요. 이 설명서도 그 순서대로 읽으시면 됩니다. 뒤쪽에는 MUC 문법, 오류와 경고, 문제가 생겼을 때 확인할 사항을 모아 두었습니다.

시작하기 전에 한 가지만 꼭 기억해 주세요.

> **저장, 컴파일, 연주는 서로 다른 작업입니다.**  
> 저장은 원본 MUC 파일을 갱신합니다. 컴파일은 현재 편집 내용을 연주 데이터로 바꿉니다. 연주는 마지막으로 컴파일한 결과를 재생합니다.

이 차이를 이해하시면 MUCEdit을 훨씬 편하게 사용하실 수 있습니다.

## 1. MUCEdit과 MUCPLAY의 역할

이름이 비슷하지만 하는 일은 다릅니다.

| 구성 요소 | 하는 일 |
|---|---|
| `MUCEDIT.COM` | MUC 텍스트 편집, 파일 입출력, 블록 선택, 검색, Undo/Redo, 명령 메뉴 |
| `MUCPLAY.COM` | MUC 적재와 컴파일, 연주, MUB/VGM 출력, 컴파일 결과와 오류 표시 |
| `MUBPLAY.COM` | 컴파일이 끝난 `.MUB` 파일을 독립적으로 연주하는 플레이어. Makoto(YM2608)용 |
| `.MUC` | 사람이 읽고 고칠 수 있는 곡의 소스 텍스트. DOS에서 `MUCPLAY SONG.MUC`로 직접 재생 가능하며, 내부에서 컴파일한 뒤 연주합니다. |
| `.MUB` | 컴파일된 곡 데이터. 필요에 따라 음색·태그·PCM을 포함하며, DOS에서 `MUBPLAY SONG.MUB`로 직접 재생할 수 있습니다. |
| `.VGM` | 재생 과정의 음원 칩 명령과 타이밍을 기록한 파일. DOS에서 `VGMPLAY SONG.VGM`으로 직접 재생할 수 있습니다. |

위 명령의 `SONG.MUC`, `SONG.MUB`, `SONG.VGM`은 예시입니다. 실제로 듣고 싶은 파일명으로 바꾸어 입력해 주세요. 각 플레이어와 해당 곡의 음원 칩을 지원하는 실행 환경이 필요합니다.

MUCEdit만 있어도 텍스트를 편집하고 저장할 수 있습니다. F1 메뉴의 컴파일·연주·내보내기를 사용하려면 호환되는 MUCPLAY가 함께 있어야 합니다. 이 작업을 위해 별도의 `MUC2MUB.COM`을 실행할 필요는 없습니다. 컴파일러는 MUCPLAY에 포함되어 있습니다.

MUBPLAY는 완성된 MUB를 따로 들어볼 때 사용합니다. 예를 들어 MUCEdit에서 F1→4로 `SONG.MUB`를 내보냈다면 DOS에서 `MUBPLAY SONG.MUB`로 연주할 수 있습니다. MUCEdit의 F1 메뉴가 호출하는 MUCPLAY와는 별도 프로그램이며, MUC 소스를 편집하거나 컴파일하는 역할은 하지 않습니다.

MUCEdit은 Windows용 VS Code 자체를 MSX로 옮긴 프로그램은 아닙니다. 익숙한 편집키를 최대한 사용할 수 있도록 구성한 MSX용 에디터입니다. 여러 파일을 탭으로 열기, 다중 커서, 마우스로 선택하기, 운영체제 공용 클립보드 같은 기능까지 같지는 않습니다.

## 2. 사용 환경과 준비할 파일

### 2.1 기본 환경

- 80컬럼 텍스트 화면을 사용할 수 있는 MSX2 이상 환경
- MSX-DOS2 계열 실행 환경과 512KB 권장의 메모리 매퍼 지원 (Megaflshrom SCC SD+, Carnivore2 등)
- 읽고 쓸 수 있는 디스크 또는 저장장치
- 연주할 경우 MUCPLAY가 지원하는 음원 장치 (Makoto YM2608 )

연동 검사에 사용한 대표 환경은 다음과 같습니다.

```tex
Panasonic_FS-A1WX
MegaFlashROM_SCC+_SD
MAKOTO
MSX-DOS2 / Nextor
```

실사용 준비에는 **512 KiB급 주 매퍼를 갖춘 환경**을 기준으로 잡으시면 좋습니다. 이것은 연동 검증에 사용한 구성이지, 모든 기종과 DOS 구성에 대한 엄밀한 최소 RAM 보증값은 아닙니다. DOS, 상주 프로그램, 현재 유지 중인 곡의 세션도 메모리를 사용하므로 설치된 RAM 총량만으로 실행 가능 여부가 결정되지는 않습니다.

또한 MSX에 내장 PSG가 있다는 것과 MUCPLAY가 요구하는 재생 장치가 있다는 것은 별개입니다. 이 설명서의 기본 연주 환경은 MAKOTO의 YM2608입니다. 다른 음원 구성은 해당 MUCPLAY 빌드의 지원 범위를 확인해 주세요.

### 2.2 파일은 우선 같은 디렉터리에 모아 주세요

처음에는 다음처럼 곡별 폴더를 구성하는 것을 권합니다.

```text
SONG/
  MUCEDIT.COM
  MUCPLAY.COM
  SONG01.MUC
  SONG02.MUC
  VOICE.DAT
  PCM01.BIN
```

실제로는 DOS에서 보이는 파일명이 중요합니다. 긴 호스트 파일명 대신 **8.3 형식의 짧은 이름**을 사용하는 것이 안전합니다. 예를 들어 `SONG01.MUC`, `VOICE.DAT`, `PCM01.BIN`처럼 정리해 주세요. 이름을 바꾸었다면 MUC 안의 파일 지정도 함께 맞춰야 합니다.

곡에 아래 태그가 있으면 그 파일이 필요합니다.

```text
#voice VOICE.DAT
#pcm PCM01.BIN
```

이름만 비슷한 다른 음색·PCM 파일을 가져오면 곡은 컴파일되어도 전혀 다른 소리가 날 수 있습니다. 곡과 함께 제공된 파일을 사용해 주세요.

### 2.3 파일명과 경로 주의사항

- 에디터의 직접 파일명 입력은 최대 63바이트입니다.
- **컴파일 연동에 사용하는 문서 이름·경로는 최대 24바이트이며 공백을 사용할 수 없습니다.**
- 음색·PCM 파일을 읽는 컴파일러의 FCB 경로는 DOS의 8.3 이름 제약을 받습니다. 긴 이름이 그대로 처리될 것이라고 생각하지 마세요.
- 파일 목록창에서 다른 경로를 입력해도 DOS의 현재 디렉터리가 바뀌지는 않습니다.
- 특히 다른 폴더의 MUC만 경로로 열면 음색·PCM·MUCPLAY의 위치를 혼동하기 쉽습니다. 처음에는 곡 폴더로 `CD`한 다음 그곳에서 실행해 주세요.

### 2.4 디스크는 쓰기 가능해야 합니다

원본 MUC를 저장하지 않는 컴파일도 임시 파일을 사용합니다. 따라서 읽기 전용 디스크에서는 연동 작업이 제한됩니다.

상태 보관용 파일에 약 33 KiB, 임시 MUC에 현재 문서 크기만큼의 공간이 필요하고, 내보내기를 하면 MUB·VGM 공간도 추가로 필요합니다. PCM이 큰 곡은 결과 파일도 커집니다. “원본 MUC가 몇 KB니까 디스크도 그 정도만 비어 있으면 되겠지”라고 생각하지 마시고 충분히 여유를 두세요.

## 3. 처음 실행하고 한 곡 들어보기

DOS에서 곡이 있는 디렉터리로 이동합니다.

```text
CD SONG
MUCEDIT SONG01.MUC
```

빈 문서로 시작하려면 파일명을 생략합니다.

```text
MUCEDIT
```

실행 후에는 다음 순서로 해보세요.

1. 파일 내용이 화면에 표시되는지 확인합니다.
2. `F1`을 누른 다음 `2`를 눌러 컴파일합니다.
3. 결과 화면에 오류나 경고가 있는지 읽습니다.
4. 안내에 따라 아무 키나 눌러 에디터로 돌아옵니다.
5. `F1`을 누른 다음 `3`을 눌러 연주합니다.
6. 중간에 멈추려면 아무 키나 누릅니다.
7. 결과 화면의 복귀 안내가 나오면 다시 키를 눌러 돌아옵니다.

여기서 `F1→2`는 F1과 숫자 2를 동시에 누르라는 뜻이 아닙니다. **F1을 눌러 메뉴를 연 다음 숫자 2를 누르는 순서**입니다.

이제 한 부분을 수정한 뒤 **다시 F1→2, 그다음 F1→3**을 해보세요. 마음에 드는 수정이라면 `Ctrl+S`로 저장하면 됩니다.

## 4. 화면과 커서 읽기

화면은 80컬럼이며, 위쪽 제목 행과 아래쪽 안내 행 사이가 편집 영역입니다.

### 제목 행

```text
MUCEdit v0.8 by ToughkidCST  |  SONG.MUC*
```

- 파일명이 표시됩니다. 아직 이름이 없으면 이름 없는 문서로 표시됩니다.
- 파일명 뒤의 `*`는 저장되지 않은 변경이 있다는 뜻입니다.
- 선택 범위가 있으면 `[SELECT]` 표시가 추가됩니다.
- 파일명이 길면 제목 행의 뒤쪽 정보가 모두 보이지 않을 수 있습니다.

### 커서와 블록은 다릅니다

커서는 글자를 넣을 위치를 나타내는 가느다란 세로 막대입니다. 현재 v0.8 구현에서는 입력 대기 중 커서가 점멸하고, 이동하면 바로 보이는 상태가 됩니다. **선택 블록의 반전 표시는 점멸하지 않습니다.** 커서가 깜박이는 것과 블록 전체가 사라지는 것은 구분해 주세요.

선택한 줄바꿈은 행 끝의 빈 한 칸으로 표시됩니다. 빈 행에도 선택 표시가 생길 수 있는데, 이것은 빈 행의 줄바꿈을 선택했다는 뜻입니다.

### 긴 행

긴 MML 행은 오른쪽으로 계속 이어질 수 있습니다. 커서를 이동하면 가로로 스크롤됩니다. 화면 오른쪽에서 보이지 않는다고 텍스트가 삭제된 것은 아닙니다.

화면 폭 80컬럼과 컴파일러의 한 행 길이 제한은 다른 이야기입니다. 긴 행을 보기에 편하도록 여러 행으로 나눌 때는, 새 행에도 반드시 채널 문자를 붙여 주세요.

## 5. 파일 열기와 파일 목록창

`Ctrl+O` 또는 `F1→1 Open/MUC`를 사용합니다.

현재 디렉터리의 `*.MUC` 파일이 한 열짜리 목록창에 표시되고, 아래쪽에는 파일명을 직접 입력할 수 있는 칸이 나옵니다.

| 키 | 파일 목록창에서 하는 일 |
|---|---|
| `↑` / `↓` | 이전·다음 파일 선택 |
| `Ctrl+↑` / `Ctrl+↓` | 이전·다음 페이지 |
| `Home` / `End` | 현재 페이지의 첫 항목·마지막 항목 |
| `Enter` | 선택한 파일 또는 입력한 이름 열기 |
| `Esc` | 취소하고 편집 화면으로 돌아가기 |
| 문자 입력 | 목록 선택 대신 파일명·경로 직접 입력 |
| `Backspace` / `Delete` | 직접 입력한 이름의 마지막 글자 지우기 |

한 페이지에는 최대 16개가 표시됩니다. 이것은 전체 파일을 16개만 읽는다는 뜻이 아닙니다. 목록 끝을 넘어 이동하거나 페이지 키를 사용하면 다음 항목을 찾습니다.

알아두실 점은 다음과 같습니다.

- 목록은 **DOS의 디렉터리 검색 순서**입니다. 이름순 정렬이 아닙니다.
- 하위 디렉터리를 탐색하는 파일 관리자는 아닙니다. 필요한 경로는 직접 입력할 수 있습니다.
- 문자를 입력하기 시작하면 기존 목록 선택 대신 직접 입력한 이름을 사용합니다.
- 파일이 없어도 직접 입력은 가능합니다. 빈 목록에서 이름 없이 Enter를 눌러도 파일이 열리지는 않습니다.
- 목록용 작업 메모리가 부족한 경우 직접 파일명 입력 방식으로 동작할 수 있습니다.

미저장 변경이 있으면 먼저 `Unsaved changes. Discard? (Y/N)`을 묻습니다. 버려도 좋을 때만 `Y`를 눌러 주세요. 이후 목록창에서 Esc로 취소하거나 새 파일 읽기에 실패한 경우에는 현재 문서가 유지되도록 처리합니다.

## 6. 저장·새 문서·다시 읽기·종료

### 저장: Ctrl+S

현재 문서를 현재 이름으로 저장합니다. 이름이 없는 문서라면 파일명을 입력합니다. 저장이 성공하면 미저장 표시가 정리됩니다.

기존 이름에 저장하면 기존 파일을 갱신합니다. 원본을 남기고 비교하고 싶다면 먼저 다른 이름으로 저장해 주세요. 저장 실패에 대비한 자동 백업 파일 생성 기능은 없습니다.

### 다른 이름으로 저장: Ctrl+Shift+S

현재 내용을 다른 파일명으로 저장합니다. 예를 들어 배포된 `BOS010.MUC`를 수정하기 전 `BOS010A.MUC`로 저장해 두면 원본과 비교하기 편합니다.

다른 이름으로 바꾼 뒤에는 연주·내보내기 전에 다시 컴파일해 주세요. 이전 파일 이름에 연결되어 있던 컴파일 결과를 새 문서의 결과로 취급하지 않습니다.

### 새 문서: Ctrl+N 또는 F1→A

새 빈 문서로 시작합니다. 미저장 내용이 있으면 버릴 것인지 확인합니다.

`F1→N Save/New`는 **현재 문서를 먼저 저장하고** 새 문서로 시작하는 명령입니다. `N`이라는 글자만 보고 “그냥 New”라고 생각하지 않도록 주의해 주세요.

### 다시 읽기: F1→O Reload

현재 이름의 파일을 디스크에서 다시 읽습니다. 미저장 수정 내용을 버리고 마지막 저장본으로 돌아갈 때 사용합니다. 미저장 변경이 있으면 확인을 묻습니다.

Reload는 Undo와 다릅니다. 파일을 다시 읽으면 그 문서를 새로 연 상태가 되므로, 이전 편집 기록을 계속 사용할 수 있다고 기대하지 마세요.

### 종료

| 명령 | 동작 |
|---|---|
| `F1→E Save/Exit` | 저장한 뒤 종료 |
| `F1→Q Quit` | 저장하지 않고 종료. 미저장 변경이 있으면 확인 |

MUCPLAY를 호출한 세션에서는 종료할 때 플레이어 쪽에 유지된 매퍼 메모리를 반환하는 작업이 이어질 수 있습니다. 종료 메시지가 잠깐 더 나온다고 바로 리셋하지 마시고 DOS 프롬프트로 돌아올 때까지 기다려 주세요.

<a id="07"></a>
## 7. 커서 이동과 블록 선택

### 기본 이동

| 키 | 동작 |
|---|---|
| `←` / `→` | 한 글자 이동 |
| `↑` / `↓` | 이전·다음 논리 행 이동 |
| `Home` / `End` | 현재 행의 처음·끝 |
| `Ctrl+Home` / `Ctrl+End` | 문서의 처음·끝 |
| `Ctrl+←` / `Ctrl+→` | 단어 단위 이동 |

위아래로 이동할 때는 가능한 한 원래 열 위치를 유지합니다. 중간에 짧은 행이나 빈 행을 지나면 잠깐 행 끝에 머물 수 있습니다.

실제 MSX 키보드에서는 **HOME이 Home, SELECT가 End**에 해당합니다. 에뮬레이터의 PC 키보드 매핑은 설정에 따라 다를 수 있습니다.

### 블록 선택

블록을 잡으려면 **Shift를 누른 채 커서를 이동**하세요.

| 키 | 선택 범위 |
|---|---|
| `Shift+←/→` | 글자 단위 |
| `Shift+↑/↓` | 행 사이로 확장 |
| `Shift+Home/End` | 현재 위치부터 행 처음·끝까지 |
| `Ctrl+Shift+←/→` | 단어 단위 |
| `Ctrl+Shift+Home/End` | 문서 처음·끝까지 |
| `Ctrl+A` | 문서 전체 |
| `Ctrl+L` | 현재 행 |

예를 들어 `t225`의 숫자를 바꾸려면 숫자 앞이나 뒤로 이동해서 Shift와 좌우키로 숫자를 선택한 뒤 새 숫자를 입력하면 됩니다. 선택된 부분은 새 입력으로 대체됩니다.

선택한 상태에서 Shift 없이 왼쪽을 누르면 선택 시작점으로, 오른쪽을 누르면 선택 끝점으로 이동하며 선택을 풉니다. Esc로 선택을 해제할 수도 있습니다.

MUCEdit의 선택은 일반적인 연속 텍스트 선택입니다. 사각형 열 선택이나 여러 위치를 동시에 편집하는 다중 커서는 지원하지 않습니다.

## 8. 복사·잘라내기·붙여넣기·행 편집

### 기본 편집

| 키 | 동작 |
|---|---|
| `Ctrl+C` | 선택 부분 복사. 선택이 없으면 현재 행 복사 |
| `Ctrl+X` | 선택 부분 잘라내기. 선택이 없으면 현재 행 잘라내기 |
| `Ctrl+V` | 클립보드 내용 붙여넣기 |
| `Backspace` | 커서 앞 글자 삭제. 선택이 있으면 선택 삭제 |
| `Delete` | 커서 뒤 글자 삭제. 선택이 있으면 선택 삭제 |
| `Enter` | 줄바꿈 삽입 |
| `Tab` | 탭 문자 삽입 |

클립보드는 MUCEdit 내부용이며 최대 4 KiB입니다. Windows/macOS에서 복사한 내용이 Ctrl+V로 자동 연결되는 것은 아닙니다. 호스트의 내용을 넣으려면 사용 중인 에뮬레이터의 문자열 입력 기능 등을 별도로 이용해야 합니다.

탭은 공백 몇 개로 바꾸어 저장하는 것이 아니라 탭 바이트 자체를 넣습니다. 특히 채널 문자 앞에 탭을 넣어 들여쓰면 MML 채널 행으로 인식되지 않을 수 있으니 주의하세요.

### 행 단위 편집

| 키 | 동작 |
|---|---|
| `Ctrl+Shift+K` | 현재 행 삭제 |
| `Ctrl+Enter` | 현재 행 아래에 새 행 삽입 |
| `Ctrl+Shift+Enter` | 현재 행 위에 새 행 삽입 |
| `Graph+↑/↓` | 현재 행을 위·아래로 이동 |
| `Shift+Graph+↑/↓` | 현재 행을 위·아래로 복제 |

Graph는 MSX 키보드의 GRAPH 키입니다. PC의 VS Code에서 Alt를 사용하는 행 이동·복제에 대응합니다.

행 이동과 복제는 클립보드를 덮어쓰지 않습니다. 이 기능은 **커서가 있는 현재 논리 행**을 대상으로 합니다. 여러 행을 선택했다고 선택된 행 전체가 한꺼번에 이동하는 방식은 아닙니다.

비슷한 프레이즈를 하나 더 만들 때는 행 복제가 편합니다. 다만 복제된 행은 같은 채널의 뒤에 이어서 연주됩니다. 다른 채널에서 동시에 연주하고 싶다면 복제한 행의 채널 문자도 바꿔 주세요.

<a id="09"></a>
## 9. Undo와 Redo

- `Ctrl+Z`: 직전 편집 되돌리기
- `Ctrl+Y`: 되돌린 편집 다시 적용하기

컴파일이나 연주를 했다가 에디터로 돌아와도 문서와 함께 Undo/Redo 상태를 유지합니다. 저장 여부를 나타내는 상태도 추적하므로, Undo로 마지막 저장 시점까지 돌아가면 미저장 표시가 없어질 수 있습니다.

다만 **무제한 Undo는 아닙니다.** 현재 기록 공간은 4 KiB이고, 변경 전후의 텍스트와 관리 정보가 함께 들어갑니다. 따라서 “항상 몇 회까지 되돌릴 수 있다”는 고정 횟수로 설명할 수 없습니다.

- 기록 공간이 차면 기존 기록을 초기화하고 새 기록을 남깁니다.
- 한 번의 변경 자체가 기록 공간보다 크면 그 변경을 Undo로 되돌리지 못하며 이전 기록도 초기화될 수 있습니다.
- Undo한 뒤 새로운 내용을 편집하면 기존 Redo 경로는 사라집니다.
- 파일을 새로 열거나 New/Reload하면 이전 문서의 Undo 기록은 유지되지 않습니다.

큰 블록을 지우거나 긴 프레이즈 전체를 바꾸기 전에는 다른 이름으로 저장해 두세요. 저는 Undo를 백업의 대체품으로 생각하지 않는 쪽을 권합니다.

## 10. 문자열 찾기와 부분 수정

`Ctrl+F`를 누르고 찾을 문자열을 입력한 뒤 Enter를 누릅니다. 찾은 부분이 선택됩니다. 같은 문자열의 다음 위치는 `F3`으로 찾습니다. 문서 끝까지 찾으면 앞부분으로 돌아가 검색합니다.

현재 검색은 **대소문자를 구분하는 일반 문자열 검색**입니다. 정규식 검색이나 전체 일괄 치환 기능은 없습니다.

대신 부분 치환은 다음처럼 할 수 있습니다.

1. `Ctrl+F`로 `t225`를 찾습니다.
2. 찾은 부분이 선택되어 있는지 확인합니다.
3. `t200`을 입력해 해당 부분을 바꿉니다.
4. 필요한 경우 같은 방법으로 다른 위치를 수정합니다.

검색으로 선택된 범위 위에 바로 입력하면 그 범위가 교체됩니다. 찾기만 하려던 경우에는 방향키나 Esc로 선택을 푼 다음 입력하세요.

## 11. F1 메뉴 전체 안내

F1을 누르면 아래 두 행이 나타납니다.

```text
E Save/Exit     Q Quit       S Save      N Save/New    A Discard/New   O Reload
1 Open/MUC      2 Compile    3 Play/Muc                4 Exp/MUB       5 Exp/VGM
```

| 키 | 메뉴 이름 | 설명 |
|---|---|---|
| `E` | Save/Exit | 저장 후 종료 |
| `Q` | Quit | 저장 없이 종료. 필요한 경우 확인 |
| `S` | Save | 현재 문서 저장 |
| `N` | Save/New | 저장 후 새 문서 |
| `A` | Discard/New | 현재 문서를 버리고 새 문서. 필요한 경우 확인 |
| `O` | Reload | 현재 이름의 파일을 디스크에서 다시 읽기 |
| `1` | Open/MUC | 파일 목록창 또는 직접 입력으로 열기 |
| `2` | Compile | **현재 메모리의 편집 내용** 컴파일 |
| `3` | Play/Muc | 마지막 컴파일 결과 연주 |
| `4` | Exp/MUB | 마지막 컴파일 결과를 MUB로 저장 |
| `5` | Exp/VGM | 마지막 컴파일 결과를 VGM으로 출력 |

메뉴에서 Esc를 누르면 명령을 실행하지 않고 돌아옵니다. `O`는 알파벳 O이며 숫자 0이 아닙니다.

<a id="12"></a>
## 12. 미저장 컴파일과 연주

### 12.1 저장하지 않아도 컴파일됩니다

F1→2는 디스크의 원본 MUC를 다시 읽어 컴파일하는 명령이 아닙니다. **지금 에디터 안에서 편집 중인 문서**를 컴파일합니다.

예를 들어 디스크의 파일이 `A t225`이고 화면에서 `A t125`로 바꾸었다면, 저장하지 않아도 F1→2는 `t125`를 사용해야 합니다. 이때 원본 MUC는 여전히 `t225`이고, 제목의 미저장 표시도 유지됩니다.

새 문서에 아직 이름이 없으면 컴파일 과정에서 이름 입력을 요구할 수 있습니다. 이름을 지정하는 것과 원본 MUC를 실제 저장하는 것은 별개입니다. **컴파일이 성공했다고 새 MUC 파일이 저장되었다고 생각하지 마세요.** 남길 내용은 Ctrl+S로 저장해야 합니다.

### 12.2 왜 MEDCOMP.MUC가 생기나요?

MUCPLAY의 컴파일러는 파일을 입력으로 받습니다. 에디터는 메모리의 문서를 현재 디렉터리의 `MEDCOMP.MUC`라는 임시 파일에 써서 넘깁니다.

또한 에디터로 돌아오기 위한 상태를 `MUCEDIT.RET`에 보관합니다. 정상적으로 복귀하면 임시 입력과 복귀 상태 파일은 정리됩니다. 이 파일들은 원본 MUC를 대신하는 일반 저장 파일이 아닙니다.

같은 이름의 `MEDCOMP.MUC`가 이미 있으면 함부로 덮어쓰지 않고 컴파일을 중단합니다. 충돌 메시지가 나온 경우의 대처는 [복구 안내](#22)를 참고해 주세요.

### 12.3 Play는 자동 컴파일이 아닙니다

```text
편집 → F1, 2 → 결과 확인 → 키를 눌러 복귀 → F1, 3
```

이 순서를 기억해 주세요. 편집한 다음 F1→3만 누르면 **이전 컴파일 결과**를 듣습니다. 이것은 미저장 내용을 저장하지 않았기 때문이 아니라, 아직 새로 컴파일하지 않았기 때문입니다.

MUCEdit의 Play는 `/L2`로 실행합니다. 반복하는 곡은 두 번의 재생 회차를 기준으로 종료하도록 요청합니다. 곡의 `L` 지점이나 각 채널의 종료 구조에 따라 반복되는 부분이 정해지므로, 모든 곡이 파일 처음부터 끝까지 똑같이 두 번 재시작된다는 뜻은 아닙니다.

### 12.4 오류가 났다면

오류 화면을 읽고 에디터로 돌아와 수정한 뒤 다시 컴파일하세요. 실패한 컴파일을 새 정상 세션으로 취급하지 않습니다. 연주를 시도하면 컴파일된 결과가 없다는 오류가 나올 수 있습니다.

`Compiled into session.`은 컴파일 성공을 알리는 메시지입니다. 하지만 그 전에 **Warning이 있었는지까지** 보셔야 합니다. 성공 메시지만 보고 경고를 지나치면 의도하지 않은 곡을 듣게 될 수 있습니다.

## 13. MUB와 VGM 내보내기

### 13.1 MUB: F1→4

마지막으로 컴파일한 세션을 MUB 파일로 저장합니다. 문서가 `SONG.MUC`이면 일반적으로 `SONG.MUB`라는 이름을 사용합니다.

MUB에는 컴파일된 곡 데이터와 필요한 음색·태그가 들어가고, PCM을 사용하는 곡에서는 PCM 뱅크도 포함됩니다. **MUB가 만들어졌다고 원본 MUC가 저장되는 것은 아닙니다.** 소스를 함께 보관하려면 Ctrl+S도 해주세요.

수정한 내용을 반영한 MUB를 만들려면 먼저 F1→2로 재컴파일해야 합니다. 이전 출력과 비교하고 싶다면 기존 MUB를 다른 이름으로 보관하세요. 내보내기가 자동 버전 관리나 백업을 해주지는 않습니다.

### 13.2 VGM: F1→5

마지막 컴파일 결과를 음원 칩 명령과 타이밍의 흐름으로 출력합니다. `SONG.MUC`의 기본 출력 이름은 `SONG.VGM`입니다.

VGM은 WAV나 MP3 같은 녹음 파일이 아닙니다. YM2608 등의 기록된 칩 명령을 지원하는 VGM 재생 환경이 필요합니다. MUC처럼 다시 텍스트를 고쳐 작곡하는 용도의 소스 파일도 아닙니다.

MUCEdit 메뉴의 VGM 내보내기는 Play의 `/L2`를 그대로 사용하는 것이 아닙니다. 별도 반복 횟수를 넘기지 않으므로 현재 MUCPLAY의 VGM 기본값인 **한 회차 출력**을 사용합니다. 큰 곡이나 PCM이 있는 곡은 출력에 시간이 걸릴 수 있으니, 완료 메시지를 확인할 때까지 기다려 주세요.

### 13.3 내보내기 전 확인

1. 필요한 수정이 모두 끝났는가?
2. 그 수정 상태에서 다시 컴파일했는가?
3. 오류뿐 아니라 경고도 확인했는가?
4. 올바른 PCM·음색 파일을 사용했는가?
5. 소스 MUC도 별도로 저장했는가?
6. 기존 출력 파일을 보존해야 한다면 미리 다른 이름으로 남겼는가?

## 14. MUC 파일의 기본 구조

MUC는 MML로 곡을 적는 텍스트 파일입니다. 기본적으로 **헤더 → 음색·매크로 정의 → 채널별 연주 내용** 순서로 구성하면 읽기 쉽습니다.

### 14.1 헤더 태그

```muc
#mucom88 1.7
#title My First Song
#composer ToughkidCST
#author ToughkidCST
#date 2026/09/14
#comment First test on MSX

D t200 C128 o4 l8 v10 cdefgab>c4
```

| 태그 | 용도 |
|---|---|
| `#title` | 곡 제목 |
| `#composer` | 작곡자 |
| `#author` | MUC 작성자·편곡자 등 제작 정보 |
| `#date` | 날짜 정보 |
| `#comment` | 설명·주석 |
| `#mucom88` | MUCOM88 관련 버전 정보 |
| `#voice` | 외부 FM 음색 파일 지정 |
| `#pcm` | PCM 뱅크 파일 지정 |
| `#driver`, `#version`, `#uuid`, `#mucmd5` | 호환용 메타데이터 |

태그 이름의 대소문자는 구분하지 않지만, **`#` 바로 뒤에 정확한 이름과 공백으로 구분한 값**을 적는 습관을 권합니다. `#title: My Song`, `# title My Song`, `#tittle My Song`은 같은 태그가 아닙니다.

메타데이터를 적었다고 그 이름의 드라이버나 컴파일러 버전이 자동으로 선택되는 것은 아닙니다. 실제 해석과 재생은 실행 중인 MUCPLAY에 달려 있습니다.

`#voice`와 `#pcm` 같은 기능 태그는 파일 맨 앞의 헤더에 모아 주세요. 일반 주석이나 본문을 먼저 적고 뒤늦게 기능 태그를 넣으면 초기 헤더 바깥의 태그로 무시될 수 있습니다. 특히 **세미콜론 주석이나 공백 문자가 들어간 행 뒤로 기능 태그를 미루지 않는 것**이 안전합니다.

`#tempo`는 현재 알려진 태그가 아닙니다. 템포는 채널의 `t` 또는 `T` 명령으로 지정하세요.

### 14.2 채널 A–K

| 채널 | 음원 |
|---|---|
| A, B, C | FM 1, 2, 3 |
| D, E, F | SSG 1, 2, 3 |
| G | 리듬 |
| H, I, J | FM 4, 5, 6 |
| K | ADPCM/PCM |

FM 채널이 A부터 F까지 연속되어 있다고 생각하기 쉽지만, 그렇지 않습니다. **D·E·F는 SSG이고 H·I·J가 나머지 FM**입니다.

채널 행은 반드시 줄 맨 앞의 대문자 A–K와 공백 또는 탭으로 시작합니다.

```muc
D o4 l4 cdef
E o3 l4 c r g r
D gab>c
```

이 예에서 D의 두 행은 서로 이어집니다. E는 별도 채널에서 진행합니다. 같은 채널의 다음 행으로 넘어간다고 옥타브·길이·음량이 자동 초기화되는 것은 아닙니다.

아래 형태는 올바른 채널 행이 아닙니다.

```text
 D cdef       ; 앞에 공백이 있음
d cdef        ; 채널 문자가 소문자
Dcdef         ; 채널 뒤 공백/탭이 없음
DE cdef       ; 두 채널 동시 지정 형식이 아님
ABCD          ; 그냥 적은 문자열
```

앞쪽에 공백을 넣어 정렬하고 싶더라도 **채널 문자만큼은 맨 앞에 남겨 주세요.** 음악 명령 사이의 공백으로 읽기 편하게 정리하면 됩니다.

### 14.3 주석

설명은 `;`를 사용하면 됩니다.

```muc
; Main melody
D o4 l8 cdef ; first phrase
D gab>c4    ; second phrase
```

설명문을 아무 표시 없이 본문에 쓰지 마세요. 현재 컴파일러가 연주 행으로 해석하지 못해 경고할 수 있습니다. 주석은 곡을 나중에 다시 고칠 때도 큰 도움이 됩니다.

<a id="15"></a>
## 15. 음표·길이·옥타브·템포

### 15.1 음표와 쉼표

`c d e f g a b`는 도·레·미·파·솔·라·시입니다. 음표는 소문자로 씁니다.

- `c+`: 도 올림
- `d-`: 레 내림
- `r`: 쉼표

```muc
D o4 l8 c c+ d d- e r g r
```

MML은 대소문자에 따라 뜻이 달라집니다. `c`는 음표지만 `C`는 기준 클록, `r`는 쉼표지만 `R`은 별도의 효과 명령입니다.

### 15.2 길이

| 표기 | 뜻 |
|---|---|
| `l4` | 숫자를 생략한 음표의 기본 길이를 4분음표로 설정 |
| `l8` | 기본 길이를 8분음표로 설정 |
| `c4` | 이번 도를 4분음표로 연주 |
| `c8` | 이번 도를 8분음표로 연주 |
| `c4.` | 점4분음표 |
| `r8` | 8분쉼표 |

```muc
D o4 l8 c d e4 f8 g4. r8
```

`C128`이면 온음표를 128클록으로 나눕니다. 이때 `l4`는 32클록, `l8`은 16클록입니다. 기본 기준도 128이지만, 다른 곳에서 가져온 프레이즈를 합칠 때는 `C` 값이 같은지 확인해 주세요.

직접 클록으로 지정하는 `%`도 사용할 수 있습니다. 예를 들어 `c%12`는 이번 음을 12클록으로 지정합니다. 보통 처음에는 `l4`, `l8` 같은 표기를 사용하고, 세밀한 리듬을 맞출 때 직접 클록을 사용하시면 됩니다.

길이 0은 사용하지 마세요. `l0`처럼 유효한 음 길이를 만들 수 없는 입력은 오류가 됩니다. 기준 클록보다 너무 큰 분모를 주어 길이가 0이 되는 경우도 피해야 합니다.

### 15.3 옥타브

- `o4`: 옥타브 4
- `>`: 한 옥타브 올리기
- `<`: 한 옥타브 내리기
- 명시적 옥타브 지정 범위: `o1`부터 `o8`

```muc
D o4 l4 c d e f >c <g
```

음표를 여러 행에 나누었을 때 이전 행의 `>`가 다음 행에도 영향을 줍니다. 프레이즈를 옮겨 붙였는데 음역이 이상하면 그 앞의 옥타브 상태부터 확인해 보세요.

### 15.4 타이와 길이 연장

`&`는 다음 음과 이어지는 타이 표현에 사용합니다. 같은 음을 길게 유지하는 용도부터 익혀 보세요.

```muc
D o4 l4 c4&c4 d4 e4
```

`^`는 앞 음의 길이를 추가하는 별도 표현입니다. 처음에는 `&`로 명확하게 작성하고, 기존 곡에 나오는 `^`를 수정할 때 앞 음과 길이의 관계를 함께 살펴보시면 좋습니다.

### 15.5 템포: t와 T는 다릅니다

| 표기 | 의미 |
|---|---|
| `t225` | Timer-B 값 직접 지정. **BPM 225라는 뜻이 아님** |
| `T120` | BPM 방식의 템포 지정. 내부에서는 Timer-B 값으로 변환 |

```muc
D T120 C128 o4 l4 cdefgab>c
```

기존 MUCOM88 곡에는 `t` 직접 지정이 많이 사용됩니다. `T`는 내부 정수 변환과 클록 설정의 영향을 받으므로 다른 재생기의 BPM 표시와 완전히 같은 측정값을 보장하는 표시는 아닙니다.

템포는 곡의 재생 시계에 영향을 줍니다. 여러 채널에 서로 다른 템포를 아무렇게나 적기보다는 한 곳에서 명확하게 관리하는 것을 권합니다. 기존 곡의 템포를 비교할 때는 다른 행에 같은 명령이 또 있는지도 찾아보세요.

## 16. 음색·음량·팬·채널별 표현

### 16.1 음량 v

`v`는 음량 지정입니다. 다만 채널 종류마다 처리 방식과 유효한 실용 범위가 다릅니다.

```muc
D o4 l8 v8 cdef v12 gab>c4
```

SSG는 0–15 범위에서 시작하는 것이 이해하기 쉽습니다. FM도 우선 기존 곡의 `v` 설정을 기준으로 작은 폭으로 조절해 보세요. K 채널은 바이트 단위의 ADPCM 음량을 사용하므로 FM·SSG와 같은 숫자를 넣었다고 같은 크기로 들리지 않습니다.

`)`는 음량 증가, `(`는 감소에 사용합니다. 숫자를 붙여 변화량을 지정하는 표현도 있습니다. 너무 큰 값을 주면 기대한 대로 커지거나 작아지는 것이 아니라 채널별 바이트 처리 범위를 벗어날 수 있으므로 조금씩 바꾸어 들어보세요.

### 16.2 음 길이와 소리 나는 길이: q

`q`는 음 끝에서 일찍 소리를 끊는 길이를 설정합니다. **q0은 기본적으로 음 끝까지 유지하는 쪽**입니다. 다른 MML에서 쓰는 “q8이면 8/8 길이” 같은 비율 표기로 혼동하지 마세요.

```muc
D o4 l8 v10 q0 cdef q4 gab>c
```

음표 전체의 시간은 같아도, q가 있는 부분은 끝을 조금 떼어 연주하는 느낌이 됩니다. 타이·엔벨로프·채널 종류에 따른 효과도 함께 작용합니다.

### 16.3 팬 p

FM·ADPCM의 기본 팬은 `p1` 오른쪽, `p2` 왼쪽, `p3` 양쪽입니다. `p0`은 양쪽 출력을 끄는 설정이 될 수 있으므로 소리가 안 날 때 꼭 확인하세요.

SSG에는 같은 방식의 독립적인 하드웨어 팬이 없습니다. SSG에 `p`를 적어 FM과 같은 좌우 이동이 생길 것이라고 기대하지 마세요.

### 16.4 FM 음색 @

FM 채널의 `@1`은 음색 번호 1을 선택합니다. 외부 음색 파일이나 소스 안의 음색 정의가 그 번호에 맞게 준비되어 있어야 합니다.

외부 파일은 헤더에서 지정합니다.

```text
#voice VOICE.DAT
```

현재 한 곡에서 사용하는 서로 다른 FM 음색은 최대 32개입니다. 음색 번호의 숫자 자체와 “이번 곡에서 사용한 음색 종류의 수”는 구분해 주세요.

소스에 직접 쓰는 기본 음색 정의는 다음 구조입니다.

```text
  @번호
   FB, ALG
  AR, D1R, D2R, RR, D1L, TL, KS, ML, DT
  AR, D1R, D2R, RR, D1L, TL, KS, ML, DT
  AR, D1R, D2R, RR, D1L, TL, KS, ML, DT
  AR, D1R, D2R, RR, D1L, TL, KS, ML, DT
```

또는 `@번호:{ ... }` 형식도 사용합니다. 앞의 두 값은 피드백과 알고리즘이며, 뒤의 네 행은 각 오퍼레이터의 파라미터입니다. 값 순서를 바꾸면 다른 음색이 됩니다. FM 음색을 처음 수정하실 때는 검증된 기존 정의를 복사해 한 항목씩 바꾸는 것이 좋습니다.

음색 정의 행의 `@`와 **채널 행 안의 음색 선택 명령 `@`**는 구분해 주세요. 채널 안의 `A @1 c`는 음색을 정의하는 것이 아니라 선택하는 것입니다.

### 16.5 SSG

SSG는 D·E·F 채널입니다. 기본 음표·길이·옥타브·음량 외에 다음 계열의 명령을 사용합니다.

| 명령 | 용도 |
|---|---|
| `@n` | SSG 프리셋 선택. FM 음색 번호와 같은 데이터가 아님 |
| `P1` | 톤 사용 설정 |
| `P0` | 믹스 출력 끄기 |
| `wN` | 노이즈 주기 설정 |
| `E...` | 소프트웨어 엔벨로프. 여섯 값을 쉼표로 구분 |
| `SN` | 하드웨어 엔벨로프 형태 |
| `mN` | 하드웨어 엔벨로프 주기 |

프리셋이나 엔벨로프까지 한꺼번에 바꾸면 어떤 설정이 음색을 바꿨는지 알기 어렵습니다. 우선 단순한 SSG 멜로디가 정상적으로 들리는지 확인한 뒤 한 항목씩 추가해 보세요.

### 16.6 리듬 G

G는 일반 멜로디 채널이 아니라 리듬 채널입니다. FM·SSG의 음량이나 음색 명령을 그대로 적용하는 채널로 생각하지 마세요.

예를 들어 G의 `v`는 전체/각 리듬의 음량을 쉼표로 나열하는 **일곱 값 형식**을 사용합니다. `G v12 c`처럼 일반 멜로디와 같은 한 값 형식으로 적으면 구분자·인수 오류가 날 수 있습니다.

리듬 파트를 처음 만들 때는 정상 재생되는 곡의 G 채널을 바탕으로 악기 선택과 음량을 유지한 채 길이부터 조절하는 편이 좋습니다.

### 16.7 PCM K

K 채널은 PCM 샘플을 선택하고 연주하는 데 사용합니다. `@n`의 의미와 실제로 나오는 소리는 사용 중인 PCM 뱅크에 따라 달라집니다.

```text
#pcm PCM01.BIN
```

이 태그는 단순한 설명이 아니라 사용할 파일을 지정합니다. `#`를 지우면 PCM 지정 기능이 사라지고 기본 이름인 `MUCOMPCM.BIN`을 찾게 될 수 있습니다.

컴파일 단계는 PCM을 음원 칩에 전송하는 단계가 아닙니다. PCM 관련 문제는 연주할 때나 MUB로 붙여 넣을 때 드러날 수도 있습니다. “컴파일이 성공했으니 PCM도 모두 정상”이라고 판단하지 마세요.

<a id="17"></a>
## 17. 반복·매크로·고급 명령

### 17.1 반복 [ ]

```muc
D o4 l8 [cdef]2 gab>c4
```

`cdef`를 두 번 연주한 다음 뒤의 프레이즈로 진행합니다. 반복 횟수는 명확하게 적는 것을 권합니다. 여는 `[`와 닫는 `]`의 짝이 맞아야 합니다.

### 17.2 마지막 반복에서 빠져나오기 /

```muc
D o4 l8 [c d / e f]2 g4
```

마지막 회차에서는 `/` 뒤의 반복 본문을 생략하고 반복 다음으로 진행합니다. `/`는 반복 안에서 사용해야 하며, 같은 반복에 중복으로 넣지 마세요.

반복 중첩은 최대 16단계입니다. 아주 복잡하게 중첩하기보다는 적당한 길이로 나누어 읽기 쉽게 작성하는 편이 좋습니다.

### 17.3 곡 반복 지점 L

```muc
D o4 l8 cdef L gab>c
```

`L`은 해당 채널의 곡 반복 지점을 설정합니다. 단순히 문자열 앞부분을 반복하는 `[ ]`와는 다릅니다. 여러 채널을 반복시킬 때는 각 채널의 프레이즈 길이와 루프 위치를 함께 맞춰야 합니다.

에디터에서 Play의 두 회차 제한과 소스의 `L`은 서로 다른 역할입니다. `L`은 곡 안의 반복 위치이고, `/L2`는 플레이어가 실행할 반복 회차를 정하는 옵션입니다.

### 17.4 매크로

반복해서 사용하는 프레이즈를 이름 대신 번호로 정의할 수 있습니다.

```muc
# *1{o4 l8 cdef}
# *2{gab>c4}
D v10 *1 *2
```

`# *1{...}`은 정의이며, 채널 안의 `*1`이 호출입니다. 정의하지 않은 번호를 부르거나 중괄호를 닫지 않으면 오류입니다.

현재 안전 한도는 매크로 본문 511바이트, 호출 중첩 4단계입니다. 자기 자신을 계속 부르는 형태도 유효한 곡 작성 방법이 아닙니다. 매크로 안에서 오류가 나면 **정의 행이 아니라 호출한 채널 행**이 표시될 수 있다는 점도 기억해 주세요.

### 17.5 포르타멘토

```muc
D o4 l4 {c>c}4 d4
```

중괄호 안의 음 사이를 이동하는 표현입니다. 매크로 정의의 중괄호와 같은 글자를 쓰지만 역할이 다릅니다. 기존 프레이즈를 수정할 때는 중괄호의 위치와 뒤의 길이 지정까지 함께 확인해 주세요.

### 17.6 고급 명령 빠른 안내

아래는 기존 곡을 읽을 때 자주 만나는 명령들입니다. “이 기호가 대략 무엇을 조절하는가”를 찾기 위한 표이며, 모든 채널에서 같은 인수를 받는다는 뜻은 아닙니다.

| 명령 | 용도·주의점 |
|---|---|
| `DN` | 디튠. 음원 종류별 값의 작용이 다름 |
| `KN`, `kN` | 이조 계열. 절대/상대 이조 상태를 설정 |
| `sN` | 셔플·음 길이 교대 조정 |
| `VN` | 전체 음량 오프셋 계열 |
| `M지연,속도,변화량,깊이` | 소프트웨어 LFO의 네 인수 형식. 실제 입력은 숫자와 쉼표로 작성 |
| `MF0`, `MF1` | 소프트웨어 LFO 끄기·켜기 |
| `MW`, `MC`, `ML`, `MD`, `MT` | LFO 부분 설정. 명령별 인수·채널 제한을 확인할 것 |
| `H...` | 하드웨어 LFO. 소프트웨어 LFO와 별개이며 채널 제한이 있음 |
| `y레지스터,값` | 레지스터 직접 지정. 다른 음원 설정을 바꿀 수 있어 주의 |
| `yTL,오퍼레이터,값` 등 | FM 파라미터 이름을 사용하는 직접 제어 계열 |
| C 채널의 `S...` | FM3 슬롯 디튠. SSG의 S와 인수 형식이 다름 |
| `R`, `Rm`, `RF` 계열 | 리버브·잔향 관련 명령. 일반적인 오디오 플러그인 효과와 같지는 않음 |
| `^길이` | 앞 음의 길이 연장 |
| `\|` | 읽기 편하게 넣는 구분 표시. 자동 쉼표나 박자 보정이 아님 |
| `:` | 그 채널의 이후 컴파일을 끝내는 명령 |

예를 들어 소프트웨어 LFO의 숫자 형식은 다음처럼 사용합니다.

```muc
D o4 l4 v10 M8,2,1,4 cdef MF0 gab>c
```

명령마다 유효 범위가 다른데, 숫자가 들어간다는 이유만으로 어떤 값이든 안전하게 사용할 수 있는 것은 아닙니다. 고급 명령은 정상 예제에서 작은 폭으로 바꾸고, 오류·경고와 실제 소리를 함께 확인해 주세요.

## 18. 직접 입력해 보는 완성 예제

### 18.1 SSG로 시작하는 첫 곡

다음 내용을 새 문서에 입력하고 `FIRST.MUC`라는 이름을 사용해 보세요.

```muc
#mucom88 1.7
#title First Steps
#composer ToughkidCST
#author ToughkidCST
#comment Simple SSG test

D T120 C128 o4 l8 v10 q0 cdef gab>c4 r4
E C128 o3 l4 v8 c r g r c r g r
F C128 o2 l2 v7 c g c g
```

1. Ctrl+S로 `FIRST.MUC`를 저장합니다.
2. F1→2로 컴파일합니다.
3. 메시지를 확인하고 돌아와 F1→3으로 들어봅니다.
4. D 채널의 `v10`을 `v6`으로 바꿉니다.
5. **저장하지 말고** F1→2, F1→3을 해봅니다.
6. 마음에 들지 않으면 Undo로 되돌리고 다시 컴파일합니다.
7. 최종적으로 남길 상태에서 Ctrl+S를 누릅니다.

이 예제는 PCM이나 외부 FM 음색을 사용하지 않도록 SSG만으로 구성했습니다. 다만 에디터에서 실제 연주하려면 앞에서 설명한 MUCPLAY의 지원 음원 환경은 필요합니다.

### 18.2 반복과 매크로를 함께 사용하기

```muc
#mucom88 1.7
#title Phrase Practice
#comment Macro and repeat test

# *1{o4 l8 cdef}
# *2{g4 e4 c4 r4}
D t200 C128 v10 [*1]2 *2
E C128 o3 l4 v8 [c r g r]2
```

`*1`을 바꾸면 그 매크로를 호출한 위치에 변경이 적용됩니다. 여러 곳에 복사해 둔 같은 프레이즈를 따로 고치는 것보다 관리하기 편합니다.

### 18.3 간단한 인라인 FM 음색

아래는 음색 정의의 배치를 보여주는 예입니다. 처음 들을 때는 음량을 낮춰 놓고 확인해 주세요.

```muc
#mucom88 1.7
#title Inline FM Test
#comment Four-operator voice example

  @1
   0,7
   31,8,4,6,8,36,0,1,0
   31,8,4,6,8,36,0,1,0
   31,8,4,6,8,36,0,1,0
   31,8,4,6,8,36,0,1,0

A t200 C128 @1 o4 l8 v8 p3 q2 cdef gab>c4
```

이 예제를 바탕으로 음색 값을 바꿀 때는 원본을 남기고 한 값씩 바꿔 보세요. 문법이 맞는 음색이라고 해서 반드시 듣기 좋은 음색인 것은 아닙니다.

<a id="19"></a>
## 19. 컴파일 오류 읽는 법

현재 컴파일러는 가능한 경우 **행 번호, 채널, 오류 코드, 이유와 원문 일부**를 표시합니다.

```text
Error line 2, channel A (code 6): Note length out of range
> A l0 c
```

읽는 순서는 다음과 같습니다.

1. `line 2`: 두 번째 행을 확인합니다. 빈 행과 주석도 행 수에 포함됩니다.
2. `channel A`: A 채널을 처리하다 발생한 오류입니다.
3. `code 6`: 음 길이 관련 오류입니다.
4. `> A l0 c`: 실제 문제가 있는 행의 일부입니다. 여기서는 `l0`을 고쳐야 합니다.

원문 발췌는 최대 72바이트이므로 긴 행의 끝부분이 모두 나오지는 않습니다. 매크로 내부에서 발생한 오류는 호출 행을 가리킬 수 있습니다. 소스 위치를 알 수 없는 파일 입출력 등의 오류에는 임의의 행 번호가 붙지 않을 수 있습니다.

에디터에 자동으로 해당 오류 위치로 이동시키는 기능은 없습니다. 메시지의 행 내용이나 명령을 기억해 두었다가 Ctrl+F로 찾는 방법이 편합니다. **먼저 발생한 오류부터 하나씩 고쳐서 다시 컴파일**해 주세요. 한 번의 실패 화면에 모든 문제가 나열된다고 기대하지 않는 것이 좋습니다.

<a id="20"></a>
## 20. 컴파일 오류 코드와 발생 조건

다음은 현재 진단 코드의 설명입니다. 같은 코드라도 문맥에 따라 여러 원인이 있을 수 있습니다.

| 코드 | 표시되는 이유 | 대표적인 발생 조건·확인할 부분 |
|---:|---|---|
| 0 | Syntax error / missing number | 필요한 숫자가 없음. 예: `A l` |
| 1 | Invalid parameter | 인수 형식 또는 숫자 범위가 부적절함. 예: `A q100000 c` |
| 2 | Repeat end without matching start | `[` 없이 `]2` 사용 |
| 3 | Unclosed repeat/loop | `[`를 열고 닫지 않음 |
| 4 | Too many voices (maximum 32) | 한 곡에서 사용하는 FM 음색 종류가 32개를 넘음 |
| 5 | Octave out of range (o1..o8) | `o0`, `o9`처럼 명시적 옥타브 범위를 벗어남 |
| 6 | Note length out of range | `l0` 등 유효한 길이를 만들 수 없음. C128 상태의 `l129`도 확인 대상 |
| 7 | Invalid loop escape | 반복 밖의 `/`, 같은 반복 안의 중복 탈출 등 |
| 8 | Missing parameter or separator | 여러 인수가 필요한 명령의 숫자·쉼표가 빠짐. 예: `A M1` |
| 9 | Command not valid for this channel | 채널에 맞지 않는 명령. 예: FM A 채널에 SSG용 `P1` 사용 |
| 10 | Too many nested repeats | 반복 중첩 한도 16단계를 초과 |
| 11 | Voice name not found or invalid | 이름으로 지정한 음색을 찾지 못하거나 이름 지정이 잘못됨 |
| 12–14 | Unspecified compiler error | 예약·일반 오류 영역. 해당 번호만으로 원인을 단정하지 말 것 |
| 15 | Macro not found | 정의되지 않은 `*번호` 호출 |
| 16 | Invalid macro definition | 닫히지 않은 정의, 과도한 중첩·재귀 호출 등 매크로 구조 문제 |
| 17 | MML line or macro too long | MML 본문 한 행 1,023바이트 또는 매크로 본문 511바이트 한도 초과 |
| 18 | Output buffer overflow | 컴파일된 곡 데이터가 출력 버퍼 32 KiB 한도를 초과 |

이 표가 모든 잘못된 숫자와 모든 MML 조합을 완전히 검사한다는 보장은 아닙니다. 문법 검사, 파일 검사, 실제 음원에서의 의미는 서로 다릅니다. 오류 없이 컴파일되더라도 의도한 소리가 맞는지는 들어보셔야 합니다.

### 직접 확인해 볼 수 있는 오류 예

아래는 **일부러 오류가 나도록 만든 입력**입니다. 실제 곡에 그대로 붙여 넣는 예제가 아닙니다.

```text
A o9 c          → 코드 5: 옥타브 범위 초과
A l0 c          → 코드 6: 0 길이
A ]2            → 코드 2: 여는 반복 없음
A [cdef         → 코드 3: 닫히지 않은 반복
A /c            → 코드 7: 반복 밖의 탈출
A M1            → 코드 8: 필요한 인수 부족
A P1 c          → 코드 9: 채널에 맞지 않는 명령
A *99 c         → 코드 15: 99번 매크로를 정의하지 않은 경우
```

### 크기 오류는 어떻게 줄이나요?

- 긴 한 행은 여러 행으로 나눕니다. 나눈 모든 연주 행 앞에 채널을 붙입니다.
- 긴 매크로는 짧은 여러 정의로 나눕니다.
- 출력 용량 초과는 소스 파일 크기와 다릅니다. 반복되는 음표를 불필요하게 길게 풀어 쓴 부분이 있는지 살펴보세요.
- 가능하다면 `[ ]` 반복으로 표현합니다. 매크로는 텍스트를 줄이는 수단이지만 전개되므로, 매크로를 썼다고 출력 크기도 반드시 줄어드는 것은 아닙니다.
- PCM 크기는 MUB 전체 크기에 큰 영향을 주지만, 코드 18의 **곡 데이터 32 KiB**와는 다른 제한입니다.

<a id="21"></a>
## 21. 경고 메시지와 잘못된 입력

**Error는 컴파일 실패, Warning은 주의가 필요한 상태**입니다. 경고만으로는 컴파일을 중단하지 않습니다.

과거에는 잘못된 채널 행이나 태그가 조용히 무시되어, “수정했는데 왜 아무 변화가 없지?”라고 느끼기 쉬웠습니다. 현재 MUCPLAY의 컴파일러에는 이런 입력을 알려주는 소스 사전 경고가 추가되어 있습니다. 단, 오래된 MUCPLAY에는 해당 경고가 없을 수 있습니다.

### 21.1 잘못된 채널 접두부

```text
Warning line 2: Invalid channel prefix; use A-K + space/tab
> Ac4
```

`A c4`처럼 채널 뒤에 공백을 넣어야 합니다. 다음도 확인해 주세요.

- 채널 문자 앞에 공백·탭을 넣었는가?
- 채널 문자를 소문자로 적었는가?
- A–K 밖의 문자를 채널로 사용했는가?
- `AB c`, `A,B c`처럼 지원하지 않는 다중 채널 접두부를 썼는가?
- 설명문이나 시험용 문자열을 주석 표시 없이 적었는가?

예를 들어 `J cdef` 앞에 문자를 붙여 `TESTJ cdef`로 바꾸면 그 행이 정상 J 채널로 연주되는 것이 아닙니다. **경고를 내고 기존 해석 방식대로 무시할 수 있습니다.** 컴파일 성공 메시지가 나왔다고 그 문자열을 음악으로 해석했다는 뜻은 아닙니다.

### 21.2 알 수 없거나 잘못된 태그

```text
Warning line 1: Unknown or malformed tag
> #tittle Example
```

철자와 `#` 뒤의 공백·콜론을 확인하세요. 사용자 정의 태그도 현재 알려진 태그 목록에 없으면 경고될 수 있습니다. 경고가 났다고 해당 텍스트를 자동 삭제하거나 수정하지는 않습니다.

### 21.3 태그 값 누락

```text
Warning line 1: Missing tag value
> #pcm
```

`#pcm PCM01.BIN`처럼 값을 넣어 주세요. 빈 `#comment`는 정상 주석 용도로 허용합니다.

### 21.4 헤더 밖의 태그

```text
Tag outside initial header is ignored
```

`#voice`, `#pcm` 등을 파일 앞의 헤더로 옮겨 보세요. `#comment`와 매크로 정의는 별도로 취급됩니다. 파일 중간에 태그를 적었다고 그 시점에 PCM 뱅크나 음색 파일이 바뀌는 것은 아닙니다.

### 21.5 PCM 파일 누락

```text
Warning: PCM file not found: MUCOMPCM.BIN
```

플레이어의 읽기 경로에 따라 다음과 같은 문구도 볼 수 있습니다.

```text
WARNING: cannot open #pcm file: MUCOMPCM.BIN
```

확인 순서는 다음과 같습니다.

1. `#pcm` 태그가 정확히 적혀 있는가?
2. 파일 맨 앞의 헤더에 있는가?
3. 지정한 PCM 파일이 현재 작업 환경에서 읽히는가?
4. DOS에서 실제 보이는 8.3 파일명이 태그와 맞는가?
5. 원래 곡에 들어 있던 PCM 뱅크가 맞는가?

호환성을 위해 PCM이 없는 MUB가 생성될 수 있습니다. **MUB written.이라는 메시지만 보고 정상적인 PCM 포함 파일이라고 판단하면 안 됩니다.** PCM이 필요한 곡이라면 누락 경고를 해결한 후 다시 출력해 주세요.

경고는 잘못된 입력의 모든 의미까지 검사하지는 않습니다. 예를 들어 날짜가 실제 달력에 맞는지, PCM 안의 각 샘플이 곡이 기대하는 악기인지는 이 경고만으로 확인되지 않습니다.

## 22. 에디터 메시지와 복구 방법

| 메시지 | 의미와 대처 |
|---|---|
| `mucEdit new requires MSX-DOS2.` | MSX-DOS2 계열 환경인지 확인 |
| `Open failed. Press a key.` | 이름·경로·디스크·파일 접근 가능 여부 확인 |
| `Text exceeds 24 KiB; not loaded.` | 정규화한 문서가 편집 용량 초과. 외부 도구로 나누거나 줄여서 다시 열기 |
| `Need 32 KiB free mapper RAM to load.` | 새 문서 적재에 임시 매퍼 2개가 필요함. 현재 작업을 저장하고 상주 프로그램·세션·RAM 구성 확인 |
| `Save failed. Press a key.` | 디스크 공간, 쓰기 보호, 이름, 장치 오류 확인. 메모리에 남은 문서를 다른 이름·장치로 저장할 방법을 먼저 확보 |
| `Document memory full. Press a key.` | 삽입·붙여넣기 후 문서가 24 KiB를 넘는지 확인 |
| `Selection exceeds 4 KiB clipboard.` | 복사·잘라내기 범위를 더 작게 나누기 |
| `Text not found. Press a key.` | 검색 철자와 대소문자 확인 |
| `Save the document first. Press a key.` | 현재 명령에 필요한 문서 이름이 없는지 확인하고 저장/이름 지정 |
| `Compile this document first: F1 then 2.` | 현재 문서를 컴파일한 뒤 연주·내보내기 |
| `Compiler path: max 24 bytes, no spaces.` | 짧고 공백 없는 파일명·경로 사용 |
| `MUCPLAY.COM not found.` | 현재 작업 디렉터리에서 MUCPLAY를 찾을 수 있는지 확인 |
| `Use the matching /E2 MUCPLAY.COM.` | 새 에디터의 E2 복귀 방식을 지원하는 MUCPLAY 사용 |
| `Cannot create MUCEDIT.RET.` | 상태 보관 파일 작성 실패. 디스크 여유·쓰기 가능 여부 확인 |
| `Cannot create MEDCOMP.MUC (exists or disk error).` | 동명의 임시 파일 충돌 또는 디스크 오류 |

### 22.1 MEDCOMP.MUC가 남아 있다면

임시 파일이라고 무조건 삭제하지 마세요. **저장하지 않은 최신 편집 내용이 들어 있을 수 있습니다.**

1. 현재 에디터와 플레이어의 작업이 진행 중인지 먼저 확인합니다.
2. 가능한 경우 에디터의 현재 문서를 별도 이름으로 저장합니다.
3. 남아 있는 `MEDCOMP.MUC`와 `MUCEDIT.RET`를 다른 곳에 복사해 보존합니다.
4. 원본 MUC와 비교하고, 필요한 수정이 임시 파일에만 남아 있지 않은지 확인합니다.
5. 진행 중인 연동·복구가 없고 백업을 확보한 뒤에만 충돌 파일을 다른 이름으로 옮기는 등의 정리를 합니다.

`MEDCOMP.MUC`는 텍스트 입력이지만 `MUCEDIT.RET`는 내부 상태 파일입니다. 둘을 같은 방식으로 편집하거나 파일 확장자만 바꾸어 소스로 사용하면 안 됩니다.

### 22.2 에디터 복귀 실패

```text
Resume failed. R: Retry  Esc: Empty editor (MUCEDIT.RET kept).
```

- `R`: 남아 있는 상태 파일로 복귀를 다시 시도합니다.
- `Esc`: 상태 파일을 지우지 않고 빈 에디터로 들어갑니다.

이때 새 파일을 만들거나 COM을 교체하기 전에 상태 파일을 먼저 보존해 주세요. `MUCEDIT.RET`는 에디터의 버전과 메모리 구조에 연결되어 있습니다. 서로 다른 빌드 사이에서 자유롭게 옮겨 쓰는 일반 복구 파일이 아닙니다.

일반 실행은 오래된 RET가 있다고 그것을 자동 복구하지 않습니다. `/R`은 플레이어가 정상 복귀에 사용하는 내부 절차이며, 임의의 RET를 가져오는 사용자용 복구 명령으로 사용하지 않는 것이 좋습니다.

<a id="23"></a>
## 23. 메모리·파일 크기·문자 처리 제한

| 항목 | 현재 기준 |
|---|---|
| 화면 | 80컬럼, 총 24행 중 일반 편집 영역 22행 |
| 편집 문서 | 최대 24 KiB = 24,576바이트 |
| 내부 클립보드 | 최대 4 KiB |
| Undo/Redo 기록 | 총 4 KiB, 변경 전후 내용과 관리 정보 포함 |
| 보조 작업 매퍼 | 16 KiB 한 세그먼트 |
| 파일 열기용 임시 매퍼 | 16 KiB 두 세그먼트 추가 필요 |
| 목록창 | 한 페이지 16개, 전체 목록은 추가 페이지 검색 |
| MML 채널 행 본문 | 최대 1,023바이트 |
| 매크로 본문 | 최대 511바이트 |
| 매크로 호출 중첩 | 최대 4단계 |
| 반복 중첩 | 최대 16단계 |
| 사용 FM 음색 종류 | 최대 32개 |
| 컴파일된 곡 데이터 | 최대 32 KiB. PCM을 포함한 MUB 전체 파일 크기와 다름 |

### 23.1 추가 매퍼가 있다고 문서가 40 KiB가 되지는 않습니다

16 KiB 보조 작업 매퍼는 행 이동·복제와 파일 목록 등의 작업 공간입니다. 문서 24 KiB, 클립보드 4 KiB, Undo 4 KiB 제한을 늘리는 설정은 아닙니다.

파일을 열 때는 현재 문서를 바로 지우지 않고 임시 영역에 새 문서를 읽어 검증합니다. 그 때문에 작업 매퍼 외에 32 KiB의 여유 매퍼가 잠시 더 필요합니다. 읽기·닫기·할당에 실패했을 때 현재 문서를 지키기 위한 구조입니다.

### 23.2 디스크 파일 크기와 편집 크기

24 KiB 제한은 줄바꿈 등을 정리한 **내부 문서 크기** 기준입니다.

- CRLF, CR, LF 줄바꿈을 읽고 내부에서는 LF로 정리합니다.
- 파일 앞의 UTF-8 BOM은 제거합니다.
- DOS의 Ctrl+Z 바이트는 텍스트 끝으로 처리합니다.
- 저장할 때는 내부 LF를 CRLF로 출력합니다.

따라서 디스크의 MUC가 24 KiB를 조금 넘더라도 줄바꿈을 정리한 내용이 한도 안이면 열릴 수 있습니다. 극단적으로 줄바꿈 비중이 큰 CRLF 파일은 약 48 KiB까지도 내부 24 KiB에 들어갈 수 있습니다. 하지만 **일반적인 48 KiB MUC를 편집할 수 있다는 뜻은 아닙니다.**

현재 컴파일러가 별도로 더 큰 소스 창을 지원하더라도 MUCEdit 자체의 편집 한도는 24 KiB입니다.

### 23.3 한글·일본어·UTF-8

MUCEdit은 바이트 기반의 MSX 텍스트 에디터입니다. UTF-8 BOM을 읽을 수 있다는 사실이 한글·일본어 Unicode 편집 전체를 지원한다는 뜻은 아닙니다.

여러 바이트로 이루어진 글자는 화면에 깨져 보이거나, 이동·삭제가 글자 단위가 아니라 바이트 단위로 작용할 수 있습니다. MML 명령·숫자·파일명은 ASCII로 작성해 주세요. 다른 문자 인코딩의 설명문을 손댈 때는 원본을 반드시 보관하고, 필요하면 해당 인코딩을 제대로 지원하는 외부 편집기로 수정하는 것이 안전합니다.

<a id="24"></a>
## 24. 자주 묻는 질문

### 저장하지 않으면 수정한 내용으로 컴파일되지 않나요?

아닙니다. F1→2는 현재 메모리의 편집 내용을 컴파일합니다. 저장은 필요 없습니다. 다만 그 후 F1→3을 눌러야 새 결과를 듣습니다. 컴파일 없이 Play만 누르면 이전 결과를 재생합니다.

### 수정했는데 컴파일 결과 화면이 똑같습니다

성공 화면의 문구가 같다고 곡 데이터도 같다는 뜻은 아닙니다. 템포나 음표가 바뀌어도 일반적인 성공 문구는 동일할 수 있습니다. 실제로 들어보거나 MUB를 다른 이름으로 보관해 비교해 보세요.

또한 주석·제목 같은 정보만 바꾸면 연주 소리는 같을 수 있습니다. 채널 접두부가 깨진 행은 경고 후 무시될 수도 있으니 Warning도 확인하세요.

### 아무 문자열이나 넣었는데 Error가 안 납니다

모든 텍스트가 MML로 해석되는 것은 아닙니다. 설명문, 잘못된 채널 접두부, 알 수 없는 태그는 경고만 내고 넘어갈 수 있습니다. **오류가 없다는 것과 모든 행이 연주에 사용됐다는 것은 다릅니다.**

### PCM 경고가 나오는데 FM은 들립니다

FM 데이터와 PCM 뱅크는 별개입니다. FM이 들린다고 PCM도 정상이라는 뜻은 아닙니다. `#pcm`, 실제 DOS 파일명, 뱅크 파일 위치를 확인해 주세요.

### MUB를 출력했는데 PCM 소리가 빠졌습니다

누락 경고를 무시하고 출력했을 수 있습니다. 현재 정책은 일부 PCM 누락 상황에서 PCM 없는 MUB 생성을 허용합니다. 올바른 뱅크를 준비하고 다시 내보내세요.

### 소리가 전혀 안 납니다

1. F1→2 (/Compile)가 성공했는지 확인합니다.
2. 연주 화면에 지원 음원 장치 관련 오류가 없는지 확인합니다.
3. 에뮬레이터·OS·실기 오디오의 음소거와 출력 연결을 확인합니다.
4. `v0`, `p0`, SSG의 `P0`, 쉼표만 있는 파트 등을 확인합니다.
5. 해당 채널의 행이 경고로 무시되지 않았는지 확인합니다.
6. PCM만 사용하는 곡이라면 뱅크 누락부터 확인합니다.

### 블록이 선택된 채 글자를 입력했더니 내용이 없어졌습니다

선택 영역을 새 입력으로 바꾸는 정상 편집 동작입니다. 선택 위에 입력하려던 것이 아니라면 Ctrl+Z로 되돌리고, 선택을 해제한 뒤 입력하세요. 큰 선택은 Undo 한도를 넘을 수 있으므로 주의가 필요합니다.

### 행을 나눴더니 뒷부분이 연주되지 않습니다

새 행 앞에 채널 문자를 빠뜨리지 않았는지 확인하세요. `D cdef` 뒤의 프레이즈를 다음 행에 `gab>c`라고만 쓰면 같은 D 채널로 자동 연결되지 않습니다. `D gab>c`라고 적어야 합니다.

### 파일 목록 순서가 이상합니다

현재 목록은 이름순 정렬이 아니라 DOS의 디렉터리 검색 순서입니다. 목록에 보이는 순서만으로 파일이 빠졌다고 판단하지 마시고 페이지를 이동하거나 이름을 직접 입력해 주세요.

### 40컬럼 화면으로 사용할 수 있나요?

현재 MUCEdit은 80컬럼 화면을 전제로 합니다. 40컬럼 전환 모드는 제공하지 않습니다.

### 화면이 느려졌습니다

실기·에뮬레이터의 CPU/VDP 설정, 에뮬레이터의 속도 제한과 프레임스킵 등을 구분해 확인하세요. 화면 갱신이 적은 것과 MSX 안의 프로그램 실행 자체가 느린 것은 다를 수 있습니다. 우선 사용자가 의도한 정상 에뮬레이터 설정으로 돌아가 비교하는 편이 좋습니다.

### 검색·일괄 치환·자동 완성은 어디 있나요?

문자열 찾기와 다음 찾기는 지원합니다. 현재 버전에는 정규식·일괄 치환·MML 자동 완성·문법 색상 표시·오류 행 자동 이동 기능이 없습니다. 선택과 검색을 조합해 부분적으로 수정해 주세요.

### MUCPLAY를 바꿀 때마다 MUCEdit도 다시 만들어야 하나요?

E2 연동 규약이 유지된다면 원칙적으로 에디터를 매번 재빌드할 필요는 없습니다. 다만 새 MUCPLAY가 해당 규약을 실제로 지키는지 연동 검증은 필요합니다. 제목의 버전 문자열만 보고 호환성을 판단하지 마세요.

<a id="25"></a>
## 25. 안전한 작업과 업데이트

제가 권하는 작업 습관은 어렵지 않습니다.

1. 받은 원본 곡은 한 벌 따로 보관합니다.
2. 작업할 파일은 다른 이름으로 저장해서 시작합니다.
3. 큰 블록 삭제·음색 전체 변경 전에는 중간 저장본을 남깁니다.
4. 수정한 결과를 들을 때마다 컴파일 성공과 경고를 확인합니다.
5. 완성되면 MUC, 필요한 음색·PCM, MUB/VGM을 구분해 보관합니다.
6. 끝낼 때는 가능한 한 메뉴를 통해 정상 종료합니다.

### 실행 파일 교체

MUCEdit과 MUCPLAY를 사용하는 도중 COM 파일을 덮어쓰지 마세요. 메모리의 코드·세션과 디스크의 새 프로그램이 섞이면 복귀 상태가 맞지 않을 수 있습니다.

권장 순서는 다음과 같습니다.

1. 편집 중인 내용을 저장합니다.
2. MUCEdit을 정상 종료하고 DOS로 돌아갑니다.
3. 별도로 유지 중인 MUCPLAY 세션이 있다면 **교체 전 플레이어**로 `/RELEASE`하여 정리합니다.
4. 기존 COM을 백업합니다.
5. 새 COM을 사용할 디렉터리에 복사합니다.
6. 새로 실행하고 작은 곡으로 컴파일·연주·복귀를 확인합니다.

`MUCPLAY.SES`는 곡 전체를 디스크에 보관하는 프로젝트 파일이 아니라, 메모리에 유지된 세션을 찾는 데 사용하는 정보입니다. 다른 머신이나 리셋 후까지 곡 데이터를 그대로 되살리는 파일로 생각하지 마세요. 세션 파일을 지우는 것과 메모리 반환도 같은 작업이 아닙니다.

### 문제를 알려주실 때

다음 정보를 함께 주시면 원인을 찾기 좋습니다.

- 실기 모델 또는 에뮬레이터와 확장 장치
- 실행한 MUCEDIT.COM과 MUCPLAY.COM의 실제 위치·파일 크기·빌드 정보
- 문제가 생긴 MUC와 필요한 음색·PCM
- “열기 → 컴파일 → 어떤 문자를 수정 → 재컴파일 → 연주” 같은 정확한 순서
- 오류·경고 문구 또는 화면
- 원본과, 남아 있다면 MEDCOMP.MUC의 별도 복사본

복구가 필요한 파일을 먼저 지운 뒤 제보하지 마시고, 가능한 한 현재 상태를 보존해 주세요. 개인적으로 공개하고 싶지 않은 내용이 있다면 복사본에서 제외하고 알려주시면 됩니다.

| 행 복제 | Shift+Graph+↑ / Shift+Graph+↓ |

### 헷갈리기 쉬운 다섯 가지

1. **Ctrl+S는 저장, F1→2는 컴파일입니다.**
2. **F1→3은 자동 저장도 자동 컴파일도 하지 않습니다.**
3. **F1→N은 Save/New, Ctrl+N은 새 문서입니다.**
4. **MML의 t와 T, c와 C는 서로 다른 명령입니다.**
5. **Warning 뒤의 성공 메시지가 경고를 없애 주지는 않습니다.**

## 27. 문서의 적용 범위

이 설명서는 MUCEdit v0.8의 현재 구현과, 2026년 9월 14일 작업 트리의 MUCPLAY·공통 MUC 컴파일러를 기준으로 작성했습니다. 최근 추가된 채널·태그 경고와 컴파일 오류 진단을 포함합니다. 오래된 MUCPLAY, 다른 MUCOM88 파생 드라이버, PC용 MML 프로그램의 동작을 모두 같은 것으로 설명하지는 않습니다.
