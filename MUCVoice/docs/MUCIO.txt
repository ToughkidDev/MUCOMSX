MUCVOICE v0.5beta — MUC FM 음색 / SCC+ 파형 가져오기·내보내기
================================================

1. 빠른 사용

FM 화면에서 R -> SONG.MUC -> Y: 파일에 들어 있는 FM 음색을 병합합니다.
SCC 화면(W)에서 R -> SONG.MUC -> Y: 파일의 @W 파형들을 병합합니다.
B -> VOICES.MUC: 선택한 뱅크의 정의된 슬롯 전체를 MUC로 저장합니다.
X -> TEST.MUC: FM은 현재 음색+시험 멜로디, SCC는 현재 파형 정의만 저장합니다.
GUI에서는 명령 키가 바로 실행되고 파일명과 Y/N은 Enter로 확정합니다.
/TEXT에서는 각 명령 뒤에도 Enter를 누릅니다. 파일명은 현재 경로의 DOS 8.3,
MUC 출력(B/X)은 새 파일만 가능하며 기존 파일을 덮어쓰지 않습니다.
DAT 저장(S)은 기존 파일 교체와 파일명 재사용을 지원합니다.

2. 가져오는 문법 (FM, ID 0..255)

  @N                 여러 줄 일반 정의
  @N:{ ... }         한 줄 또는 여러 줄 중괄호 정의
  @%N                원시 25바이트 정의

일반 정의는 먼저 FB, ALG 두 값, 이어서 OP1, OP2, OP3, OP4 순서로 각 9개:
AR, DR, SR, RR, SL, TL, KS, ML, DT를 받습니다. 예:

  @7:{;GOLDEN
  7,2
  31,8,3,5,2,41,1,1,3
  31,5,4,5,2,39,0,5,2
  31,4,2,5,1,31,0,3,7
  28,30,6,6,0,0,2,1,4
  }

FB/ALG 0..7, AR/DR/SR 0..31, RR/SL 0..15, TL 0..127,
KS 0..3, ML 0..15, DT 0..7입니다. DT는 Yamaha 원시 코드입니다.
일반 정의에는 AM이 없으므로 AM=0입니다. 저장 시 논리 OP2/OP3을 칩의
하드웨어 슬롯 순서로 올바르게 배치합니다.

원시 정의는 DAT 레코드의 1..25번 바이트와 같은 순서로 0..255 값 25개를
받습니다. 예약 비트와 AM을 포함해 그대로 보존합니다. 10진수와 $FF 같은
16진수, CRLF/LF/CR, 공백·탭·쉼표와 ; 주석을 지원합니다.
파일 첫 UTF-8 BOM은 건너뛰고 DOS Ctrl-Z는 EOF로 처리합니다.

행의 첫 유효 문자가 @인 정의를 인식합니다. A @7 같은 악보의 음색 선택,
#voice 외부 라이브러리 지정, @"이름" 프리셋 조회로 실제 외부 음색을 찾아
오는 기능은 아닙니다. 지원하지 않는 @ 정의나 잘린/범위 초과 정의는 오류입니다.
일반 정의의 확장 10번째 인자나 SSG-EG 등은 임의로 버리지 않고 거부합니다.
SSG/리듬/ADPCM 정의 가져오기는 지원하지 않습니다.

SCC+ 문법 (ID 0..255):

  @W7 = {
  -128,-120,-112,-104,-96,-88,-80,-72,
  -64,-56,-48,-40,-32,-24,-16,-8,
  0,8,16,24,32,40,48,56,
  64,72,80,88,96,104,112,120
  }

32개 샘플을 정확히 지정하며 각 값은 -128..127의 부호 있는 10진수입니다.
선택적인 + 부호, 소문자 @w, 공백·탭·쉼표·줄바꿈과 ; 주석을 허용합니다.
=와 중괄호는 필수입니다. 16진수 샘플, 31개/33개 샘플, 범위 초과는 오류입니다.
내보내기는 같은 @W 문법을 사용하며 32바이트를 변형 없이 보존합니다.
SCWD에 파형 이름 필드가 없으므로 주석을 SCC 이름으로 저장하지 않습니다.

이 문법은 기존 PC SCC 도구와 현재 MUCOMSX의 SCC/SCC+ 지원 악보에서 활용하는
파형 교환 문법입니다. 정의만 있는 B/X 출력은 완성된 악보가 아니며, 실제 곡의
채널·음표·음색 선택은 툴체인의 해당 악보 문법에 맞게 별도로 작성해야 합니다.
현재 파형은 K로 직접 시험하거나 V의 공통 SCC CH1 시험 VGM으로 확인하세요.

3. 번호·이름·안전성

원래 MUC의 번호를 그대로 사용합니다. 현재 선택 슬롯 한 개에 몰아넣거나
사용 중인 번호를 다른 번호로 바꾸지 않습니다. 같은 종류 안의 중복 번호는
실수로 덮어쓰는 일을 막기 위해 거부합니다. 현재 뱅크와 번호가 겹치는 것은
확인창의 Y를 누를 때 교체하고, 파일에 없는 슬롯은 그대로 둡니다.
FM과 SCC가 섞인 파일은 두 종류 모두 검증하되 선택한 뱅크만 병합합니다.
FM @7과 SCC @W7처럼 서로 다른 종류의 같은 번호는 함께 사용할 수 있습니다.
선택한 종류의 정의가 없으면 알림만 표시하고 뱅크를 변경하지 않습니다.

파일을 별도 뱅크에 파싱하고 모든 검증과 닫기가 성공한 후에만 확인창을
엽니다. 취소, 잘못된 정의, 읽기/닫기 실패 시 현재 뱅크·Undo를 보존합니다.
성공하면 선택한 종류의 첫 정의를 선택하고 해당 뱅크를 미저장 상태로 표시합니다.
기존 선택 번호를 유지하는 기능은 아닙니다. 특히 0번 무음 파형을 포함하는 SCC
뱅크를 다시 가져온 뒤에는 I로 들어볼 파형 번호를 다시 선택하세요.
일괄 병합은 기존 1슬롯 Undo로 되돌릴 수 없어 같은 뱅크의 Undo를 초기화합니다.
다른 뱅크 소유 Undo는 유지합니다.
필요하면 병합 전에 S로 현재 DAT를 보관하세요.

FM은 첫 파라미터 앞의 ; 주석에서 처음 6바이트를 음색 이름으로 가져오며 나머지는
주석으로 무시합니다. 이름이 없으면 공백입니다. 원시 CP932 이름 바이트는
보관하지만 GUI에서는 ASCII 밖의 이름을 점으로 표시합니다.
내보낼 때 이름 6바이트를 ; 뒤에 기록하며 줄바꿈/제어문자는 공백으로 바꿉니다.
DAT 전용 첫 바이트(레코드 헤더)는 MUC 문법에 없으므로 내보내지 않습니다.

4. 정의된 슬롯이란?

처음 실행 시 FM은 1번 INIT, SCC는 0번 무음 파형이 정의되어 있습니다. FM 값/이름 편집, 복사, TFI
가져오기, MUC 가져오기를 통해 정의 상태가 켜집니다. 일반 1슬롯 Undo는
이 상태도 복원합니다. B는 정의 상태가 켜진 슬롯만 번호 순서대로 출력합니다.

기존 8,192바이트 FM DAT에는 '빈 슬롯' 정보가 없습니다. 따라서 DAT를 읽으면
256개 모두 정의된 것으로 취급합니다. DAT 내용을 보고 조용한 음색을 마음대로
삭제하거나 빈 슬롯으로 추측하지 않습니다. 정의 상태 자체를 DAT에 저장하는
독자 확장은 하지 않았습니다. MUC의 @ 정의 목록이 희소 슬롯 목록 역할을 합니다.
반면 SCC SCWD DAT에는 파형 ID 목록이 있으므로 정의된 슬롯 목록도 복원됩니다.
0.10의 FM D -> Y는 선택 슬롯의 정의 상태를 끕니다. U로 되돌릴 수 있으며,
그 슬롯은 G의 새 VGM 음색 배정에 사용할 수 있습니다. DAT 원시 레코드는
지우지 않으므로 정의된 슬롯 목록을 보존하려면 B의 MUC를 함께 보관하세요.
SCC 편집/프리셋/복사/가져오기는 슬롯을 정의하며 D는 해당 정의를 삭제합니다.

B 출력은 FM @%N 또는 SCC @W 정의만 포함하며 연주 파트는 없습니다.
FM은 실제 악보에 삽입하거나 X의 시험곡 출력을 사용하세요. SCC X도 파형
정의만 출력하며 미정의 슬롯은 거부합니다. B/X 출력은
DAT 저장이 아니므로 미저장 표시와 Undo를 지우지 않습니다.

5. 사용 제한

음색 가져오기는 MUCPLAY/MUC2MUB의 입력 제한이나 MUCEDIT의 편집 한계를 변경하지 않습니다.
