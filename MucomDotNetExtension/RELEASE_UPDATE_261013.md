# MUCOMSX 업데이트 안내

[English](RELEASE_UPDATE_261013.en.md) · [日本語](RELEASE_UPDATE_261013.ja.md)

v0.81-beta 이후 추가된 기능과 수정 사항, 기존 파일과의 호환성, 안전한 업데이트 방법을 안내합니다.

## 공개 버전과 무엇이 달라졌나

| 항목 | v0.81-beta | 현재 버전 |
| --- | --- | --- |
| 60,000바이트 편집 / 64KiB 입력 / 120KiB 음악 DATA | 포함 | 유지 |
| 단일 YM2608 mucomDotNET 확장·다중 페이지·FM3 | 포함 | 유지 |
| MSX-MUSIC / 내부 PSG / msPb0100 | 포함 | 문서의 오래된 별도 빌드 설명 교정 |
| 연주 CPU 자동 가속·`/N` | 포함 | 문서 교정. 컴파일 자동 가속 기능은 아님 |
| SCC/SCC+ 기반 SSG 확장·msPb0101 | 이후 개발에서 추가 | 포함 |

### SSG 확장을 실제 MSX에서 사용하기

`#SSGExtend On`은 접두어 없는 D/E/F의 음색 경로를 SCC/SCC+의 1–3번 채널로 근사합니다. `@I0..9`, `@W0..255`, `peL,R`을 지원하며, 64개 부호 있는 샘플은 32개로 변환됩니다. 스테레오 지정은 모노 이득으로 근사합니다. 노이즈·실칩 엔벌로프 경로는 MAKOTO를 사용하며 `MSXD/E/F`는 내부 PSG입니다.

SCC+를 우선 탐색하고 일반 SCC로 대체합니다. 등록 RAM 매퍼를 제외하고 슬롯·확장 슬롯과 파형 RAM을 원복 가능한 방법으로 검사합니다. 기존 매퍼 뱅크 안에서 처리하며 최소 512KiB 조건을 높이지 않습니다. 일반 SCC의 4/5채널 공유 제약을 넘어 5개의 독립 SCC+ 파형을 보장하는 기능은 아닙니다. 같은 카트리지를 쓰는 네이티브 SCC 경로와 SSG 확장의 충돌은 거부합니다.

SSG 확장 MUB는 `msPb0101`입니다. 기능 바이트 26은 SSG 확장 `2`, 네이티브 혼합 `3`이며 예약 바이트 27–33은 0입니다. 기존 MUB8·muPb·msPb0100을 그대로 구분하고 알 수 없는 구조는 거부합니다. VGM은 공통 SCC 클록/포트로 기록하여 일반 SCC에서도 재생할 수 있게 합니다. 자세한 문법과 한계는 [SSG 확장 안내](SSG_EXTEND.md)를 읽어 주세요. 일반 MUB 플레이어가 MUCOMSX 전용 msPb를 지원한다고 가정하면 안 됩니다.

### PCMInvert는 PCM을 뒤집는 기능이 아닙니다

`#PCMInvert On/Off`는 K(ADPCM)의 상대 옥타브 `>`/`<` 방향을 컴파일 단계에서 바꿉니다. PCM 파일 바이트를 변환하거나 재생 중 데이터를 뒤집지 않으므로 그에 따른 실시간 부담이 추가되지 않습니다. `#pcm` 파일명 태그와 혼동하던 경계 검사도 수정했습니다. WAV에서 PCM 뱅크를 만드는 `#@pcm`은 여전히 미지원입니다.

### 리듬 뮤트와 세션 연주의 정확성

`#OPNA1RhythmMute`가 네이티브 MSX 타깃 비트까지 설정해 정상 OPNA 음악 스트림이 비는 컴파일러 결함을 수정했습니다. MUCPLAY 세션 및 MUCEDIT 연계에서 헤더의 리듬 마스크를 복원하지 않던 부분도 수정했습니다. 이 태그로 잘못 만들어진 예전 MUB는 원본 MUC를 다시 컴파일해야 합니다. 플레이어 교체만으로 빠진 음악 DATA가 복구되지는 않습니다.

이 마스크는 음악 명령에서 생성하는 리듬 키온을 제한합니다. 사용자가 직접 쓰는 `y16`은 원시 레지스터 쓰기이므로 마스크를 우회하며, 키오프는 막지 않습니다. 이는 MDPlayer 비교에서도 유지한 의도된 규칙입니다. 리듬 자동 팬 `pm1 p4..p6`의 대기값은 각 대상 드럼 명령마다 기록하고 생략 시 현재 음표 길이를 씁니다. 명시 대기값은 1–255입니다.

### 컴파일 시간과 메모리

빈 페이지의 반복 검색을 생략하고 활성 행 범위를 줄였습니다. 매크로 정의 색인·복사/충돌 처리와 청크 저장을 개선했습니다. 없는 페이지의 엔트리, 매크로의 첫 정의 우선 규칙, 음악 DATA와 파일 저장 결과는 보존합니다. 전곡·전 문법에서 일정한 배속을 보장하는 기능은 아닙니다.

## 용량과 남아 있는 한계

| 구분 | 이번 빌드의 한계 |
| --- | --- |
| MUC2MUB·MUCPLAY 원본 입력 | 65,536바이트 |
| MUCEDIT 편집 문서 | 줄바꿈 정규화 후 60,000바이트 |
| 컴파일 음악 DATA 합계 | 122,880바이트. 구조·음색 테이블 포함 |
| 단일 OPNA 페이지 스트림 | 59,546바이트 |
| 네이티브 MSX 페이지 스트림 | 59,106바이트 |
| 최소 RAM 매퍼 | 512KiB. 모든 최대 크기의 동시 세션 보장은 아님 |

120KiB는 MUB 전체 파일 크기 상한이 아닙니다. 헤더·태그·ADPCM은 별도입니다. PCM은 음악/음색 DATA 뒤에 디스크 출력 시 붙이며 재생에는 해당 PCM과 칩 용량 제한도 적용됩니다. RAM을 더 꽂아도 위 음악 DATA 한계가 자동으로 늘지는 않습니다.

파트별 분기의 중첩, 추가 OPNA/OPNB/OPM 칩, `@M`, `PCn`, IDE용 메모, `#@pcm`의 WAV 변환은 미지원입니다. YM2413·내부 PSG·SCC의 음색은 YM2608 또는 PC 가상 SSG의 완전 음향 복제가 아닙니다. 고부하 악보가 정상 Z80에서 매 틱을 제시간에 처리한다는 보장도 없습니다. 가속은 연주 중에만 사용하고 종료 시 원래 CPU 모드로 돌립니다. `/N`은 자동 선택을 끕니다.

## MUCVOICE: MSX에서 음색을 편집하고 들어보기

MUCVOICE v0.5beta는 기존 네 도구와 같은 툴체인 ZIP에 포함되어 있습니다. 다섯 COM과 기본 합성 음색 데이터를 같은 작업 폴더에 복사하고, `MUCVOICE/START.MD`에서 음색 에디터 안내를 읽으세요. 전체 한국어·영어·일본어 설명서는 별도 문서 ZIP에 있습니다. MSX-DOS2/Nextor·Screen 2에서 YM2608 FM과 SCC/SCC+ 음색을 편집하고 DAT/TFI/MUC/VGM을 가져오거나 내보냅니다. PCM 뱅크 제작 도구는 아닙니다.

- 12개 FM과 32개 SCC 기본 프리셋, 파형 타일 선택, 파일 브라우저의 음색 미리 보기.
- Space 미리 듣기, `C D E F G A B` 음표 미리 듣기, Shift로 위 옥타브. 일반 건반 모드는 `K`.
- 숫자 위치에서 바로 입력, Tab 확정/다음 항목, Esc 취소. 화살표 연속 조정은 부드러운 가속, Shift는 1단위 미세 조정.
- FM/SCC 각각의 미저장 상태와 Undo 보존, 파일명 재사용, 오류 메시지 구분, 파일/프리셋 이동과 종료 시 발음 정리.
- FM의 그래픽 미리 보기는 엔벌로프/파라미터 설명이지 실제 합성 오디오 파형이 아닙니다.

동봉 프리셋은 직접 합성한 데이터입니다. 다른 곳에서 가져온 음색은 해당 이용 조건을 확인하세요. 조작과 파일 형식은 `QUICK.TXT`, `KEYBOARD.txt`, `MUCIO.txt`, `VGMIO.txt`, `TFI.txt`를 보세요.

## 교체 순서

1. 원본 곡·음색·PCM을 백업하고 MUCEDIT를 정상 종료합니다. 남은 세션은 **교체 전** MUCPLAY의 `/RELEASE`로 정리합니다.
2. 다섯 COM을 같은 릴리즈의 세트로 교체합니다. 다른 폴더/PATH의 예전 COM도 확인합니다. 편집한 DAT는 기본 프리셋으로 덮어쓰지 마세요. msPb 재생에는 이를 지원하는 MDPlayer 빌드를 사용합니다.
3. DOS 8.3 파일명·현재 폴더·`#voice`/`#pcm`을 확인하고 다시 컴파일합니다. `.MD5`는 필요하지 않습니다. 남아 있는 옛 32문자 메타데이터 읽기는 계산/검증을 하지 않으므로 무결성 증거로 쓰지 않습니다.
4. 저장된 같은 MUC와 같은 자원으로 MUC2MUB, MUCPLAY, MUCEDIT의 MUB 전체 바이트를 비교합니다. 편집기 미저장 내용·줄바꿈·태그 차이를 음악 DATA 결함과 구분합니다.
5. 연주·반복·종료 무음과 MUB/VGM 출력까지 확인합니다. 동봉 SHA-256은 파일 동일성을 확인하며 음악의 정답을 증명하지 않습니다.

릴리즈 ZIP마다 `manifest.json`, 내부 `SHA256SUMS.txt`, 외부 `.zip.sha256`을 제공합니다. ZIP 자체와 압축을 푼 파일의 체크섬을 확인하세요. 구성요소의 출처와 라이선스는 `NOTICE.txt`와 `LICENSES/`에 있습니다.
