# SCC制御・効果テーブル・実行時フレーズ


## 圧縮行の共通 MML 文法

`?XU` を指定した MSX 圧縮行でも `|`、`[ ... ]n`、`L` を使用できます。
`|` は区切りで、データを増やしません。繰り返しは二重までで、同じチャンネルの
次の行に続けられます。定義の閉じ括弧 `}` をまたぐ繰り返しは禁止です。
`L` はチャンネルのループ開始位置で、後の `!` から戻ります。
圧縮行の `/` による脱出は未対応です。`[A / B]n` は `[A B]n-1 A` とし、
`n-1` には計算済みの整数を書いてください。

```text
MSXA ?XU1 ?XT1 ?IR3 v12 o4 [c%2 [d%2]2]3 e%2 !
MSXD ?XU1 ?XT1 ?EP0,$81,$38 v12 o4 c%4 !
```

圧縮 OPLL メロディでも `?IR1`–`?IR15`、`?IU0`–`?IU15` を使用できます。
ユーザー音色は先に `?IU番号={8バイト}` で定義します。PSG 専用の圧縮曲では
`?WD` は不要です。SCC の波形は圧縮演奏行より前に定義してください。
OPLL メロディと MSXG で `?FB0 ... ?FBn` が動作します。`?XT4` の休符は
効果を開始せずに待ち、MSXG `?XT64` の休符もドラムを鳴らしません。
`?ID` は保留中の `?IT`、音量、`?IB` を反映します。`?WM` の読み出し間隔が
共有波形領域の末尾を超えると、先頭の波形から循環します。
既存の別名と OPNA 文法は維持し、混合曲でも `#CarrierCorrection` と
`#OPNA1RhythmMute` を保持します。

## 機能名によるMSX命令

推奨名は大文字2文字です。例：`?EP2,41,112`、`?DW-3`、
`?WD0={...}`、`?WS1,0`、`?FC1`。旧1文字の?／@別名は出力を
維持します。`@EP`という別名はありません。数字の@番号、FM定義、
OPNAと仮想SSGの@I/@Wは変更しません。WDはsigned8を32個定義し、
グローバル定義だけで新経路には移りません。ただし`#sccvoice`バンクを取り込むグローバル`?WS`行は、SCC行に?／@文字コマンドがなくてもMSX文法を選びます（2026-10-30）。`?XT1 ?WP2`は旧
`?k1,2`と同じオブジェクトです。compactの?XUはマクロ外の
チャンネルに直接書きます。KT/IM表、XH/XC/XR制御、VF全体フェードはPN6の新機能です。
全命令は文書ZIPの`docs/MSX_MML_JA.TXT`を参照してください。
以下の番号型yは別の従来プロトコルとして維持します。

```text
SCCA @0 ?EP2,41,112 ?DW-3 o4 l8 cdef !
```

既存のSCCA–SCCEの音符、v/E/M/D/P/@は維持します。SCCのvは現在のEレベルを直ちに出力し、Eの追加進行や周波数書込みは行いません。非所有ページの終了による消音を修正しました。同音タイは MUSICLALF・mucomDotNET と同じく、タイ音符を読むティックではEを進めず音量も書かず、次のティックから進めます。そのためタイ内のv変更は1ティック後に反映され、1クロックのv段階は出力されません（2026-10-30、MDPlayer4Macと一致）。この二点はOPNA SSGにも適用します。

既存構文 `y0,0,制御番号,値` を使います。SCCでは4バイトの `FF EC 番号 値` に変換します。raw SCCストリームとは別の意味付き制御で、他のパートのyは変えません。

| 番号 | 機能 | 値 |

| 224 | 絶対音量 | 0–15、255で現在のEに復帰 |
| 225 | 直接周期の下位バイト準備 | 0–255 |
| 226 | 上位バイト確定・周期出力 | 0–15、255で音符周期に復帰 |
| 227 | SCC周期単位オフセット | 符号付きバイト、-3は253 |
| 228 | チャンネルのハードウェアゲート | 0/1、効果位相を維持 |
| 229 | 波形転送方針 | 0通常、1対象消音、2全体消音。128を加えると同一波形も強制転送 |
| 230 | 定義する表を初期化・選択 | 0–7 |
| 231 | 段階を追加 | 1–255音楽ティック |
| 232 | 最後の段階の音量 | 0–15、255維持 |
| 233 | 最後の段階の周期オフセット | 符号付きバイト、128維持 |
| 234 | 最後の段階のゲート | 0/1、255維持 |

周期は9–4095に制限し、同じ値の明示的な周期出力も省略しません。転送前のゲートマスクを復元します。通常SCCの4/5番共有波形では対象消音時に両方を閉じます。

共有表は8個、各16段階までです。初期段階値は音量・周期・ゲート・波形維持です。周期オフセットは累積値ではありません。リリース位置の直前でサステイン反復し、キーオフ後はリリース末尾のみ進みます。末尾では最後の値を保持します。同音タイは再開始しません。ゲートを閉じても効果と内部Eは進みます。非所有ページは既存SSGの所有権方針に従い停止します。時間単位はVBlankでなくテンポに従う音楽ティックです。

フレーズはSCCページ間で本文を共有し、ページごとの4段返却スタックで32ビット位置と境界を保存します。マッパー境界にも対応します。登録前の呼出し、深さ超過、不正な表はエラー停止します。再帰は使用しないでください。呼出しは呼出し元の状態で実行し、復帰時に音量や波形を自動復元しません。従来の#*マクロは引き続きコンパイル時展開です。

従来のmsPb0102機能値5は読み込めます。新制御を使うファイルのみ機能値13となり、旧DOSプレイヤーは拒否します。新制御のない既存楽譜のMUB/DATAは維持します。一致したMUC2MUB/MUCPLAY/MUBPLAYを使用してください。MUCEDITでは既存y構文で編集します。外部PCエンジンの対応は仮定しません。

通常Z80・512KiBマッパー・D600作業領域を維持し、追加マッパーバンクは使用しません。連続書込みでスロット切替を共有します。Konamiドライバーで観測した制御単位を提供するもので、原曲PCM位相の一致や毎ティック波形転送の無負荷化を保証するものではありません。
