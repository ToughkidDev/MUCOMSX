# MSX-MUSIC・内蔵PSGへの互換出力

MUC2MUB・MUCPLAY・MUBPLAYは、それぞれのCOMと同じビルドの`.MXR`を現在のDOSフォルダーまたは`PATH`へ一緒に配置します。モジュールは起動時に読み込み、演奏ティック中には読みません。音楽DATA上限は96KiB（98,304バイト）です。

MSX PSG/SCC+の音符・共有フレーズ・波形変調・スイープ・エンベロープは[MSX制御ガイド](SCC_CONTROL.ja.md)および文書ZIPの`docs/MSX_MML_JA.TXT`をご覧ください。全体モードなしでOPNAと併用できます。

2026-10-03実装。YM2608向けMUCの音符・命令を再利用し、YM2413とMSX内蔵PSGで
似た編曲を演奏します。異なるチップ間の波形一致を目的とする機能ではありません。

| パート | 出力 |
| --- | --- |
| MSXA/B/C/H/I/J | YM2413 FM 1～6 |
| MSXG | OPLL BD・SD・CYM・HH・TOM |
| MSXD/E/F | 内蔵PSG 1～3 |
| 接頭辞なし A～K | 従来のMAKOTO/OPNA、変更なし |

`D0`は従来のOPNA SSGです。`MSXD0`が内蔵PSGです。数字省略はページ0。
ページ0～9を使えますが、物理チャンネルを共有するため同時発音数は増えません。
`MSXABC`・`MSXDE`・`MSXA09`も使用可能です。接頭辞は行の選択子全体に適用されます。
OPNAとMSXは別の行に書いてください。`MSXK`とネイティブFM3特殊命令はエラーです。

```text
MSXD @0 v12 t180 o5 l8 cdefgab>c
MSXE @0 v10 o4 l4 c g e g
MSXG v63,31,31,31,31,31,31 @31 l8 c r c r
```

音符、長さ、タイ、反復、マクロ、ソフトウェアLFO、ポルタメントは既存処理を再利用。
PSG周期をクロック変換し、レジスタ7のI/O設定を保存、14/15への音楽書き込みを遮断します。
PSGは音量だけでなく有効なソフトウェアエンベロープも指定してください。

FM音色は2オペレータ向け特徴に縮約し、15個のROMプリセットとのパラメータ距離で
選択します。スペクトル最適化や聴感上の最適一致ではありません。
共有ユーザー音色の上書きは行いません。RIMは省略、左右パンはモノ化し、ミュートは保持。
非対応レジスタ、ハードウェアLFO、SSG-EG、音程範囲超過等は変換警告の対象です。
`y`はOPNAレジスタの意味であり、OPLLレジスタへの直接アクセスではありません。

4ツールの通常操作で使用でき、追加CLI指定は不要です。現在の再生にはMAKOTOと
MSX-MUSICが必要です（PSGだけのMSXパートでも同じ）。対応Panasonicは高速Z80、
turbo RはR800を使用し、終了時に元へ戻します。`/N`は呼び出し時のCPUを維持します。
コンパイルは自動CPU切替の対象外です。
ただしOne Chip MSX（OCM）では4ツールとも`/N`の有無にかかわらず、カートリッジスロットの
クロックを3.58MHzに合わせてからCPUを8.06MHzに上げ（MUC2MUBはコンパイル中、
MUCEDITはエディター実行中）、終了・エラー・中断時に元の速度とスロットクロックへ戻します。

MSXパート使用曲はMUCOMSX専用`msPb0100`、拡張子は`.MUB`です。
通常のMUB8/muPbの意味は変わりません。他のMUBプレイヤーでの互換性を仮定しないでください。
ツールチェーンのVGM出力は2026-10-30に削除しました。VGMが必要ならMUCPlaygroundの保存（.vgm）を使ってください。

入力MUCは65,536バイト、編集文書は正規化後60,000バイト、音楽DATAは98,304バイトです。
ネイティブページのストリーム上限は59,106バイトでヘッダー・タグ・PCMは別です。
最低マッパーは512KiB。ドライバは1バンク、ネイティブページ状態は最大2バンクを追加使用します。
空きメモリはDOS・常駐ソフト・ページ/反復構成に依存します。

格納形式は220ページエントリ、1,986バイトのヘッダ。ネイティブKは終了0バイトのみ、
ループなしで、実行しません。内部DATA F1/F5の接頭部894バイト、音色位置LE32は+886、
全長LE32は+890です。ディスクヘッダのオフセットとは異なります。

比較表はBSD-3-ClauseのymfmにあるDavid Viens・Hubert Lamontagneのプリセットデータです。
NOTICEとYMFM-LICENSEを同梱します。GPL変換コードやNuked-OPLLエミュレータは含みません。

## SCC専用5チャンネル：SCCA–SCCE

`SCCA`〜`SCCE`はSCC/SCC+のチャンネル1〜5です。OPNAの`D/E/F`、内蔵PSGの`MSXD/MSXE/MSXF`は変更しません。`SCCABC`で複数チャンネル、`SCCA9`でページ9を選択できます。ページ0〜9は同じ物理チャンネルを共有します。

```text
#title SCC five voices
#sccvoice SCCVOICE.DAT
SCCA @0 o4 v15 l8 cdefgab>c
SCCB @1 o3 v12 l4 ceg>c
SCCC @2 o3 v12 l4 egb>e
SCCD @3 o2 v10 l4 cgcg
SCCE @4 o5 v10 l8 rcrc rcrc
```

`#sccvoice`は楽譜先頭のヘッダーで指定します。省略時は`SCCVOICE.DAT`です。DOSの作業ディレクトリでMUCと同じ場所に、空白なしの8.3ファイル名で置いてください。FMの`#voice`とは別の**SCWD v1**形式です。[MUCPlayground](https://toughkiddev.github.io/MUCOMSX/MUCPlayground/)のSCCバンクやSCC Wave Toolsで保存したDATを使えます。`@0`〜`@255`は定義済み波形IDを選びます。未定義ID、CRC破損、非対応バージョン、長さ・ID順序の異常はエラーです。波形は符号付き8ビット32サンプルです。

音符・休符・音長・オクターブ・音量・ゲート・タイ・繰返し・マクロ・ソフトウェア音程変化にはSSG系命令を使います。各ページの初期ソフトウェアエンベロープは波形とは別に設定されます。SCCにOPNAのノイズ、ハードウェアエンベロープ、ステレオパンはなく、同じ音響機能を再現するモードではありません。同じSCCを使う`#SSGExtend On`やraw SCCストリームとは併用しないでください。

SCC+は5波形が独立しています。通常SCCも5音程を演奏できますが、**SCCD/SCCEの波形RAMは共有**され、最後に書いた波形が両方に適用されます。異なる5波形の同時演奏にはSCC+が必要です。

MUC2MUBの変換、MUCPLAY/MUCEDITのコンパイル・再生・MUB出力、MUBPLAYの再生に対応します。波形をMUBに含むため再生時のDATは不要です。下記のインライン定義を使えば再コンパイル時もDATは不要です。

SCC専用楽譜は**msPb0102**のMUBを生成します。最新の4つのCOMを一緒に導入してください。旧msPb0100/0101専用プレイヤーや未更新の外部プレイヤーとの互換性は前提にできません。既存楽譜の形式は維持します。

最小512KiBマッパー、MUC入力65,536バイト、MUCEDIT文書60,000バイト、音楽DATA98,304バイトの上限を維持します。SCWD波形キャッシュは必要時に別バンクを確保し、拡張コード用16KiBバンクと分離します。SCCページ状態は既存ネイティブグループに16KiBバンク1個を追加使用します。DOSや常駐ソフトで空き容量は変わるため、不足時は他のセッションを解放してください。


## MUC内でSCC波形を直接定義

OPNA音色定義の中括弧形式に合わせた`@W番号:{ ... }`で、32バイトのSCC波形を定義できます。パート側は`@番号`で選択します。必要なSCC波形をすべて定義すれば、`#sccvoice`や外部DATなしでコンパイル・再生・MUB出力ができます。

```muc
  @W7:{
    -128,-120,-112,-104,-96,-88,-80,-72,
    -64,-56,-48,-40,-32,-24,-16,-8,
    0,8,16,24,32,40,48,56,
    64,72,80,88,96,104,112,120
  }
SCCA @7 o4 v15 l8 cdefgab>c
```

番号は0–255、値は-128–127の10進整数を正確に32個指定します。カンマ・空白・改行で区切り、`;`コメントも使えます。定義行は任意の字下げの後に`@W`で始めます。旧形式`@W番号 = { ... }`と、`@W番号`の次の行から32個を書く形式も対応します。同じSCC番号の重複定義、個数・範囲の誤り、未定義番号の選択はエラーです。FMの`@7`とSCCの`@W7`は独立しています。

外部SCWDと併用すると、同じ番号はインライン定義を優先します。`#sccvoice`で明示したファイルの欠落やDATの破損はエラーです。DATなしで使う場合はそのヘッダーを削除してください。指定がなければ従来どおり既定の`SCCVOICE.DAT`を探しますが、なくてもインライン定義を使えます。

MUCPlaygroundのSCC波形エディター（SCCバンクの**編集**）は、直した波形を`@W番号:{ ... }`の定義としてMUCに挿入します（[MUCPlaygroundユーザーガイド](https://toughkiddev.github.io/MUCOMSX/MUCPlayground/Manual/?lang=ja#banks)、文書ZIPの`shared/docs/MUCPLAYGROUND.ja.md`の5章）。定義のみを挿入するため、上記のようにSCCA–SCCEの演奏行を追加してください。512KiBマッパー条件と既存のMUC/音楽DATA上限は変わりません。`#SSGExtend On`の64サンプル`@W`とは別のSCC専用定義です。両モードは混在できません。
