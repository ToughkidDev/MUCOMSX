# SCC 제어·효과 표·런타임 구절


## 압축 행의 공통 MML 문법

`?XU`가 있는 MSX 압축 행에도 `|`, `[ ... ]n`, `L`을 사용할 수 있습니다.
`|`는 구분선이며 데이터를 추가하지 않습니다. 반복은 최대 두 겹이고 같은 채널의
다음 줄에서 닫을 수 있습니다. 정의의 `}`를 넘는 반복은 허용하지 않습니다.
`L`은 채널 본문의 루프 시작이며 뒤의 `!`가 그 위치로 돌아갑니다.
압축 행의 `/` 반복 탈출은 지원하지 않습니다. `[A / B]n`은
`[A B]n-1 A`로 작성하세요. 여기서 `n-1`은 계산한 정수로 써야 합니다.

```text
MSXA ?XU1 ?XT1 ?IR3 v12 o4 [c%2 [d%2]2]3 e%2 !
MSXD ?XU1 ?XT1 ?EP0,$81,$38 v12 o4 c%4 !
```

압축 OPLL 멜로디에서도 `?IR1`–`?IR15`, `?IU0`–`?IU15`를 사용합니다.
사용자 음색은 먼저 `?IU번호={8바이트}`로 정의하세요. PSG 전용 압축곡은
`?WD`가 없어도 됩니다. SCC 압축곡의 파형은 연주 행보다 앞에 정의합니다.
OPLL 멜로디와 MSXG에서 `?FB0 ... ?FBn`도 사용할 수 있습니다.
`?XT4`의 `r`는 효과를 시작하지 않고 기다립니다. MSXG `?XT64`의 `r`도
드럼을 타격하지 않습니다. `?ID`는 대기 중인 `?IT`, 음량, `?IB`를 반영합니다.
`?WM`의 샘플 간격이 공유 파형 영역 끝을 넘으면 첫 파형부터 순환합니다.
기존 별칭과 OPNA 문법은 유지됩니다. OPNA와 MSX를 함께 사용할 때도
`#CarrierCorrection`과 `#OPNA1RhythmMute`의 설정을 유지합니다.

## MSX 기능명 명령

권장 표기는 기능 이름을 나타내는 대문자 두 글자입니다. 예:
`?EP2,41,112`, `?DW-3`, `?WD0={...}`, `?WS1,0`, `?FC1`.
기존 `?e`·`@e`, `?d`·`@d`, `?W`·`@W` 등은 호환 별칭으로 유지합니다.
새 이름에는 `@EP` 같은 별칭이 없습니다. 숫자 `@번호`, FM 음색 정의,
OPNA와 가상 SSG의 `@I`·`@W`는 바꾸지 않습니다.
`?WD` 정의는 signed8 32샘플이며, 전역 정의만으로 경로를 전환하지 않습니다.
단, `#sccvoice` 뱅크를 가져오는 전역 `?WS` 행은 SCC 행에 `?`/`@` 문자 명령이 없어도 MSX 문법을 선택합니다(2026-10-30).
`?XT1 ?WP2`는 기존 `?k1,2`와 같은 객체 바이트입니다.
`?XU`는 매크로 밖 채널에 직접 쓰는 compact 선언입니다.
`?KT`·`?IM`은 공유 음고/프로그램 표, `?XH/?XC/?XR`은 프로그램 제어,
`?VF`는 MSX 전역 페이드입니다. 이 새 기능은 PN6를 사용합니다. 전체 명령·호환표는
문서 ZIP의 `docs/MSX_MML_KO.TXT`를 참조하십시오.
아래 번호형 `y`는 별도의 기존 프로토콜이며 재명명하지 않습니다.

```text
SCCA @0 ?EP2,41,112 ?DW-3 o4 l8 cdef !
```

SCCA–SCCE의 기존 음표, `v`, `E`, `M`, `D`, `P`, `@` 문법을 유지한다.
`v`는 현재 E 수준으로 SCC 음량을 즉시 갱신하며 E를 추가로 진행하거나 주기를 쓰지 않는다.
비소유 페이지의 종료는 발음 중인 페이지를 끄지 않는다. 동음 타이는 MUSICLALF·mucomDotNET과 같이, 타이 음표를 읽는 틱에는 E를 진행하지 않고 음량도 쓰지 않으며 다음 틱부터 진행한다. 따라서 타이 안의 `v` 변경은 1틱 뒤에 반영되고, 1클록짜리 `v` 단계는 출력되지 않는다(2026-10-30, MDPlayer4Mac과 일치).
SSG의 기존 `v` 실행 규칙은 유지하며, 페이지 종료와 타이 수정은 SSG에도 적용한다.

## 전용 제어

기존 4인수 `y0,0,번호,값`을 SCC 채널에서 사용한다. 이 범위는 칩 레지스터 주소가 아니라 의미가 정의된 SCC 제어 번호다.
컴파일러는 이를 짧은 `FF EC 번호 값`으로 저장한다. 일반 OPNA/SSG의 y와 raw SCC 모드는 변경하지 않는다.

| 번호 | 기능 | 값 |
|---|---|---|
| 224 | 실제 음량 | 0–15; 255는 현재 진행 중인 E 음량으로 복귀 |
| 225 | 직접 SCC 주기 하위 바이트 준비 | 0–255; 이 명령만으로 출력하지 않음 |
| 226 | 주기 상위 바이트와 출력 | 0–15; 255는 음표 주기로 복귀 |
| 227 | SCC 주기 단위 오프셋 | 부호 있는 8비트의 바이트 표현; -3은 253 |
| 228 | 현재 채널 하드웨어 게이트 | 0/1; 음표 위치·E·효과 위상은 유지 |
| 229 | @ 업로드 정책 | 0 그대로, 1 대상 채널 닫기, 2 칩 전체 닫기; 128을 더하면 동일 파형도 강제 업로드 |

주기는 오프셋 적용 후 9–4095로 제한한다. 같은 주기의 명시적 출력도 생략하지 않는다.
게이트와 음량은 독립적이다. 기존 `P`의 톤/노이즈 의미도 그대로다.
업로드는 이전 게이트 마스크를 복구한다. 일반 SCC의 4·5번 공유 파형에 대상 음소거를 적용하면 둘 다 닫는다.
기본 @ 캐시는 동일 파형을 생략한다. 전체 채널 음소거는 요청한 업로드에만 적용한다.

예: 동음 타이를 유지하며 음량만 7로 바꾸고, 직접 주기 456을 출력한다.

```text
SCCA @0 E255,0,0,0,0,255 v15 o4 c%4&y0,0,224,7 c%4&y0,0,225,200 y0,0,226,1 c%4
```

## 번호형 효과 표

8개 공유 표(0–7), 표마다 최대 16단계다. 표는 정의한 뒤 선택한다. 정의 명령은 시간을 소비하지 않는다.
단계는 지속 틱 수·실제 음량·주기 오프셋·게이트·기본 파형을 묶는다. 음량만 사용하면 엔벌로프 표,
주기 오프셋을 반복하면 SCC 주기 단위 LFO, 파형/게이트까지 지정하면 효과음 표가 된다.

| 번호 | 기능 | 값 |
|---|---|---|
| 230 | 정의할 표 선택·초기화 | 0–7 |
| 231 | 새 단계 추가 | 지속 시간 1–255 음악 틱 |
| 232 | 마지막 단계의 실제 음량 | 0–15; 255 유지 |
| 233 | 마지막 단계의 주기 오프셋 | 부호 있는 바이트; 128은 유지 |
| 234 | 마지막 단계의 게이트 | 0/1; 255 유지 |
| 235 | 마지막 단계의 기본 파형 | 0–9; 255 유지 |
| 236 | 유지 구간 반복 위치 | 단계 0–15; 255 반복 없음 |
| 237 | 키오프 뒤 릴리스 시작 위치 | 단계 0–15; 255 즉시 음소거 |
| 238 | 재생할 효과 표 선택 | 0–7; 255는 표 진행만 중단 |
| 239 | 새 음표의 위상 정책 | 0 첫 단계부터, 1 현재 위상 유지 |

새 단계의 기본값은 음량·주기·게이트·파형 유지다. 표의 주기 오프셋은 누적 가산이 아니라 음표/직접 주기에 대한 절대 오프셋이다.
단계 233의 128은 유지 표식이므로 표에서는 -128을 표현하지 않는다. 일반 227에서는 -128도 가능하다.
선택한 표의 첫 단계는 첫 음표 틱에 적용한다. 타이는 재시작하지 않는다.
반복은 릴리스 위치 앞에서 돌아가고 키오프 후에는 릴리스 꼬리만 실행한다. 꼬리가 끝나면 마지막 값을 유지한다.
반복 없는 유지 구간도 마지막 값을 유지한다. 한 페이지는 한 틱에 한 단계만 진행하므로 시간 없는 무한 루프가 없다.
게이트가 닫혀 있어도 효과는 진행한다. 다른 페이지가 채널을 소유하는 동안에는 기존 SSG 페이지 정책처럼 효과 진행이 멈춘다.
표를 중단해도 마지막 제어값은 유지된다. 자동 E/음표 주기로 되돌리려면 224=255, 226=255, 227=0을 명시한다.
시간 단위는 VBlank 프레임이 아닌 음악 틱이며 템포 변경을 따른다.

```text
; 2틱 음량3/주기-3, 2틱 음량14/주기+3을 반복
SCCA y0,0,230,0 y0,0,231,2 y0,0,232,3 y0,0,233,253
SCCA y0,0,231,2 y0,0,232,14 y0,0,233,3 y0,0,236,0
SCCA y0,0,238,0 @0 v15 o4 c%32 r%4
```

## 런타임 구절

| 번호 | 기능 | 값 |
|---|---|---|
| 240 | 공유 구절 시작 주소 등록 | ID 0–7 |
| 241 | 구절 끝 / 호출자 복귀 | 반드시 0 |
| 242 | 등록된 구절 호출 | ID 0–7 |

등록 위치에서는 본문이 한 번 연주된다. 이후 호출은 MUB 안의 같은 본문을 재사용하며, 호출마다 본문을 복제하지 않는다.
구절은 SCC 페이지 사이에서도 공유한다. 주소·본문 경계·복귀 주소는 32비트이며 매퍼 경계를 지원한다.
반환 스택은 페이지마다 4단계다. 미정의 ID, 깊이 초과 및 잘못된 표는 실행 오류로 중단한다.
정의는 사용보다 먼저 실행되어야 한다. 전방 참조와 재귀는 사용하지 않는다.
구절은 음표/제어 상태를 호출자의 상태로 실행하며, 끝에서 음량·파형 등을 자동 복구하지 않는다.

```text
SCCA @0 v15 o4 y0,0,240,0 c%8d%8e%8g%8 y0,0,241,0
SCCA y0,0,242,0 y0,0,242,0 r%4
```

기존 `#*` 매크로는 계속 컴파일 시 펼쳐진다. 위 예는 별도의 실제 실행 중 호출이다.

## 파일과 실행 조건

기존 SCC 파일(msPb0102 기능값 5)은 계속 읽는다. 새 전용 제어를 사용한 파일만 기능값 13(추가 비트 8)을 쓴다.
이를 모르는 기존 DOS 연주기는 해당 파일을 명시적으로 거부한다. 새 명령을 사용하지 않는 기존 악보의 MUB/DATA는 그대로다.
이 실행 확장은 이 도구체인의 MUC2MUB/MUCPLAY/MUBPLAY를 대상으로 한다. 외부 PC 엔진에 같은 확장 지원이 있다고 가정하지 않는다.
MUCEDIT는 기존 y 문법으로 편집하며 일치하는 MUCPLAY를 통해 컴파일·연주한다.

일반 Z80/512KiB 매퍼 한도를 유지한다. 효과 상태와 표는 기존 뱅크의 빈 공간을 사용한다.
출력은 슬롯을 매 바이트 바꾸는 대신, 주기 쌍/파형을 연속 전송한다. 음악 틱마다 파형을 바꾸는 악보의 비용까지 없애지는 않는다.
코나미 ROM 분석에서 관측한 제어 단위를 제공하는 것으로, 게임 드라이버 전체나 원본 PCM 위상과의 일치를 보증하는 기능은 아니다.
