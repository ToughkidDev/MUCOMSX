# MUCPLAY 사용자 설명서

MSX PSG `MSXD/E/F`, SCC+ `SCCA..E`와 OPLL `MSXA/B/C/H/I/J`·리듬 `MSXG`는 OPNA 행과 함께 사용합니다. 전역 모드 태그는 없습니다. [MSX MML](../docs/MSX_MML_KO.TXT), [새 엔벌로프·디튠](../docs/MSX_STAGE1.TXT), [OPLL 명령](../docs/OPLL_NATIVE.TXT)을 참고하세요.

`MUCPLAY.COM`과 **같은 빌드의 `MUCPLAY.MXR`**을 현재 DOS 폴더 또는 `PATH`에 함께 설치하고 교체하세요. 모듈은 실행을 시작할 때 읽으며 연주 틱 중에는 디스크에서 코드를 읽지 않습니다. 이전 PMC/PNC/EXP 파일은 사용하지 않습니다. 실행 코드 뱅크와 SCC 음색 캐시는 분리하며, 컴파일 음악 DATA의 상한은 **96KiB(98,304바이트)**입니다.

## 업데이트 안내

**2026-11 업데이트(v1.0-Stable 이후)**의 전체 변경과 알려진 제한은 [변경 내역](../shared/docs/RELEASE_NOTES.md)에 있습니다. MSX 칩 확장 명령은 [MucoMSXExtension](../MucoMSXExtension/readme.ko.md)을 보세요. 아래 첫 문단은 2026-10-13 업데이트 안내입니다.

[최신 릴리즈 안내](../shared/docs/RELEASE_UPDATE_261013.md)에 SCC/SCC+ SSG 확장·PCMInvert·컴파일 최적화와 세션 리듬 마스크 복원 수정을 정리했습니다. 기존 세션은 교체 전 `/RELEASE`로 정리하고 네 COM을 함께 교체하세요. 사용자 음색 DAT는 기본 프리셋으로 덮어쓰지 마세요. 결함으로 음악 DATA가 빠진 MUB는 다시 컴파일해야 합니다. MSX-MUSIC/PSG·연주 자동 가속은 공개 v0.81에도 이미 포함되어 있습니다.

### 2026-11: MUCVOICE 제거 — 음색·PCM 편집은 MUCPlayground로

이번 버전부터 툴체인에 MUCVOICE가 들어 있지 않습니다. FM 음색, SCC/SCC+ 파형, ADPCM PCM 뱅크는 툴체인의 공식 편집 환경인 웹 브라우저용 [MUCPlayground](https://toughkiddev.github.io/MUCOMSX/MUCPlayground/)에서 편집합니다. **FM 뱅크**·**SCC 뱅크**·**PCM 뱅크**에서 `#voice`·`#sccvoice`·`#pcm` 파일을 열고, FM 음색 편집기·SCC 파형 편집기·PCM 샘플 편집기로 소리를 들으며 고친 뒤 **저장**으로 내려받습니다. 받은 파일을 MSX에서 MUC와 같은 폴더에 DOS 8.3 이름으로 두고 이 도구로 컴파일·연주하면 됩니다. MSX 컴파일러는 `#@pcm`의 WAV 변환을 하지 않으므로 PCM은 반드시 BIN 뱅크로 저장하세요. 화면 그림과 단계별 설명은 [MUCPlayground 편집 가이드](../shared/docs/MUCPLAYGROUND.md), 버튼과 단축키는 [MUCPlayground 공식 사용 설명서](https://toughkiddev.github.io/MUCOMSX/MUCPlayground/Manual/?lang=ko#banks)에 있습니다. 툴체인 ZIP의 FMVOICE.DAT·SCCVOICE.DAT는 MUCPlayground에서 로드해 출발점으로 쓸 수 있습니다(INIT.TFI는 MUCPlayground에서 읽지 않습니다). 폴더에 남은 예전 MUCVOICE.COM은 갱신되지 않으므로 지워도 됩니다.

> 입력 MUC는 65,536바이트(MUC2MUB·MUCPLAY), 편집 문서는 정규화 후 60,000바이트(MUCEDIT), 음악 DATA는 98,304바이트입니다. 페이지 스트림 상한은 OPNA 59,546·네이티브 MSX 59,106바이트이며 최소 매퍼는 512KiB입니다. 헤더·태그·PCM은 음악 DATA와 별도입니다.

## 1. 먼저 알아두면 좋은 이야기

MUCPLAY는 MUCOM88의 음악 소스인 MUC 파일을 MSX에서 컴파일하고 연주하는 프로그램입니다. MUC 파일을 바로 실행해서 들어볼 수도 있고, 소스를 메모리에 올려 놓은 뒤 컴파일과 연주를 나누어 실행할 수도 있습니다.

음악을 수정하면서 같은 곡을 여러 번 확인할 때는 두 번째 방법이 편합니다. 컴파일한 데이터를 메모리에 유지하므로 다시 연주할 때마다 소스 전체를 컴파일할 필요가 없습니다. 마음에 드는 결과가 나오면 MUB 파일로 저장하면 됩니다.

처음부터 모든 옵션을 외울 필요는 없습니다. 우선 한 곡을 연주해 보고, 그다음 `/LOAD`, `/COMPILE`, `/PLAY` 세 명령에 익숙해지면 됩니다.

이 설명서는 MUCPLAY를 사용하는 방법에 집중했습니다. MUC 작성 문법과 컴파일 오류의 상세 설명은 다루지 않습니다.

### 이 설명서에서 사용하는 프로그램 이름

| 프로그램 | 맡은 일 |
|---|---|
| `MUCPLAY.COM` | MUC를 컴파일해 연주하고, 메모리에 있는 결과를 MUB로 저장합니다. 이 설명서의 주인공입니다. |
| `MUBPLAY.COM` | 이미 만들어진 MUB 파일을 읽어 연주합니다. |
| `MUCEDIT.COM` | MUC를 편집하며 MUCPLAY와 연계해 컴파일·연주·내보내기를 실행합니다. |
| `MUC2MUB.COM` | MUC를 MUB 파일로 변환하는 별도 컴파일러입니다. |

MUCPLAY에는 필요한 컴파일러가 포함되어 있습니다. 일반적인 실행을 위해 `MUC2MUB.COM`을 따로 실행하거나 같은 폴더에 둘 필요는 없습니다.

## 2. 빠르게 시작하기

설명서의 명령은 MSX-DOS2 또는 Nextor의 DOS 프롬프트에서 입력합니다. 

예제에서는 곡 이름을 `SONG.MUC`로 가정하겠습니다. 

### 우선 한 곡 들어보기

곡 파일과 그 곡에 필요한 음색·PCM 파일이 있는 디렉터리에서 실행합니다.

```text
MUCPLAY SONG.MUC
```

mucplay는 소스를 읽고 컴파일한 다음 연주합니다. 재생을 중간에 끝내려면 일반 문자 키나 Esc를 누르세요. 곡이 정해진 종료 조건에 도달해도 DOS로 돌아옵니다.

화면에 다음 안내가 보이면 재생을 멈출 수 있다는 뜻입니다.

```text
Press any key to stop.
```

### 여러 번 들어보고 파일까지 저장하기

```text
MUCPLAY /LOAD SONG.MUC
MUCPLAY /COMPILE
MUCPLAY /PLAY
MUCPLAY /MUB SONG.MUB
MUCPLAY /RELEASE
```

각 줄은 앞 명령이 끝나 DOS 프롬프트로 돌아온 뒤 실행합니다. `/PLAY`에서 곡을 끝까지 듣거나 키를 눌러 정지한 다음 저장 명령을 실행하세요.

이 순서로 작업하면 소스 적재, 컴파일, 연주, 파일 저장, 메모리 정리까지 한 번씩 경험할 수 있습니다.

## 3. 실행 환경과 파일 준비

### 실행에 필요한 것

이 설명서는 **YM2608을 사용하는 Makoto용 MUCPLAY**를 기준으로 합니다.

준비할 것은 다음과 같습니다.

- MSX-DOS 2 또는 해당 기능을 제공하는 Nextor 환경
- 프로그램과 컴파일 작업에 사용할 여유 메모리 매퍼 RAM
- 실제로 소리를 들으려면 Makoto(YM2608)
- `MUCPLAY.COM`
- 연주할 MUC와 그 곡이 사용하는 음색·PCM 파일
- 세션 파일과 출력 파일을 기록할 수 있는 디스크 공간

처음 환경을 구성한다면 512KB 이상의 매퍼 RAM을 갖춘 구성을 기준으로 준비하는 편이 좋습니다. 설치된 RAM 용량과 실제 사용 가능한 여유 메모리는 다릅니다. 다른 프로그램이나 유지 중인 세션도 메모리를 사용합니다.

내장 매퍼와 외장 매퍼가 함께 있으면 시작할 때 빈 메모리가 더 많은 매퍼를 골라 작업에 씁니다. 두 매퍼를 합쳐 쓰지는 않으며, 구성에 따라 DOS가 쓰는 매퍼만 사용할 수도 있습니다. 지원 Panasonic 기종은 연주할 때 고속 Z80(5.37MHz), turbo R은 R800으로 자동 가속합니다. One Chip MSX(OCM)에서는 `/N`과 관계없이 카트리지 슬롯 클럭을 3.58MHz로 맞춘 뒤 CPU를 8.06MHz로 올립니다. 종료하면 모두 원래 속도로 되돌립니다. `/N`을 붙이면 Panasonic·turbo R 자동 가속을 하지 않습니다.

YM2610B/Neotron-B용 프로그램은 별도 대상입니다. 파일명이 비슷하더라도 이 설명서의 Makoto용 실행 파일과 혼동하지 말아 주세요.

### 파일을 배치하는 방법

처음에는 한 앨범에 필요한 파일을 한 디렉터리에 모아 두면 편합니다.

```text
ALBUM\
    MUCPLAY.COM
    SONG.MUC
    VOICE.DAT
    PCM.BIN
```

여기서 `VOICE.DAT`와 `PCM.BIN`은 배치 예시입니다. 앨범에서 실제로 사용하는 이름을 유지하세요. 이름만 예제처럼 바꾸면 곡이 필요한 파일을 찾지 못할 수 있습니다. 외부 음색이나 PCM을 쓰지 않는 곡에는 해당 파일이 필요하지 않을 수도 있습니다.

`MUCPLAY.COM`을 DOS의 검색 경로에 두고 사용해도 됩니다. 프로그램을 찾는 경로와 곡의 동반 파일을 찾는 작업 디렉터리는 별개이므로, 곡이 있는 디렉터리로 이동해서 실행하는 방식을 권합니다.

### 파일명과 경로

MSX-DOS에서 보이는 이름을 기준으로 입력하세요. 처음에는 공백 없는 짧은 8.3 이름을 사용하면 혼동을 줄일 수 있습니다.

```text
SONG.MUC
SONG.MUB
```

긴 파일명이나 따옴표로 묶은 공백 포함 경로를 현대적인 셸과 같은 방식으로 처리한다고 생각하지 않는 편이 좋습니다. 특히 컴파일 경로에는 별도의 파일명 처리 제한이 있으므로 긴 전체 경로보다 해당 디렉터리에서 짧은 파일명으로 실행하세요.

openMSX의 호스트 폴더 이름과 DOS에서 보이는 이름이 다를 때는 `DIR`로 확인합니다.

## 4. 명령어 한눈에 보기

| 명령 | 하는 일 | 명령 뒤의 파일명 |
|---|---|---|
| `MUCPLAY SONG.MUC` | MUC를 읽고 컴파일한 뒤 바로 연주 | 입력 MUC |
| `MUCPLAY /LOAD SONG.MUC` | 소스와 컴파일 준비 데이터를 메모리에 적재 | 입력 MUC |
| `MUCPLAY /COMPILE` | 적재된 소스를 컴파일해 결과를 메모리에 유지 | 필요 없음 |
| `MUCPLAY /PLAY` | 컴파일된 메모리 데이터를 연주 | 필요 없음 |
| `MUCPLAY /MUB SONG.MUB` | 컴파일된 결과를 MUB로 저장 | 출력 MUB |
| `MUCPLAY /RELEASE` | 세션 메모리를 해제하고 세션 파일을 삭제 | 필요 없음 |

명령 옵션은 대소문자를 구분하지 않습니다. 이 설명서에서는 알아보기 쉽도록 대문자로 표기했습니다.

`/LOAD`, `/COMPILE`, `/PLAY`, `/MUB`, `/RELEASE`는 단계별 명령입니다. 처음에는 여러 동작 옵션을 한 줄에 섞기보다 각각 실행하세요. 반복 횟수를 지정하는 `/L`은 재생 명령에 함께 붙여 사용합니다.

MUB 저장 예제에는 확장자까지 적었습니다. 사용자가 지정할 출력 이름도 같은 방식으로 입력하는 것을 권합니다.

## 5. 한 곡 바로 연주하기

가장 간단한 실행 방법입니다.

```text
MUCPLAY SONG.MUC
```

이 명령은 입력 MUC를 읽고 컴파일한 뒤 연주합니다. 같은 명령을 다시 실행하면 소스 읽기와 컴파일도 다시 진행합니다.

단순히 곡을 들어볼 때는 이 방식이 편합니다. 이후 MUB로 저장할 계획이라면 다음 장의 세션 방식을 사용하세요. **직접 실행 한 번을 `/LOAD`와 `/COMPILE`을 마친 영구 세션으로 간주하면 안 됩니다.**

### 재생을 시작하기 전의 준비 시간

명령을 입력한 즉시 소리가 나는 것은 아닙니다. 소스를 읽고 컴파일하는 시간, 필요할 경우 PCM을 Makoto의 샘플 메모리로 전송하는 시간이 필요합니다.

MSX2 이상과 turbo R에서는 연주를 시작하기 전에 곡의 앞부분을 미리 계산해 메모리 세그먼트 하나(16KB)에 채워 둡니다. 그래서 곡 정보가 나온 뒤 소리가 나기까지 잠깐 걸릴 수 있습니다. 연주 중에도 계속 미리 계산해 두므로 디스크나 화면 처리가 잠깐 몰려도 소리가 밀리지 않습니다. 미리 계산이 연주를 따라가지 못하면 직접 출력 방식으로 바꿔 계속 연주합니다. 빈 세그먼트가 없으면 처음부터 직접 출력 방식으로 연주합니다.

### 이미 MUB 파일을 가지고 있다면

완성된 MUB 파일은 MUBPLAY로 실행합니다.

```text
MUBPLAY SONG.MUB
```

MUCPLAY의 `/PLAY` 뒤에 MUB 파일명을 붙여서 디스크 MUB를 여는 방식은 아닙니다. `/PLAY`는 MUCPLAY가 이미 컴파일해 둔 메모리 세션을 사용합니다.

## 6. 메모리 세션으로 작업하기

세션은 “지금 작업하고 있는 곡을 메모리에 유지해 두는 것”이라고 생각하면 됩니다. 프로그램이 DOS로 돌아와도 적재한 소스와 컴파일 결과를 다음 명령에서 사용할 수 있습니다.

### 1단계: 소스 적재 — `/LOAD`

```text
MUCPLAY /LOAD SONG.MUC
```

MUC를 읽어 컴파일할 준비를 하고 DOS로 돌아옵니다. 이 단계에서는 컴파일하지 않고, 연주도 하지 않습니다.

기존 세션에 다른 곡의 소스나 컴파일 결과가 남아 있다면 그것을 해제한 뒤 새 소스를 적재합니다. 이전 작업을 남기고 싶다면 새 곡을 `/LOAD`하기 전에 필요한 파일로 저장하세요.

### 2단계: 컴파일 — `/COMPILE`

```text
MUCPLAY /COMPILE
```

앞에서 메모리에 적재한 소스를 컴파일합니다. 결과는 메모리에 남고 DOS로 돌아옵니다.

여기서 알아둘 점은 세 가지입니다.

- 디스크에 MUB 파일을 자동 생성하지 않습니다.
- 연주를 시작하지 않습니다.
- 이 단계에서 PCM을 Makoto의 샘플 메모리로 전송하지 않습니다.

파일명 인수도 필요하지 않습니다. 어느 곡을 컴파일할지는 현재 세션에 적재된 소스로 결정됩니다.

### 3단계: 연주 — `/PLAY`

```text
MUCPLAY /PLAY
```

현재 컴파일 결과를 연주합니다. 필요한 PCM 파일을 읽어 샘플 데이터를 준비한 뒤 연주를 시작합니다.

정지 후에도 세션은 남습니다. 따라서 바로 다시 들어볼 수 있습니다.

```text
MUCPLAY /PLAY
```

다시 실행하면 곡의 시작부터 연주합니다. 이전에 멈춘 위치에서 이어 듣는 일시 정지·재개 기능은 아닙니다.

### `/COMPILE`을 두 번 실행하면

```text
MUCPLAY /LOAD SONG.MUC
MUCPLAY /COMPILE
MUCPLAY /COMPILE
```

반복 컴파일할 수 있습니다. 적재한 MUC와 보이스 데이터는 유지하고, 기존 MUB 세그먼트는 해제한 다음 새로 컴파일합니다.

이때 이전 컴파일 결과를 별도로 보관해 두지는 않습니다. 새 컴파일이 완료되어야 다음 `/PLAY`, `/MUB`에서 사용할 결과가 준비됩니다.

### 디스크에서 소스를 고쳤다면 다시 `/LOAD`

이 부분은 꼭 기억해 주세요. `/COMPILE`은 디스크의 MUC 파일을 다시 읽는 명령이 아닙니다.

외부 편집기로 파일을 수정하고 저장했다면 다음 순서로 반영합니다.

```text
MUCPLAY /LOAD SONG.MUC
MUCPLAY /COMPILE
MUCPLAY /PLAY
```

`/LOAD`를 생략하면 메모리에 남아 있는 이전 소스를 다시 컴파일하게 됩니다. 외부 음색 파일을 변경했을 때도 소스를 다시 적재하는 방식으로 작업하세요.

### 명령별로 무엇이 남는가

| 실행한 명령 | 메모리에 적재한 소스 | 컴파일 결과 | 디스크 출력 |
|---|---|---|---|
| `/LOAD` | 새 소스로 바뀜 | 기존 결과 해제 | 세션 관리 파일 |
| `/COMPILE` | 유지 | 새 결과 생성 | MUB 저장 안 함 |
| `/PLAY` | 유지 | 유지 | 음악 파일 저장 안 함 |
| `/MUB` | 유지 | 유지 | 지정한 MUB 생성 |
| `/RELEASE` | 해제 | 해제 | 세션 관리 파일 삭제 |

이 표는 각 동작이 정상 완료된 경우를 기준으로 합니다.

## 7. 반복 재생과 정지

### 반복 횟수 지정

`/L` 뒤에 한 자리 숫자를 붙여 사용합니다.

```text
MUCPLAY SONG.MUC /L2
```

메모리 세션 재생에도 같은 옵션을 사용합니다.

```text
MUCPLAY /PLAY /L2
```

| 지정 | 재생 동작 |
|---|---|
| 생략 | 기본 1회 재생 |
| `/L1` | 1회 재생 |
| `/L2` | 2회 재생 |
| `/L3` … `/L9` | 지정한 횟수만큼 재생 |
| `/L0` | 곡의 루프를 계속 반복 |
| `/L` | 숫자 없이 쓰면 무한 반복 지정 |

처음 한 번을 포함한 횟수입니다. `/L2`는 처음 연주한 뒤 두 번을 더 반복하라는 뜻이 아닙니다.

현재 숫자 입력은 0부터 9까지 한 자리 기준입니다. `/L10`처럼 두 자리 횟수를 지정하지 마세요.

### 반복은 곡이 가진 루프를 따릅니다

반복 재생은 곡 전체 파일을 매번 처음부터 다시 실행하는 기능과는 다릅니다. 음악 데이터에 들어 있는 루프 위치를 사용하므로, 도입부가 한 번 나온 뒤 본문만 반복되는 곡도 있습니다.

루프가 없는 곡은 모든 채널이 끝나면 종료합니다. `/L0`을 붙였다고 해서 루프가 없는 곡까지 자동으로 처음부터 무한 재생하는 것은 아닙니다.

반복 횟수는 `L` 반복점이 있는 채널의 진행으로 판단합니다. MSX 네이티브 악보(msPb0103~0109)는 MUCOM88의 `L` 반복점 없이 채널마다 점프로 되돌아가 반복합니다. 이런 곡은 채널마다 반복을 따로 세어, 살아 있는 모든 채널이 n번 이상 반복했을 때 n번째 연주 구간이 끝난 것으로 봅니다. 그래서 반복 구간이 가장 긴 채널이 곡의 한 바퀴가 되고, 반복하지 않고 연주 중인 채널이 있으면 그 채널이 끝날 때까지 기다립니다. 모든 채널이 스스로 끝나는 곡은 끝에서 종료합니다.

### 중간에 멈추기

재생 중 일반 문자 키나 Esc를 누르면 정지하고 돌아옵니다. Ctrl이나 Shift 같은 보조 키만 누르는 것보다는 문자 키를 사용하는 것이 확실합니다.

정지는 세션 해제와 다릅니다. `/PLAY`를 멈췄다고 적재된 소스나 컴파일 결과가 사라지지는 않습니다. 완전히 작업을 마칠 때 `/RELEASE`를 실행하세요.

## 8. MUB 파일로 저장하기

MUB는 컴파일된 음악 데이터와 재생에 필요한 정보를 담는 파일입니다. 완성된 곡을 MUBPLAY로 듣거나 보관할 때 사용합니다.

```text
MUCPLAY /LOAD SONG.MUC
MUCPLAY /COMPILE
MUCPLAY /MUB SONG.MUB
```

`/MUB` 뒤의 이름은 **새로 저장할 출력 파일명**입니다. 읽을 MUC나 MUB 이름이 아닙니다.

### 어떤 데이터가 저장되는가

현재 세션의 컴파일 결과를 사용합니다. `/MUB`를 실행했다고 소스를 다시 컴파일하지는 않습니다.

MUB 저장 과정에서는 헤더, 곡 데이터, 태그 정보와 함께 PCM 동반 파일도 출력에 반영합니다. `/COMPILE` 단계의 메모리 결과와 배포용 MUB 파일이 담당하는 역할이 여기서 구분됩니다.

PCM이 정상적으로 포함된 MUB는 재생할 때 그 안의 샘플 데이터를 사용할 수 있습니다. 저장 단계까지는 앨범의 PCM 파일을 원래 위치에 두세요. 저장이 끝났다는 메시지만 보지 말고 PCM 관련 알림이 있었는지도 함께 확인하는 것이 좋습니다.

### 저장 후 확인하기

```text
DIR SONG.MUB
MUBPLAY SONG.MUB
```

파일이 만들어졌는지 확인하고 직접 들어보세요. MUCPLAY에서 미리 들은 결과와 저장한 MUB의 재생 결과를 확인하는 습관을 권합니다.

### 이름을 달리해서 여러 결과 남기기

```text
MUCPLAY /MUB SONG01.MUB
MUCPLAY /MUB SONG02.MUB
```

같은 컴파일 결과를 여러 이름으로 저장할 수 있습니다. 음악 내용을 바꾸려면 소스를 수정하고 다시 적재·컴파일해야 합니다.

기존 파일과 같은 이름으로 저장하면 덮어쓸 수 있습니다. 이전 결과를 남기려면 다른 이름을 사용하세요. 출력 디렉터리가 필요하다면 먼저 준비해 두어야 합니다.

## 9. VGM 출력 기능 제거

코드에 쓸 메모리를 확보하기 위해 2026-10-30부터 MUCPLAY의 VGM 출력(`/VGM 파일명`과, 파일을 연주하면서 VGM을 함께 기록하던 짧은 형식 `/V`)을 제거했습니다. MUCEDIT의 F1→5 VGM 내보내기도 함께 없어졌습니다. 비워진 코드 공간은 앞으로의 기능을 위해 남겨 둡니다. 현재 MUCPLAY의 사용법은 `MUCPLAY file.muc [/L<n>]`, 또는 `/LOAD f`, `/COMPILE`, `/PLAY`, `/MUB f`, `/RELEASE`입니다.

같은 날(2026-10-30) MUBPLAY의 VGM 출력(`/V`)도 제거되었으므로, 이제 MucoMSX 툴체인(MUC2MUB, MUCPLAY, MUBPLAY, MUCEDIT)의 어떤 도구도 VGM 내보내기를 제공하지 않습니다. 곡을 완성된 재생 파일로 남기려면 `MUCPLAY /MUB SONG.MUB`로 MUB를 저장해 주세요.

## 10. 메모리 정리와 앨범 이동

### 작업을 마칠 때 — `/RELEASE`

```text
MUCPLAY /RELEASE
```

현재 세션의 MUC·보이스·MUB 데이터와 관리용 헤더 메모리를 해제하고 `MUCPLAY.SES`를 삭제합니다.

디스크에 보관한 원본 MUC와 이미 저장한 MUB 파일은 그대로 남습니다. `/RELEASE`는 음악 파일을 삭제하는 명령이 아닙니다.

### `MUCPLAY.SES`는 무엇인가

명령을 나누어 실행해도 같은 메모리 데이터를 찾을 수 있도록 사용하는 작은 관리 파일입니다. 이 파일 자체에 곡 전체가 들어 있는 것은 아닙니다.

따라서 다음과 같이 생각하면 됩니다.

- `MUCPLAY.SES`만 복사해 다른 컴퓨터나 다른 부팅 환경에서 곡을 복원할 수는 없습니다.
- 전원을 끄거나 리셋한 뒤에는 이전 메모리 세션을 이어 사용할 수 없습니다.
- 곡을 보관하려면 MUC를 저장하고, 필요에 따라 MUB도 내보내야 합니다.
- 메모리를 정리할 때는 세션 파일을 직접 지우지 말고 `/RELEASE`를 사용합니다.

세션 파일만 먼저 삭제하면 프로그램이 기존 메모리를 찾아 해제하기 어려워질 수 있습니다.

### 작업 디렉터리를 유지해 주세요

세션 관리 파일은 현재 작업 디렉터리에서 찾습니다. PCM 경로도 상대 경로일 수 있으므로 적재부터 컴파일·재생·내보내기·해제까지 같은 디렉터리에서 마치는 것이 가장 간단합니다.

다른 앨범으로 이동할 때는 다음 순서를 사용하세요.

```text
MUCPLAY /RELEASE
CD ..
CD ALBUM2
MUCPLAY /LOAD SONG2.MUC
MUCPLAY /COMPILE
MUCPLAY /PLAY
```

이 예제는 `ALBUM2`가 DOS에서 접근 가능한 디렉터리이고, 이동한 뒤에도 MUCPLAY를 실행할 수 있도록 프로그램이 배치되어 있다고 가정합니다.

다른 디렉터리에서 `/RELEASE`를 실행한다고 이전 디렉터리의 세션까지 찾아 일괄 해제하는 것은 아닙니다. 앨범 폴더를 떠나기 전에 정리하는 습관을 들이면 좋습니다.

## 11. 음색·PCM 파일 관리

> **음색·PCM 파일 만들기:** FM 음색 파일, SCC 파형 파일, PCM 뱅크는 [MUCPlayground](https://toughkiddev.github.io/MUCOMSX/MUCPlayground/)에서 편집해 **저장**으로 내려받은 뒤 이 폴더로 복사합니다. 순서는 [MUCPlayground 편집 가이드](../shared/docs/MUCPLAYGROUND.md#3-msx와-오가는-기본-순서)를 보세요.

MUC 하나만 복사해서는 원래 곡과 같은 소리가 나지 않는 경우가 있습니다. 앨범에 포함된 음색 데이터와 PCM 데이터도 음악의 일부로 생각해 주세요.

### 음색 데이터

외부 음색을 사용하는 곡은 해당 음색 파일을 함께 준비합니다. 세션 작업에서는 적재한 보이스 데이터가 컴파일에 사용되므로, 외부 파일을 바꾼 뒤에는 `/LOAD`부터 다시 진행하는 것이 좋습니다.

### PCM 데이터

PCM을 사용하는 곡은 재생 시 파일에서 샘플을 읽어 Makoto의 샘플 메모리에 올립니다. 한 번 컴파일했다고 해서 PCM 파일까지 영구적으로 메모리에 보관해 둔다고 생각하지 마세요.

| 작업 | PCM에 대해 알아둘 점 |
|---|---|
| `/COMPILE` | 칩으로 PCM을 전송하는 단계가 아닙니다. |
| `/PLAY` | 필요한 외부 PCM을 읽어 연주를 준비합니다. |
| `/MUB` | PCM 파일을 읽어 출력 MUB에 붙이는 과정이 있습니다. |

`#pcm` 태그에 적은 PCM 파일이 없으면 컴파일을 시작하지 않고 오류 19(`PCM file in #pcm tag not found`)로 멈춥니다. 곡을 연주하거나 MUB를 만들지 않습니다. 태그 없이 기본 `MUCOMPCM.BIN`을 찾다가 없을 때만 예전처럼 경고 후 계속합니다.

`#pcm` 줄이 없고 기본 `MUCOMPCM.BIN`도 없는 곡은 경고를 표시한 뒤 ADPCM 파트 없이 연주합니다. 이전에 Makoto에 올라가 있던 PCM이 대신 울리지 않습니다.

동반 PCM 파일은 해당 곡과 맞는 MUCOM용 데이터여야 합니다. WAV나 AIFF 파일의 확장자만 BIN으로 바꾸어 사용할 수는 없습니다.

### 일부 악기만 이상할 때

전체 소리가 아니라 샘플 악기만 빠지거나 다른 소리가 난다면 먼저 다음을 확인해 주세요.

1. 곡에 맞는 PCM 파일을 함께 가져왔는지.
2. 파일 이름이 DOS에서 올바르게 보이는지.
3. 적재 후 작업 디렉터리나 파일 위치를 바꾸지 않았는지.
4. 같은 이름의 다른 앨범 파일로 덮어쓰지 않았는지.

파일을 정리한 뒤 `/LOAD → /COMPILE → /PLAY` 순서로 다시 확인하면 됩니다. 파일 구성과 재생 상태를 확인하기 전부터 소스의 악기 설정을 바꿀 필요는 없습니다.

## 12. MUCEDIT와 함께 사용하기

MUCEDIT에서는 편집 중인 곡을 MUCPLAY에 넘겨 컴파일하고 연주할 수 있습니다. 편집, 확인, 다시 편집하는 흐름을 이어 가기 위한 기능입니다.

기본적인 작업 순서는 다음과 같습니다.

1. MUCEDIT에서 곡을 불러옵니다.
2. 필요한 부분을 편집합니다.
3. 에디터의 컴파일 기능을 실행합니다.
4. 연주 기능으로 결과를 확인합니다.
5. 정지 후 에디터로 돌아와 작업을 이어갑니다.
6. 원본 소스를 저장하고 필요하면 MUB를 내보냅니다.

에디터가 사용하는 연계 옵션과 복귀 처리는 에디터에 맡기세요.
**MUB를 내보내는 것과 편집한 MUC 원본을 저장하는 것은 별개의 작업입니다.** 음악 파일을 내보냈더라도 다음에 다시 편집할 소스는 에디터에서 따로 저장해 주세요.

메뉴의 정확한 배치와 편집 키는 MUCEDIT 설명서를 참고하세요. 여기서는 MUCPLAY가 맡는 컴파일·연주·출력 흐름까지만 설명합니다.

## 14. 상황별 작업 예제

### 같은 곡을 반복해서 들어보기

```text
MUCPLAY /LOAD SONG.MUC
MUCPLAY /COMPILE
MUCPLAY /PLAY /L0
```

원하는 만큼 들은 다음 키를 눌러 정지합니다. 다시 들으려면 `/PLAY`만 실행하면 됩니다.

```text
MUCPLAY /PLAY /L2
MUCPLAY /RELEASE
```

### 외부 편집기에서 수정한 내용을 반영하기

먼저 편집기에서 MUC를 저장한 뒤 DOS에서 실행합니다.

```text
MUCPLAY /LOAD SONG.MUC
MUCPLAY /COMPILE
MUCPLAY /PLAY
```

이전 소스를 다시 컴파일하는 일이 없도록 `/LOAD`를 포함했습니다.

### 들어본 뒤 MUB 남기기

```text
MUCPLAY /LOAD SONG.MUC
MUCPLAY /COMPILE
MUCPLAY /PLAY
MUCPLAY /MUB SONG.MUB
MUCPLAY /RELEASE
```

들어본 컴파일 결과를 MUB에 저장하는 예제입니다. MUB 자체의 재생 횟수를 `/MUB`에서 고정하는 것은 아닙니다.

### 같은 앨범에서 다음 곡으로 바꾸기

```text
MUCPLAY /LOAD SONG1.MUC
MUCPLAY /COMPILE
MUCPLAY /PLAY
MUCPLAY /MUB SONG1.MUB
MUCPLAY /LOAD SONG2.MUC
MUCPLAY /COMPILE
MUCPLAY /PLAY
MUCPLAY /MUB SONG2.MUB
MUCPLAY /RELEASE
```

두 번째 `/LOAD`가 첫 곡의 적재 데이터와 컴파일 결과를 해제하고 새 곡으로 바꿉니다. 따라서 같은 디렉터리에서 곡을 바꿀 때마다 `/RELEASE`를 반드시 끼워 넣을 필요는 없습니다. 작업을 끝내거나 다른 앨범 디렉터리로 이동할 때는 해제해 주세요.

### 연주하지 않고 파일만 만들기

```text
MUCPLAY /LOAD SONG.MUC
MUCPLAY /COMPILE
MUCPLAY /MUB SONG.MUB
MUCPLAY /RELEASE
```

파일 생성 전에 `/PLAY`를 반드시 실행할 필요는 없습니다.

## 15. 자주 묻는 질문

### `/COMPILE`은 끝났는데 MUB 파일이 없습니다.

정상입니다. 결과가 메모리에 준비된 단계입니다. 파일로 보관하려면 `/MUB 출력파일명.MUB`를 실행하세요.

### `/LOAD` 다음에 바로 `/PLAY`하면 되나요?

먼저 `/COMPILE`로 재생 데이터를 만들어야 합니다. 기본 순서는 `/LOAD → /COMPILE → /PLAY`입니다.

### `/PLAY`를 다시 실행할 때마다 컴파일하나요?

아닙니다. 현재 컴파일 결과를 다시 사용합니다. 다만 PCM을 사용하는 곡의 샘플 준비 등 재생 초기화는 다시 진행합니다.

### 소스를 고쳤는데 같은 음악이 나옵니다.

외부에서 저장한 파일을 다시 `/LOAD`했는지 확인하세요. `/COMPILE`만 반복하면 이전에 메모리에 적재한 소스를 사용합니다.

### `/MUB` 뒤에 원본 MUC 이름을 쓰나요?

저장할 MUB 이름을 씁니다. 예를 들어 `MUCPLAY /MUB SONG.MUB`입니다. 원본 이름을 출력 이름으로 잘못 지정하지 않도록 확장자까지 확인해 주세요.

### `/L0`인데 곡이 끝납니다.

곡 데이터에 루프가 없으면 모든 채널이 끝날 때 종료합니다. 무한 반복 지정은 곡 안의 루프를 계속 사용하는 의미입니다.

### 정지한 뒤에도 메모리가 사용 중인 것은 정상인가요?

세션 방식으로 작업했다면 정상입니다. 다시 연주하고 내보낼 수 있도록 데이터를 유지합니다. 필요가 없어졌을 때 `/RELEASE`를 실행하세요.

### 다른 폴더로 갔다 오니 세션을 찾지 못합니다.

세션을 만든 디렉터리로 돌아와 작업하세요. 관리 파일과 PCM의 상대 경로가 현재 디렉터리에 영향을 받습니다. 이전 폴더의 작업을 마치고 해제한 뒤 새 폴더로 이동하는 편이 좋습니다.

### 리셋했는데 `MUCPLAY.SES` 파일은 남아 있습니다.

그 파일만으로 메모리의 곡을 복원할 수는 없습니다. 새 부팅에서는 소스를 다시 `/LOAD`하고 `/COMPILE`해서 작업하세요. 세션 파일은 음악의 저장본이 아닙니다.

### 배포할 때 `MUCPLAY.SES`도 함께 넣어야 하나요?

필요 없습니다. 편집 가능한 소스를 배포하려면 MUC와 필요한 동반 파일을, 완성된 재생 파일을 배포하려면 MUB를 준비하세요. MUB에 필요한 PCM이 정상적으로 포함됐는지도 확인해 주세요.

### 컴파일과 재생 중 어느 단계에서 PCM 파일이 필요한가요?

세션의 `/COMPILE`이 끝났다는 이유로 PCM 파일을 치우면 안 됩니다. `/PLAY`, `/MUB`에서 샘플을 읽을 수 있도록 작업이 끝날 때까지 같은 앨범에 두세요.

### `/RELEASE`하면 저장한 음악도 지워지나요?

아닙니다. 메모리 세션과 관리 파일을 정리하며, 저장한 MUC·MUB는 남습니다.

## 16. 마지막으로 기억할 명령

처음에는 아래 순서만 익혀 두면 충분합니다.

```text
MUCPLAY /LOAD SONG.MUC
MUCPLAY /COMPILE
MUCPLAY /PLAY
```

결과를 남길 때는 다음 명령을 실행합니다.

```text
MUCPLAY /MUB SONG.MUB
```

작업을 마치면 정리합니다.

```text
MUCPLAY /RELEASE
```

자주 쓰는 흐름은 **불러오기 → 컴파일 → 들어보기 → 저장 → 해제**입니다. 여기에 익숙해지면 반복 횟수를 바꾸거나 MUCEDIT와 연결해서 훨씬 편하게 작업할 수 있습니다.

## MSX-MUSIC·내부 PSG 확장

최신 통합 빌드는 MSX 접두어 파트와 전용 msPb 출력, 연주 CPU 자동 가속을 지원합니다. 기존 파트는 OPNA로 유지됩니다. 사용 조건·용량·근사 변환의 제한은 새 안내를 우선 확인해 주세요.

[MSX target guide](../shared/docs/MSX_TARGETS.md)

`#SSGExtend`, `@I`, `@W`, `pe`, `#PCMInvert`는 [SCC+ SSG 확장 안내](../shared/docs/SSG_EXTEND.md)를 참조하세요. 기존 msPb 계열을 확장한 근사 연주 기능이며 PC 가상 SSG와 완전 일치는 아닙니다.

## SCC 전용 악보

`SCCA`–`SCCE`는 SCC/SCC+ 1–5번 채널입니다. `SCCABC` 같은 복수 선택과 페이지 0–9를 지원합니다. 악보 앞쪽의 `#sccvoice SCCVOICE.DAT`로 SCWD v1 뱅크(MUCPlayground의 SCC 뱅크에서 저장)를 지정하고, 각 SCC 파트에서 `@0`–`@255`로 정의된 파형을 고릅니다. DAT는 MUC와 같은 작업 폴더에 DOS 8.3 이름으로 두세요. 기본 파일명은 `SCCVOICE.DAT`입니다.

예: `SCCA @0 o4 v15 l8 cdefgab>c`

MUB에는 파형이 포함되어 재생 시 DAT가 필요 없습니다. MUCEDIT에서 컴파일·연주·MUB 내보내기를 그대로 사용할 수 있습니다. 새 `msPb0102` 형식이므로 최신 MUC2MUB/MUCPLAY/MUCEDIT/MUBPLAY를 함께 설치하세요. 일반 SCC에서는 4·5번 파형이 공유되며, 다섯 독립 파형에는 SCC+가 필요합니다. `#SSGExtend On` 및 raw SCC와는 혼합하지 마세요. 512KiB 매퍼, MUCEDIT 60,000바이트, 음악 DATA 96KiB 한도는 유지됩니다. 자세한 명령과 파일 규격은 공통 MSX_TARGETS 안내의 SCC 전용 5채널 항목에 있습니다.


## MUC 안에 SCC 파형 직접 정의

`@W번호:{ ... }`로 SCC의 32바이트 파형을 MUC 안에 정의할 수 있습니다. OPNA의 중괄호 음색 정의와 같은 형태이며, 연주 파트에서는 `@번호`로 선택합니다. 필요한 SCC 파형을 모두 정의하면 `#sccvoice`와 외부 DAT 없이 컴파일·연주·MUB 출력이 가능합니다.

MUCPlayground의 SCC 파형 편집기가 넣어 주는 `@W번호:{ ... }` 정의도 그대로 사용할 수 있습니다([SCC 파형 편집 가이드](../shared/docs/MUCPLAYGROUND.md#5-scc-파형-편집)). 번호 0–255, 샘플 32개, 값 -128–127입니다. 같은 번호의 외부 파형보다 인라인 정의가 우선하며, 명시한 `#sccvoice` 파일이 없으면 오류입니다. 자세한 예와 호환 문법은 MSX_TARGETS의 SCC 파형 정의 안내에 있습니다.
